# llm_app — прототип точного запуска больших моделей на слабой видеокарте

Генерирует **тот же текст, что модель в полной точности (fp32)**, но быстрее и в меньшей памяти:

- веса слоёв сжаты **без потерь** до 12 бит (знак+мантисса 8 бит + 4-битный код порядка, редкие исключения списком);
- выбор слова по int8-копии словаря со **строгой границей ошибки**, точно пересчитываются только кандидаты (1-25 слов);
- если модель не влезает в видеокарту — **план памяти**: сколько влезет слоёв в видеокарте, остальные через один
  считает процессор (из файла модели), пока следующий слой едет по шине;
- **угадывание вперёд** маленькой моделью той же семьи (`--draft`): текст не меняется, слов за проход больше;
- начало запроса, совпавшее с прошлым (история разговора), не пересчитывается.

Модели Ollama (GGUF: Q4_K, Q6_K, F16) читаются прямо из `~/.ollama` по имени (`qwen3:14b`): веса
перекладываются без потерь в удобный для видеокарты вид, счёт fp32; модель, не влезающая в видеокарту,
частично подкачивается по шине, а угадыватель (`--draft qwen3:0.6b`) проверяется пачкой за один проход.
На ноутбуке с RTX 5060 8 ГБ, qwen3:14b: обычный чат 6.5 слов/с (Ollama 6.2), математика и код 10-15 (Ollama 6.2).

Сейчас: видеокарты NVIDIA (Windows, Linux), модели семьи Qwen3 (плотные), Python + torch + Triton + Numba.

## Запуск

```
python -m llm_app serve --model Qwen3-8B [--draft Qwen3-0.6B]   # сервер на :11435 (точный режим)
python -m llm_app serve --model qwen3:14b --draft qwen3:0.6b     # модель Ollama (GGUF)
python -m llm_app chat  --model Qwen3-8B                        # разговор в терминале
python -m llm_app plan  --model Qwen3-8B                        # показать план памяти
python -m llm_app.selftest --model Qwen3-8B                     # проверка: текст = эталон fp32
python -m llm_app.bench <имя> <url> <модель> [задач]            # сравнение серверов (скорость, GSM8K)
```

`--model` — папка модели Hugging Face или имя в кэше (`Qwen3-8B`, `Qwen/Qwen3-8B`).
Сервер понимает запросы Ollama (`/api/chat`, `/api/generate`, `/api/tags`) и OpenAI (`/v1/chat/completions`),
поэтому подходят готовые программы-клиенты.

Первый запуск дольше: настройка ядер под видеокарту (сохраняется в `~/.cache/llm_app/tune.json`) и компиляция.

## Устройство

| Файл | Что |
|---|---|
| `model.py` | чтение модели (safetensors, memmap), описание архитектур |
| `plan.py` | план памяти по свободной VRAM/RAM |
| `engine.py` | движок: слои в видеокарте / по шине / на процессоре, чтение запроса послойно, генерация, угадывание |
| `head.py` | выбор слова: int8-словарь в видеокарте + точные строки из файла |
| `wcomp.py` | сжатие 12 бит и ядра умножения (одно слово, пачка до 16 на тензорных блоках) |
| `tkernels.py` | ядра Triton: bf16-умножение, нормировка, поворот, внимание |
| `cpu_layer.py` | слой на процессоре (Numba, веса bf16, счёт fp32) |
| `tune.py` | автонастройка ядер |
| `server.py` | HTTP-сервер (Ollama/OpenAI) |
| `reference.py` | эталон: обычный torch fp32 |
| `gguf.py`, `gkernels.py`, `gengine.py` | модели GGUF: чтение, перекладка и ядра Q4_K/Q6_K/F16, движок |
| `gcpu.py` | слой GGUF на процессоре (Numba) |

## Чего пока нет

Mac (нужны ядра Metal), AMD, другие семьи моделей (Llama, Mistral, Gemma), модели MoE, угадывание при
случайном выборе (сейчас только при жадном), кэш k, v в fp16 для длинных текстов, установщик одним файлом.
