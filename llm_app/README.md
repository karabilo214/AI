# llm_app

Экспериментальный движок Qwen3: плотные модели HF/BF16 и GGUF, а также Qwen3-MoE/GGUF. Цель — уменьшать вычисления и передачу весов, сохраняя результат целевой модели в согласованном численном режиме.

## Точность

Сжатие BF16 и перекладка Q4_K/Q6_K/F16/F32 сохраняют исходные веса. Это не гарантия битового совпадения разных порядков вычисления CPU/GPU или совпадения текста на любых входах. Greedy с draft проверяет предложения большой моделью; совпадение с прямыми шагами требует экзамена каждого backend и размещения. GGUF KV округляется до fp16, включая CPU-путь, где округлённые значения хранятся в fp32 для Numba.

HF sampling пересчитывает весь словарь, без прежнего вероятностного отсечения. Greedy HF использует консервативный отбор кандидатов и пересчёт; формальная универсальная граница для всех архитектур не заявляется. Speculative sampling при temperature > 0 пока нет: draft в этом режиме отключается.

## Установка

Python 3.12. Общие зависимости: `python -m pip install -r llm_app/requirements.txt`.

Исполнительный GPU-backend требует NVIDIA, совместимый torch с CUDA и Triton для выбранной ОС. Проверенная локально версия torch — 2.15.0 на Mac; это не аттестация CUDA-сборки. Mac/Metal и AMD не реализованы. Тесты управления состоянием и CPU-арифметики запускаются на Mac без Triton.

C++: `sh llm_app/cpp/build.sh`. На Mac собирается Windows DLL через mingw-w64, на Linux — qmm.so через g++. До загрузки проверяются X86_V4/F16C и ABI. При отсутствии поддерживаемой библиотеки плотный CPU-путь использует Numba; MoE требует C++ и завершается понятной ошибкой. Windows/Linux сборки должны пройти отдельную проверку на целевой машине.

## Запуск

```sh
python -m llm_app plan --model qwen3:14b
python -m llm_app serve --model qwen3:14b --draft qwen3:0.6b --tokenizer Qwen3-8B
python -m llm_app serve --model qwen3:30b --draft qwen3:0.6b --tokenizer Qwen3-8B
python -m llm_app chat --model Qwen3-8B
```

`--k 0` — адаптивный черновик, 1–15 — фиксированный. `--maxt` ограничивает контекст. `--resident` задаёт число GPU-слоёв. Для MoE `--no-cpu` допустим, только если все слои размещены в GPU; подкачки MoE без CPU нет. GGUF-токенизатор проверяется по ID и словарю файла; draft должен иметь совместимые ID. Для HF при нескольких snapshots используются refs/main или явно выбранная папка, а не сортировка имён ревизий.

## API

Реализовано подмножество OpenAI chat/completions, Anthropic messages и Ollama chat/generate: обычный и потоковый текст, инструменты, JSON-ограничения GGUF. Полная совместимость всех агентов и всех API-параметров не заявляется. Изображения, несколько completion-вариантов, принудительный выбор конкретного инструмента и неподдерживаемые параметры отклоняются явно.

JSON по схеме проверяется при нормальном завершении. При исчерпании лимита `length` JSON может быть неполным. Размер и сложность схем ограничены, внешние ссылки запрещены; компиляция xgrammar выполняется в отдельном процессе с таймаутом 30 секунд.

`--host 0.0.0.0` открывает доступ по сети. `--api-key` включает Bearer/x-api-key. Допуск соединений и очередь ограничены; отмена останавливает выдачу между вычислительными шагами. Выполняющееся CUDA-ядро не прерывается насильно. `--force-greedy` явно переводит запросы в greedy.

## Метрики

`gen_n`/usage — все выданные токены, включая EOS; `decode_n` — последующие после первого. `prompt_ms`/`first_token_ms` включают чтение запроса и получение первого токена; `gen_ms` — вычисления последующих проходов, без пауз потребителя. При проверке пачки время может включать вычисление отброшенного хвоста: это реальная цена speculative decoding.

В Ollama-совместимом ответе `eval_count` соответствует последующим токенам и `eval_duration`; `total_output_tokens` содержит полный счётчик, `first_token_count` — отдельный первый токен. Это расширение/уточнение локального контракта. Старые результаты и счётчики Ollama нельзя смешивать без проверки одинаковых границ измерения. Скорость после исправлений — в [итоговом отчёте](VERIFICATION_REPORT.md).

## Проверки

```sh
NUMBA_NUM_THREADS=2 python -m unittest discover -s llm_app/tests -t .
python llm_app/cpp/pool_test.py
python -m llm_app.selftest --model Qwen3-8B
python -m llm_app.check_switch qwen3:14b qwen3:0.6b
python -m llm_app.api_test http://127.0.0.1:11435 key
```

Первые проверки доступны локально. Остальные требуют соответствующей модели и разрешённой целевой машины. Ошибки должны давать ненулевой exit code. [Исходный аудит](CODE_AUDIT_REPORT.md), [статус исправлений и ограничения](AUDIT_FIXES.md).
