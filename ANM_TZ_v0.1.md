# ANM — Adaptive Neural Memory
## Техническое задание, версия 0.1 (исследовательский прототип)
Дата: 2026-11-05

## 0. Цель и границы
Создать единую нейронную систему с неизменяемой базовой сетью и встроенными пластичными структурами опыта, подключёнными в нескольких точках промежуточных вычислений. Пластичные структуры обучаются по проверенной обратной связи, могут изменять веса, включать/отключать связи и при необходимости расширять ёмкость. Они воздействуют на предсказания непосредственно, без поиска внешних текстовых воспоминаний.

Система считается исследовательским прототипом, а не заявкой на сознательный ИИ. Не заявлять, что улучшение уже доказано. Не ставить задачей обучение собственной LLM с нуля.

**Жёсткие инварианты:** базовые параметры и конфигурация модели после загрузки не изменяются; отключение всех пластичных путей возвращает исходный выход базовой модели при одинаковых настройках; обучаемые структуры являются узлами *общего* вычислительного графа; исходные параметры и архитектура доступны для восстановления; никакой текстовой базы RAG в тракте вывода.

## 1. Технологии и окружение
- Python 3.11+, PyTorch 2.x с CUDA, Transformers, safetensors; PEFT только как контрольный baseline.
- Этап А: малая собственная модель PyTorch (без LLM), CPU/GPU.
- Этап B: Qwen3-0.6B с 28 Transformer-блоками (или совместимая открытая компактная causal LM); для 8 ГБ VRAM использовать последовательности 128–256 токенов, batch=1, gradient accumulation, при необходимости 4-bit загрузку/CPU offload; подтвердить фактическое потребление тестом до запуска длительного обучения.
- Запись метрик JSONL и SQLite; исходники, тесты, конфигурации и воспроизводимые seeds в Git.
- C# / C++ возможны для оболочки и вызова сервиса, но не обязательны для ядра исследования.

## 2. Архитектура вычисления
Пусть `h_l` — тензор [batch, sequence, hidden] после базового Transformer-блока `l`. Базовые преобразования `F_l` фиксированы: `h_l_base = F_l(h_{l-1})`.

На выбранных границах блоков подключаются пластичные структуры памяти `M_j`. Они действуют *внутри* общего forward-графа, могут влиять на несколько границ и получать входы с нескольких уровней, если это не нарушает причинность токенов.

Первая реализуемая форма:
```
h_l_base = F_l(h_{l-1})
delta_l = sum_j gate[j,l](h_l_base, state_j) * M[j,l](h_l_base, state_j)
h_l = h_l_base + alpha_l * delta_l
```
- Все `gate` и `M` — обучаемые параметры пластичной сети; веса `F_l` заморожены.
- `M` можно использовать как общую структуру с выходными проекциями на несколько уровней; не создавать отдельную внешнюю память рядом с LLM.
- Выход пластичных модулей изначально строго нулевой (zero-init выходной проекции), а `alpha_l` ограничен; включение модулей в нулевом состоянии должно давать базовый ответ.
- Тензоры каждого уровня сохраняют исходную размерность и тип; нельзя нарушать causal mask, позиционные кодировки или KV-cache.
- Обратные связи внутри одного forward допускаются только если задан конечный порядок вычислений (например, 1–2 явно развёрнутых recurrent steps); произвольные циклы в графе запрещены в v0.1.

### 2.1. Основная форма: память как параллельная ветвь каждого блока (изменение от 2026-11-06, по решению заказчика)
Память — часть вычисления каждого Transformer-блока, а не поправка между блоками. Она получает тот же вход, что и блок, и работает одновременно с ним:
```
h_l = F_l(h_{l-1}) + alpha_l * W_l( sum_i a_i * V_i )
a = softmax( cos(Q_l(h_{l-1}), K) / tau ), по ячейкам K_i и ячейке «ничего не подошло»
```
- Ячейки `K_i`, `V_i` — обучаемые веса, общие для всех блоков: одна память на всю модель. Это не внешнее хранилище: нет ни текста, ни поиска вне графа. Запрет RAG действует.
- Каждый токен обращается к ячейкам по смыслу своим активированием. Ячейка «ничего не подошло» имеет нулевое значение и не обучается как значение.
- Форма из начала раздела 2 (поправка на границах блоков) остаётся контрольным вариантом для сравнения.
- Все инварианты раздела 0 сохраняются: при нулевых `W_l` и при отключении выход в точности равен базовому.

**Планка, заданная до запуска (Qwen3-0.6B, те же 20 фактов и перефразированные вопросы).** Ветвь считается успешной, если выполнено всё:
1. воспоминания без подсказки выше 25% и не ниже лучшего результата LoRA (45%);
2. ложные воспоминания не выше, чем у LoRA при том же числе повторов;
3. общие знания не ниже 50%;
4. диагностика: сигнал памяти различает факты заметно лучше, чем у контрольного варианта (сходство сигналов разных фактов ниже 97%), а вопрос и его перефразировка чаще попадают в одни и те же ячейки, чем разные факты.
Если п. 1 не выполнен на лучшем варианте после 3 seed, место встраивания не считается решением проблемы.

В дополнение к остаточным поправкам реализовать варианты для сравнений: (a) additive residual, (b) gated residual, (c) низкоранговые преобразования внутри `q_proj`, `v_proj`, `o_proj`, `down_proj`. Для v0.1 достаточно (a)+(b); (c) — контрольная реализация в следующем этапе.

## 3. Пластичная группа и изменение топологии
Структура памяти представляет собой обучаемый граф с конечным числом слотов нейронов и связей, не внешнее хранилище фактов.

Для каждой группы:
- `group_id`, список точек подключения (`target_layers`), trainable weight tensors, бинарные masks активных связей, gate-weights, usage counters, quality statistics, optimizer state, generation ID.
- Начальный размер: configurable `hidden=64`, `capacity=128`, active_fraction=0.25 (на малой сети); параметры для LLM определяются бенчмарком VRAM.
- Добавление связи: выбрать неактивный слот по градиентному сигналу/контролируемой пробе; инициализировать нулём или малым значением; обучить, оценить на отложенных примерах; подтвердить только если качество не ухудшилось.
- Отключение связи: сначала поставить mask=0, не стирать оригинальные веса или историю; подтвердить только после сравнения с включённой связью. Размер веса **не является** доказательством бесполезности.
- Удаление: логическое, с возможностью rollback. Физическое уплотнение параметров — отдельная офлайн-операция.
- Расширение группы: когда порог заполнения >80% и новые факты не усваиваются при текущей ёмкости; расширить tensor, masks, optimizer state, сохранить совместимость соединений, новый слот инициализировать с нулевым влиянием.
- Уменьшение размера: только после длительной неактивности и положительного теста абляции. Базовые связи не удаляются никогда.
- Каждое структурное изменение имеет transaction ID, checkpoint до/после, метрики и обратимую операцию.

В v0.1 использовать разреженные маски поверх плотных небольших тензоров для удобства автодифференцирования. Не заявлять реальную экономию FLOPS: mask сама по себе не ускоряет плотные GEMM. Источник алгоритмического вдохновения: RigL (prune low-magnitude / grow via gradient), но обязательно проверять вклад на тестах.

## 4. Событие опыта и критерии доверия
Опыт — не строка в prompt и не готовая справка. Это тренировочное событие, которое производит градиент/корректировку пластичной структуры, плюс служебная запись для воспроизводимости.

Схема `ExperienceEvent`:
```
{
  "event_id": "uuid",
  "timestamp": "iso8601",
  "input": "...",
  "prediction": "...",
  "verified_target": "... | null",
  "feedback_source": "unit_test|deterministic_oracle|human_verified|self_estimate",
  "confidence": 0.0,
  "loss": 0.0,
  "impact": 0.0,
  "novelty": 0.0,
  "repetition_group": "string|null",
  "consent_scope": "local_experiment",
  "train_eligible": false
}
```
- `self_estimate` не может единолично подтверждать истинность или немедленно запускать обучение.
- Значимость события (impact) отделена от величины ошибки (loss): высокое отклонение по вероятности не всегда означает высокую цену ошибки.
- Повторения считать по независимым подтверждениям, а не по дубликатам одного сообщения.
- Для внешней обратной связи различать наблюдение, гипотезу, подтверждение; эмоциональные предположения не использовать как «истину» без согласия/уточнения.
- Критический подтверждённый эпизод немедленно сохраняет checkpoint/метаданные и допускает короткую тренировку *кандидата*; новая версия подключается только после регрессионных тестов. Это не гарантия, что один случай можно выучить без побочных эффектов.
- Не хранить личную информацию пользователей в обучающей выборке без соответствующего согласия; поддержать удаление события и повторное обучение адаптивных параметров с чистого checkpoint при необходимости. Удаление записи из журнала не гарантирует удаления влияния уже выполненного обучения.

## 5. Алгоритм онлайн-адаптации
1. `forward`: исполнить базовые Transformer-блоки и встроенные пластичные изменения; собрать prediction и диагностические активации.
2. `observe`: получить проверяемый результат извне (oracle/test/human). Если результата нет, **не** считать собственный ответ правильным только из-за уверенности модели.
3. `score`: оценить loss, consequence/impact, confidence, novelty, repetitions.
4. `route`: вычислить обучаемые gate и активность групп. Группы не обязаны быть размечены предметными областями вручную.
5. `candidate_train`: сохранить snapshot; обновить только веса памяти (`requires_grad=False` для базы; optimizer включает только plastic tensors). Реализовать ограничение gradient norm, learning rate schedule, replay проверенных эпизодов и регуляризацию.
6. `validate`: провести отложенные тесты новой задачи и регрессионный набор ранее освоенных задач.
7. `commit/rollback`: принять изменения только при прохождении критериев; иначе восстановить checkpoint.
8. `structural_update`: с заданной периодичностью анализировать потенциальные grow/prune; отдельно тестировать каждую серию изменений; трассировать версию графа.

Ключевой принцип: нейросеть не должна учиться на любом собственном тексте без независимой оценки результата.

## 6. Тестовые среды и экспериментальные группы
Два уровня тестов:
**A. Малый контролируемый стенд** — синтетические задачи без LLM. Базовая модель предварительно учится на двух закономерностях; новые две закономерности появляются последовательно. Есть oracle для 100% проверяемого ответа.
**B. Текстовый стенд** — Qwen3-0.6B с задачами: искусственный язык команд с секретными семантиками, небольшие функции с автоматическими юнит-тестами и задачи по корректировке заданных правил. Секретные правила создаются детерминированным seed после выбора базовой модели; одинаковые тесты дают baseline, память, baseline-LoRA и ANM.

Конфигурации (одни и те же данные, seeds, бюджет обновлений):
- A0: исходная модель без модификаций;
- A1: исходная модель + фиксированная внешняя память в контексте (контроль, **не** целевая архитектура);
- A2: LoRA с фиксированной топологией (контроль);
- A3: встроенная память с фиксированными связями и gating;
- A4: встроенная память с gating + динамическим grow/prune.

Тесты:
- `unseen_combinations`: обобщение на новых входах, не присутствовавших в обучении;
- `retention`: повторная проверка старых задач после обучения новым;
- `context_reset`: отключить историю, внешнюю память и везде подать идентичный чистый prompt;
- `baseline_restore`: отключить пластичные соединения и сверить logits с базой;
- `false_feedback`: специально давать 10% ложных feedbacks; они не должны приниматься как достоверные без независимого подтверждения;
- `prune_ablation`: сравнить сеть до/после отключения связей;
- `capacity`: сравнить фиксированную и растущую ёмкость при одинаковом вычислительном бюджете;
- `multi_seed`: не менее 5 независимых seeds, публиковать среднее, разброс и raw results.

Метрики: accuracy на скрытом тесте; success@1 для кода, процент проходящих unit tests; forgetting = old_accuracy_before - old_accuracy_after; invalid_update_rate; rollback_rate; trainable_parameters; actual GPU memory; wall-time; latency; количество добавленных/отключённых соединений. Для генеративного текста тестировать детерминированным decoding с одинаковыми настройками.

## 7. Критерии приёмки (предварительно установленные экспериментальные пороги)
**A. Функциональная корректность**
- Базовый checksum SHA-256 не меняется ни после одного train step.
- Отключение всех пластичных групп воспроизводит базовые logits (max abs diff ≤ 1e-5 в FP32 на игрушечной сети; для mixed precision порог определить из реальной численной точности).
- Градиенты только у пластичных параметров; базовые `grad` отсутствуют или всегда не используются.
- Grow/prune, save/load, rollback, and mask serialization покрыты тестами; после повторной загрузки результат совпадает в пределах численной точности.
- Нет утечки тестовых ответов в train или сохранённые подсказки; тест-датасет неизменяем.

**B. Экспериментальная полезность**
- На малом стенде A4 статистически превосходит A0 по задаче нового правила и сохраняет ≥95% исходного уровня качества на старых правилах; числа — цели эксперимента, не обещание результата.
- После сброса контекста и без внешней памяти наблюдается улучшение A4 над A0 на отложенных новых примерах (порог полезности: ≥10 процентных пунктов, среднее 5 seeds; дополнительно анализировать доверительный интервал).
- Рост структуры демонстрирует прирост над A3 при сопоставимом числе активных параметров/вычислений; если нет, честно зафиксировать отрицательный результат и не расширять проект.
- A4 сравнивается с A2 при одинаковом бюджете обучения; если A2 лучше, это не авария, а важный научный результат.

## 8. Этапы работ и deliverables
### E0 — Инфраструктура
Создать CLI (`train-base`, `train-memory`, `eval`, `inspect-graph`, `rollback`, `export-metrics`), конфиг YAML, логирование, воспроизводимость, тесты. Результат: reproducible training loop.

### E1 — Игрушечная общая сеть
Написать PyTorch сеть 6 базовых блоков с двумя/тремя встроенными пластичными группами в разных точках. Тестировать точность и заморозку базовых весов. Результат: единая сеть, пластичные структуры влияют на конечный выход.

### E2 — Пластичность графа
Добавить mask-based grow/prune, reserve capacity, checkpoint/rollback, group gating, replay. Результат: структура реально меняет число активных соединений и может откатываться без изменения базового ядра.

### E3 — Непрерывное обучение
Запустить последовательные задачи, отложенные тесты, ложную обратную связь, формирование групп опыта по активациям и градиентам. Результат: таблицы и графики реальной адаптации, забывания и роста.

### E4 — Перенос в Qwen3-0.6B
Найти интерфейсы блоков, внедрить hooks/wrappers или собственные модули на границах 4–6 выбранных Transformer-блоков (контрольный вариант) и параллельную ветвь в каждый блок (основной, раздел 2.1). Сначала residual injection, затем gated structures. Проверить baseline equivalence, KV-cache и память GPU.

### E5 — Проверка гипотезы
Сравнить A0–A4 на идентичных данных. Выпустить report.md: таблица результатов, стоимость, ошибки, reproducibility, решение go/no-go. Не писать о «новом интеллекте» без измеряемых подтверждений.

## 10. Ошибки реализации, которые недопустимы
- Подменять встроенную память RAG, embeddings database или текстовыми prompt-историями.
- Учить baseline weights, даже случайно, либо сохранять изменённый базовый checkpoint.
- Выдавать новый LoRA-адаптер *после* ответа за доказательство предложенной интегрированной структуры.
- Назначать одному воспоминанию один физический слой без обоснования.
- Удалять соединения исключительно по малой абсолютной величине весов без абляции.
- Создавать произвольные циклы без фиксированной развёртки времени и проверки градиентов.
- Засчитывать тесты, попавшие в обучение, как обобщение.
- Принимать уверенную самооценку LLM как достоверную обратную связь.
- Утверждать улучшение способности без сравнения с фиксированным LoRA и обычным обучением.

Прежде чем подключать настоящую LLM, предъявить: 1) тензорные размеры и вычислительный граф; 2) исходные и новые logits на двух тестовых примерах; 3) доказательство неизменности хеша всех базовых параметров после обучения; 4) рост качества на невиденных примерах; 5) работу `disable_memory=true`, которая возвращает исходную сеть; 6) тесты с реальным запуском и журналом метрик. Не заявлять завершение без результатов тестов.
