# Палитра RAMVI

Общая палитра для десктопного приложения и будущего сайта. Цвета подобраны по визуальным мотивам логотипа, а не извлечены автоматически из пикселей. Это предложение для интерфейса; подключение к оболочке ещё не реализовано.

## Файлы

- [Наглядный образец обеих тем](palette-preview.html): открыть в браузере, кнопки имеют hover/focus/pressed.
- [palette.json](palette.json): основной источник HEX-токенов, независимый от UI-фреймворка.
- [palette.css](palette.css): те же токены как CSS variables, выбор через `data-theme="light"` / `data-theme="dark"`.
- [contrast-report.json](contrast-report.json): рассчитанные отношения контраста для предусмотренных пар.

|---|---|---|
| Фон | `#F7F5FB` | `#14101C` |
| Поверхность | `#FFFFFF` | `#1E172A` |
| Основной текст | `#241735` | `#F4EFFB` |
| Вторичный текст | `#685B78` | `#C0B2D0` |
| Основное действие | `#6928BD` | `#B58AFF` |
| Текст на основном действии | `#FFFFFF` | `#241035` |
| Коралловый акцент | `#FF8868` | `#FFAA8F` |
| Текст на коралловом | `#35162C` | `#35162C` |
| Тень (тёмная) | `#D6CCE6` | `#07050B` |
| Тень (светлая) | `#FFFFFF` | `#251D33` |

Фиолетовый объединяет приложение с логотипом. Коралловый выделяет редкие дополнительные действия и брендовые детали. Основная площадь экрана остаётся спокойной: нейтральные поверхности с лёгким фиолетовым оттенком. Градиенты логотипа допустимы в приветствии и материалах сайта; рабочие панели и текстовые кнопки используют сплошные заливки.

## Правила применения

1. Компоненты используют семантические имена (`primary`, `text`, `surface`), а не конкретные оттенки из `brand`. Это позволяет менять тему без изменения компонентов.
2. Для каждого фона используется предусмотренный цвет текста: особенно `on-primary`, `on-accent`, `on-selection`. Белый текст на коралловой кнопке не предусмотрен.
3. `border` — мягкое декоративное разделение. Если граница нужна для распознавания поля или контрола, использовать более контрастный `control-border`. Фокус обозначать отдельным внешним контуром `focus` с отступом.
4. Успех, предупреждение, ошибка и информация имеют свои пары текста/подложки. Всегда добавлять текст или значок: один цвет не должен передавать состояние. Коралловый брендовый акцент не означает ошибку.
5. Отключённые элементы используют `disabled-bg` / `disabled-text` и реальное disabled-состояние. Снижать прозрачность обычного текста вместо этого не следует.
6. Chat, Agent и Character используют одну палитру. Состояния эмоций персонажа не меняют смысл системных цветов ошибок/разрешений.
7. Для веба подключить CSS; для Avalonia или другой десктопной оболочки создать адаптер ресурсов из JSON, сохранив имена. JSON — источник истины, CSS не редактировать отдельно. Выбор темы: системная, светлая, тёмная; ручной выбор сохранять.
8. Оболочка выполнена в неоморфизме (3.16): поверхности цвета `background`, объём — двумя тенями `shadow-dark` / `shadow-light`. Тени декоративны и не несут смысла; текст и контуры полей проверяются так же, как без них. Ресурсы Avalonia генерирует `desktop/tools/palette_to_axaml.py`.
9. Текущий логотип содержит тёмную надпись. На тёмной теме временно использовать светлую подложку, как в образце. Отдельную светлую версию логотипа подготовить до выпуска тёмного интерфейса.

## Проверка

Для указанных сплошных sRGB-цветов рассчитаны 46 пар: текст на предназначенных поверхностях и состояниях кнопок, статусные пары, фокус и границы контролов. Минимальное отношение среди проверенных текстовых пар — **5,15:1**; все проверенные текстовые пары выше 4,5:1, контуры выше 3:1. Расчёт использует относительную яркость sRGB и `(Lmax + 0.05) / (Lmin + 0.05)`.

Это проверка токенов, а не готового приложения: после интеграции отдельно проверить реальные размеры текста, фокус клавиатуры, масштабирование, системный режим высокой контрастности и состояния компонентов. Смешивание прозрачностей и новые сочетания требуют нового расчёта.
