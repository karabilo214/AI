# Character · модуль 0.2.0

`ramvi_character` — необязательный модуль. Его манифест находится в
`modules/character/manifest.json`. Host запускает отдельный worker только при
открытии раздела «Персонаж». Core/Chat/Agent модуль не импортируют.

## Готово

- Lifecycle initialize/activate/deactivate/suspend/resume/dispose.
- Текстовый режим без STT/TTS/LLM/renderer/human_brain. Пока это состояние
  редактирования (черновик и выбранная модель), не генерация ответов.
- Checkpoint в собственном namespace модуля: черновик, модель и эмоция.
  Перезапуск не возобновляет старую речь или анимацию.
- `present(emotion, animation)` принимает только состояния пакета и возвращает
  версионированную директиву. Это основа будущего вывода Response Planner,
  а не подключённый сейчас LLM. Имена файлов, программы и команды не принимаются.
- Самодостаточный пакет ресурсов и отдельный Avalonia-проигрыватель в оболочке.
  Контролы в разделе «Персонаж» пока проверяют изображение локально; доставка
  потоковых директив от worker, диалог и голос относятся к следующим шагам.

## Профили и эмоции (9.2–9.3)

`personality.py` и `definitions/profiles.json`: пять встроенных профилей версии
1.0.0, пользовательские версии и восемь черт 0–1. Базовый профиль, явные
настройки, границы и приобретённые поправки разделены. Границы выше настроек,
настройки выше поправок. Автоматическая адаптация пока не включена.

Вызовы worker: `profiles`, `select_profile`, `add_profile`, `set_preferences`,
`set_boundary`. Это управляющие вызовы владельца, не инструменты LLM.
Профили и границы пока настраиваются программно; редактор UI — 9.13.

`emotions.py` и `definitions/emotions.json`: первичное/вторичное состояние,
интенсивности, затухание по времени, возвращение к neutral и новые состояния
без изменения Core. `react` принимает событие с оценками силы/значимости/
новизны/уверенности; `appraise` — проверенные изменения компонентов;
`add_emotion` — новое определение. Анализа естественного языка здесь ещё нет.

Checkpoint state/2 сохраняет обе подсистемы и читает старый state/1.
Эмоциональная оценка отделена от визуального `present`: переключение картинки
не подменяет осмысление реплики. Доставка директив и LLM/TTS пока впереди.
Подробности и проверки — [9.2–9.3](../docs/reports/CHARACTER_STATE.md).

## Утверждённое поведение

Кивок и «нет» — 2×, остальные движения — 1×. Idle — лёгкое покачивание
выбранного выражения без моргания. Моргание — отдельное действие.
Изменение эмоции не сбрасывает фазу разговора. После однократного жеста
возвращается idle с прежней эмоцией.

Электронные talk-звуки, shake_head и beep_no не включены в рабочий пакет.
Разговор и «нет» озвучиваются через TTS; TTS пока не подключён.
Остальные звуки сохранены как ресурсы, автоматического воспроизведения
в приложении сейчас нет. Текст или эмоция от LLM сами по себе не включают
микрофон, не дают права управлять окнами и не запускают системные действия.

## Ресурсы и сборка

Оригиналы остаются в `assets/branding/`. Команда из корня репозитория:

```sh
python3 ramvi/character/tools/build_assets.py
```

Рабочий пакет `ramvi_character/assets/pack.json` имеет схему
`ramvi.character.pack/1`: 72 PNG, 62 WAV, 13 выражений, 5 движений.
Исходные кадры idle с морганием в пакет не копируются. У idle указан renderer
`expression_bob`, а не список картинок. Фронтальная мимика сохраняется
отдельными слоями; повороты пока только стилизованные деформации исходника.
См. также исходные README наборов: права на персонажа сохраняются за
правообладателем, процедурные звуки заявлены исходным набором как CC0-1.0.

Переносимый комплект копирует код/ресурсы Character и манифест; путь к модулю
добавляется во встроенный Python. Можно собрать отдельный wheel без зависимостей.
Сам сервис Character не требует, отсутствие модуля не меняет обычный чат.

Проверки и границы готовности — [отчёт](../docs/reports/CHARACTER_BOOTSTRAP.md).
