# ADR-0001: структура RAMVI

Статус: принято. Дата: 2026-11-13.

## Контекст

RAMVI развивается в существующем репозитории. Рабочий движок и проверочные материалы уже существуют; нужен последовательный перенос с сохранением истории и поведения. Техническое задание описывает приложение, движок, сервис и дополнительные подсистемы как отдельные части.

## Решение

1. Весь новый код продукта и его документация находятся внутри `ramvi/`.
2. Движок размещается в `engine/ramvi_engine/` с подпакетами `core`, `kernels`, `cpu`, `native`, `formats`, `planning`, `generation`, `server`. Перенос выполняется в пункте 1.4, разделение HTTP-модуля — в 1.5.
3. Сервис, агент, голос и хранилище получают отдельные пакеты `ramvi_service`, `ramvi_agent`, `ramvi_voice`, `ramvi_storage`. Тесты и инструменты отделяются от исполняемого кода. Подробная целевая схема — в [плане](../PLAN.md).
4. Python-код использует Python 3.12. Общая конфигурация Ruff, mypy и pytest находится в `pyproject.toml`: форматирование и lint, строгая проверка типов нового кода, тесты без обязательного GPU.
5. Зависимости разработки перечислены в группе `dev` и зафиксированы по версиям. Текущий `pyproject.toml` задаёт инструменты; сборочная конфигурация компонентов появляется при их реализации. Пустой устанавливаемый пакет приложения не создаётся.
6. Локальные данные, модели, логи, результаты и производные сборки исключены из git. Пути рабочего окружения не записываются в исходники. Лицензия продукта — MIT с согласованным правообладателем.
7. `llm_app` сохраняется до успешного экзамена переноса 1.9 и удаляется только в 1.11. Импорты, команды и проверки переводятся последовательно; документы не означают, что код уже перенесён.
8. Оболочка приложения пока не выбрана. Сравнение вариантов и решение оформляются отдельным ADR по пункту 3.1.

## Последствия и проверка

Для документации и общих проверок достаточно лёгкого окружения разработчика; PyTorch, CUDA и модели не устанавливаются вместе с инструментами каркаса. Перенос старого движка не совмещается с изменением алгоритмов. Новые пакеты включаются в проверки типов и тестов по мере появления.

Для пункта 1.3 проверяются установка группы `dev`, Ruff lint/format, mypy strict, pytest и локальные ссылки документации. Продуктовая работоспособность, скорость и точность подтверждаются отдельными экзаменами плана.
