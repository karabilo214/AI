# ADR-0004: движок распознавания речи (STT)

Статус: **принято** 2026-11-18. Решение владельца: **whisper.cpp + модель large-v3-turbo q5_0**, плюс необязательное распознавание через сторонний API (вкладка «Звук» в настройках). Пункт 5.1 [PLAN.md](../PLAN.md), требования VOI-01…VOI-03 ТЗ.

## Решение

1. **Локальное распознавание по умолчанию — whisper.cpp**, модель `ggml-large-v3-turbo-q5_0.bin` (574 041 195 байт, SHA-256 `394221709cd5ad1f40c46e6031ca61bce88931e6e088c188294c6d5a55ffa7e2`). Работает без сети, на процессоре (VOI-03); видеокарта — только если свободна, решение в 5.4 по замеру.
2. **Запасная модель для слабых машин** — `ggml-small-q5_1.bin` (190 085 487 байт, SHA-256 `ae85e4a935d7a567bd102fe55afc16bb595bdb618e11b2fc7591bc08120411bb`): втрое быстрее, но украинский заметно хуже (таблица ниже).
3. Модели в комплект не кладутся: скачиваются менеджером загрузок (4.3) при первом включении голоса, с проверкой SHA-256.
5. **Детектор речи Silero** (`ggml-silero-v5.1.2.bin`, 885 098 байт, SHA-256 `29940d98d42b91fbd05ce489f3ecf7c72f0a42f027e4875919a28fb4c04ea2cf`, встроен в whisper.cpp) включён всегда, запас вокруг речи 1000 мс. Без него на тишине whisper выдумывает текст (на Mac и Windows — «Продолжение следует...»). Скачивается вместе с моделью распознавания.
4. **Распознавание через API — по выбору пользователя** (пункт 5.7): один адаптер для стандарта `POST /v1/audio/transcriptions` (OpenAI, Groq и другие совместимые сервисы, локальные серверы в сети). Google Cloud Speech-to-Text — позже отдельным адаптером (бэклог B.9). Условия:
   - по умолчанию выключено, работает локальный whisper.cpp;
   - пока выбран API, у кнопки микрофона видна метка «звук отправляется в <сервис>»;
   - ключ хранится только через `SecretBackend` сервиса — не в `settings.json` и не в журналах;
   - нет сети или ошибка сервиса — понятная ошибка и предложение распознать локально, без тихого переключения.

6. **Видеокарта — отдельной загрузкой** (решение владельца 2026-11-18, пункт 5.4). На Windows с NVIDIA в разделе «Звук» можно скачать ускоритель — официальную сборку whisper.cpp `b5454` с CUDA 12.4 (`whisper-bin-win-cuda-12.4.0-x64.zip`, 684 913 404 байта, SHA-256 `afef0b881c500958921c3f5523b50e59ee2ec9b6f5cbd25b324c51ed308a957a`; из архива берутся 17 файлов: `whisper-server.exe`, ggml, cuBLAS 12, cudart). Библиотеки CUDA из torch комплекта не подходят (CUDA 13), сборка под CUDA 11.8 не видит RTX 5060. При каждой записи: видеокарта, если ускоритель скачан, свободно ≥ 1312 МиБ видеопамяти (пик whisper-server 1056 + запас) и ≥ 683 МБ RAM (пик 427 + запас); иначе CPU, если свободно ≥ 1419 МБ RAM (turbo), иначе small (≥ 1053 МБ), иначе ошибка `voice.no_memory`. `whisper-server` живёт одну запись (127.0.0.1, свободный порт, звук — WAV в теле запроса) и сразу останавливается, освобождая видеопамять. Процесс на CPU работает с пониженным приоритетом.

## Рассмотренные варианты

| Вариант | Итог |
|---|---|
| **whisper.cpp** (через `pywhispercpp` 1.5.1, внутри whisper.cpp) | **Выбран**: точность как у faster-whisper, памяти вдвое меньше, колесо под Windows 1,3 МБ |
| faster-whisper 1.2.1 (CTranslate2, int8) | Отклонён: та же точность, памяти 1,8 ГБ против 0,9, зависимости ~66 МБ (ctranslate2 19,5 + av 26,8 + onnxruntime 15,9 + tokenizers 2,7 МБ) |
| Vosk 0.3.44, small-модели | Отклонён: ~21% ошибочных слов на всех языках, не определяет язык сам, нужна отдельная модель на каждый язык |

Способ подключения whisper.cpp (Python-колесо `pywhispercpp` в процессе-исполнителе или готовый `whisper-cli` отдельным процессом) — решается в 5.2; на результат замера не влияет, движок один.

## Замер

Mac M1 Pro (8 производительных + 2 экономных ядра), **только процессор** (`use_gpu=False`, у faster-whisper `device="cpu"`), 4 потока. Данные: FLEURS dev (Google, CC-BY 4.0), первые 20 или 40 записей RU/UK/EN — живая речь, 6–7 минут на язык при 40 записях. «Ошибки» — доля неверных слов после приведения к нижнему регистру и удаления знаков препинания (ё = е). Числа: whisper пишет цифрами, в эталоне FLEURS бывают и слова, и цифры, — расхождение считается ошибкой у всех движков одинаково. «Время» — секунд обработки на секунду речи. Память — пик процесса.

Заведомо решаемая проверка до сравнения: по 5 коротких фраз на язык, озвученных системными голосами macOS (Milena, Lesya, Samantha). Все три движка распознали их с верным языком; ошибки — отдельные окончания и цифры вместо слов.

### Windows (ноутбук: Ryzen 7 260, 8 ядер / 16 потоков), только CPU

Тот же комплект `runtime\python` + колёса `pywhispercpp` 1.5.1 и `sounddevice` 0.5.6 для win_amd64. whisper.cpp в колесе: AVX2, FMA, OpenMP; AVX-512 и BLAS нет. Короткая фраза (2 с), язык задан, без детектора, 3 повтора:

| Модель | 4 потока | 8 потоков | 12 потоков | 16 потоков |
|---|---:|---:|---:|---:|
| turbo q5_0 | 11,6 с | 7,0–7,6 с | 6,5 с | 6,35 с |
| turbo q8_0 (874 МБ) | — | 5,1 с | — | 4,65 с |
| turbo f16 (1,6 ГБ) | — | 6,3–6,5 с | — | 6,2 с |
| small q5_1 | — | 1,3–1,5 с | — | 1,3 с |

Через сервис (8 потоков, детектор 1000 мс): фраза 2–14 с — 7,5–7,9 с с заданным языком, 14,6–15,6 с с «auto»; тексты те же, что на Mac. **На Windows CPU turbo медленнее Mac в ~2,5 раза**: на Mac whisper.cpp считает через Accelerate, в колесе для Windows матричного ускорения нет. Что делать — пункт 5.4 (видеокарта при свободной памяти, q8_0, small для слабых машин).

Запись на Windows: интерфейс MME обрезает имена до 31 символа и добавляет служебное «Переназначение звуковых устройств»; поэтому берётся WASAPI (полные имена), а 16 кГц моно открывается только с `WasapiSettings(auto_convert=True)` — без него «Invalid sample rate».

### 5.4: видеокарта и соседство с LLM (ASUS, RTX 5060 8 ГБ, драйвер 616.92)

Официальные сборки `b5454`, фраза 2 с, turbo q5_0, язык задан, 8 потоков:

| Сборка | Кодировщик | Всего (с загрузкой модели) |
|---|---:|---:|
| CPU (выбор ядер, cascadelake) | 5,8–6,2 с | 6,3–6,7 с |
| CPU + OpenBLAS | 6,0–6,1 с | 6,5–6,6 с |
| CUDA 12.4 | 0,14 с | 0,69 с (первый запуск 37 с — драйвер собирает ядра под sm_120, дальше кэш) |
| CUDA 11.8 | видеокарту не видит, CPU | 6,3–6,9 с |

Через сервис с ускорителем (`whisper-server`, без LLM): запуск 3,2 с (пока человек говорит), после остановки записи 0,30–0,55 с, язык 12/12, после каждой записи видеопамять 0 и процессов нет. Пик видеопамяти: turbo q5_0 1056 МиБ, q8_0 1342, small 726.

С загруженным 14B Q4_K_M + угадыватель 0.6B (движок комплекта, занято 6338 МиБ, свободно 1562): голос выбрал видеокарту; во время генерации (запрос 1648 токенов, ответ 160) распознавание 0,97–1,05 с, генерация 20,0 / 20,0 с против 19,7 / 19,7 с без голоса (+1,5 %), пик видеопамяти 7335 из 8151 МиБ, ошибок нехватки памяти нет. Свободной RAM при 14B — 0,3–0,8 ГБ: CPU-распознавание отказало с `voice.no_memory` (нужно 1419, свободно 778), генерация не пострадала. `whisper-server` держит до 427 МБ RAM.

## Найденные ограничения (решать в 5.2 и 5.4)

1. **Постоянная цена вызова.** whisper всегда считает окно 30 с, поэтому turbo тратит ~3,4 с на фразу любой длины: 5 коротких фраз (12–17 с речи) — 17 с с заданным языком.
2. **Режим «auto» вдвое медленнее** при том же тексте: язык определяется отдельным проходом кодировщика (те же 5 фраз — 34 с).
3. **Укороченное окно (`audio_ctx`) не подходит для turbo**: при окне по длине фразы + 64 доля ошибочных слов 51–80% на FLEURS RU/UK и 251% на коротких фразах EN (модель выдумывает текст). Отброшено.
4. **Windows CPU медленный** (таблица выше): 7,5 с на фразу с заданным языком, 15 с с «auto»; официальные CPU-сборки с AVX-512 и BLAS не быстрее. Решено видеокартой (пункт 6 решения), CPU остаётся запасным путём.
5. **При 14B на 16 ГБ RAM распознаванию на CPU места нет** — голос работает только на видеокарте или сообщает о нехватке памяти.
