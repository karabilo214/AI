## Методика и ограничения

- Скорость — сумма eval_count / сумма eval_duration. Для сравнения по одному вопросу также объединяются оба повтора; среднее скоростей не используется.
- TTFT — время первого непустого фрагмента по часам HTTP-клиента. Загрузка модели, прогрев и отдельные контроли не входят в измеряемые 30 запросов.
- Перед сравнением проверены одинаковые задачи, параметры, веса, токенизатор и размещение слоёв. Внутри каждого варианта hash кода одинаков во всех рядах.
- Ollama не запускалась; взят исторический JSON на тех же 30 вопросах. Это не одновременный A/B-замер с Ollama; её архив не содержит полного манифеста.
- Как в прежнем сравнении, eval_count нашего API исключает первый токен; архив Ollama не выделяет его отдельно. Историческая методика сохранена.
- Два повтора показывают наблюдаемый разброс; сами по себе они не доказывают статистическую значимость изменения скорости. Итог приёмки требует также контролей plain/draft, fp32 и проверки завершения процессов из журнала запуска.
- Совпадение текстов с Ollama не является критерием переноса: эталон поведения — наш движок до переноса. Сравнение текстов всех шести пар приведено выше.

Полные ответы остаются во входных JSON. Машиночитаемые итоги: `summary.json`, таблица: `comparison.csv`. SHA256 входных файлов и манифесты — в `summary.json`.

## Контроли до WIDE30

В замороженном снимке на Windows прошли **184 теста и 125 подслучаев**. Это включает прежние 89 тестов; их число не является замером скорости.

Через новый общий диспетчер выполнены две самопроверки HF Qwen3-0.6B по 48 токенов на каждый из трёх запросов: обычная и `resident=0` с draft Qwen3-0.6B. В обоих случаях совпадение с эталоном fp32 — 3/3; кэш продолжения совпал; все три последовательности с draft совпали с обычной генерацией. Это fp32-проверка HF 0.6B, не полная fp32-проверка квантованной 14B.

Также прошли девять GPU F32-кейсов, семь размеров графа с сохранением KV и native-матрицы 14B против декодированной матрицы (максимальная напечатанная относительная ошибка 2,3·10⁻⁷).

Расширенная проверка API на Qwen3-8B + draft прошла: авторизация, одинаковый потоковый и обычный ответ, нулевой бюджет, JSON Schema, обрезка по длине, отмена и повторный запрос. Официальные клиенты OpenAI/Anthropic и HTTP-запросы Ollama дали **14/14** успешных проверок. Ollama как процесс не запускалась.

Перед каждым из четырёх рядов проверены восемь сравнений обычного target и target с draft, именно по спискам токенов. Арифметические контроли дали `4`, `3973`, `100032`; ещё пять — WIDE №1, 9, 13, 20, 29. Все 32 сравнения прошли, списки токенов совпали и между запусками. Plain target — контроль без угадывания; это не гарантия истинности всех ответов WIDE.

До первого WIDE внешний сценарий потребовал исправления пути импорта инструмента. Модельный код не менялся, завершённые проверки сохранены; ни один измеренный ряд до этой поправки не начинался. Во время всех четырёх рядов исходники и параметры неизменны.
