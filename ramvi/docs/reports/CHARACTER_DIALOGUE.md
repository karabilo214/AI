# Character 9.5–9.6: структурированный ответ и текстовый диалог

Дата проверки: 2026-11-19. Модуль `ramvi-character` 0.4.0.

## Что реализовано

- `response.py` и `definitions/response.schema.json`: JSON Schema Draft 2020-12,
  версия `ramvi.character.response/1`, intent, семантическая эмоция, интенсивность,
  ID/порядок сегментов, текст, стиль голоса, анимация и предложения памяти.
- Поток — NDJSON: `start`, от одного до восьми `segment`, `end`. Только целая,
  прошедшая схему и проверку последовательности запись становится событием.
  Текст JSON, reasoning и незавершённая строка не управляют представлением.
- Без streaming провайдер возвращает массив записей. Весь документ проверяется
  до выдачи первого события. Strict structured streaming не требуется: проверка
  выполняется внутри Character. Не заявляем поддержку JSON Schema самим движком.
- Разрешённые эмоции берутся из реестра Character, стили/анимации — из доверенного
  набора возможностей. В текстовом прототипе разрешены `neutral` для голоса и
  `none` для анимации; подключение renderer/TTS остаётся отдельными пунктами плана.
- Лимиты: восемь сегментов, 2048 UTF-8 байт на текст сегмента, 16 000 байт на
  объединённый текст, 8192 байта на строку, 48 000 байт на структурированный ответ.
  До четырёх предложений памяти, текст до 512 байт; evidence только из контекста,
  оставшегося после сокращения. NaN, неизвестные поля и привилегированные команды
  отклоняются.
- Если корректных сегментов ещё не было, ошибка формата допускает одну отдельную
  генерацию обычного текста. Этот fallback ограничен, разбит по UTF-8 границам и
  также проверен схемой; эмоция нейтральная, анимации и записи памяти нет.
  После частично принятого потокового ответа ошибка завершает ответ; повтор уже
  выданных сегментов не выполняется. Без полного корректного завершения кандидаты
  памяти не публикуются. Даже опубликованный кандидат имеет статус `candidate`,
  не подтверждается и не записывается автоматически как факт.

## Runtime и интерфейс

`dialogue.py` обращается только к scoped `llm.*` и `data.*`; UI открывает одну
явно объявленную команду `dialogue` через общий `/sections/{id}/commands/{command}`.
Core не импортирует Character и не разбирает его эмоции или протокол. Другие
методы worker, включая lifecycle, через этот маршрут недоступны.

Ответ выполняется в отдельном потоке модуля; запуск, опрос и отмена — короткие
вызовы RPC. Модель выбирается через общий `SwitchableProvider` внутри общей
очереди LLM. Используется точный локальный tokenizer/chat template, без thinking,
с предварительным бюджетом контекста 8192 и резервом ответа 1536 токенов. Если
токенизатор не настроен, ответ завершается ошибкой вместо неточного подсчёта.
Новый endpoint `llm.capabilities` ничего не загружает.

Каждый ответ получает серверный response_id. Stop, смена модели, профиля или
границ отменяют текущий ответ. Поздние события отбрасываются и в модуле, и в UI.
Новый ответ начинается после завершения предыдущего потока. Lifecycle не
восстанавливает незаконченные генерации. Неотменяемый синхронный вызов провайдера
может завершаться до собственного таймаута; его результат после Stop не выдаётся.

История хранится отдельно от Chat/Agent и checkpoint: `dialogue.json` в собственном
namespace модуля, атомарная запись, до 16 целых обменов и 32 000 байт. Старые целые
обмены удаляются первыми. Это ограниченная история диалога, а не долговременная
память из будущих пунктов 9.18–9.20. Смена модели её не сбрасывает. Профиль,
эмоциональное состояние, выбранная модель и явные границы сохраняются прежним
checkpoint `state/3`, совместимым с `state/1–2`.

В Character добавлены отдельный текстовый ввод, отправка/Stop, история, выбор
модели и профиля. Слева сохранён ручной предпросмотр персонажа. Голос и LLM-анимация
здесь не включены; текстовый модуль не зависит от их наличия. Кивок/«нет» остаются
2×, остальные движения 1×; idle без встроенного моргания, речевые SFX не включены.

Для встроенного Python worker запускается статическим bootstrap с явными путями:
Windows `._pth` игнорирует `PYTHONPATH`, поэтому одной переменной окружения было
недостаточно для загрузки отдельного пакета/тестовой копии.

## Проверки

- 109 связанных Python-тестов прошли; 16 проверок Avalonia прошли. Ruff, mypy,
  проверка переводов (671 ключ, RU/EN) и `git diff --check` — без ошибок.
- Тесты протокола перебирают все позиции разрыва строки, проверяют частичный JSON,
  неверные ID/порядок, неизвестные действия, пределы интенсивности/размера, NaN,
  неподходящий evidence и атомарность непотокового документа.
- Runtime проверен с тестовым провайдером: Stop/поздний ответ в обоих режимах,
  смена границ во время генерации, один fallback, ошибка после частичного ответа,
  отсутствие автоматической записи кандидатов, смена модели и восстановление.
- Интеграционный тест на Mac проходит через аутентифицированный HTTP API, настоящий
  отдельный worker, scoped services и SharedLLM с тестовым провайдером. Чужой токен
  отвергается, не объявленный в manifest метод недоступен; suspend/resume сохраняет
  историю и профиль. В лёгком CI без tokenizer этот дополнительный тест пропускается.
- Avalonia headless: история/профиль/модель, отправка, поздний пакет после Stop,
  повторный Dispose, прежний renderer и независимый черновик Chat. Окно проверено
  по отрисованному снимку.
- Wheel установлен вне checkout: lifecycle и загрузка схемы работают.

## Живая модель: пределы вывода

Скрипт: [dialogue_live.py](character_checks/dialogue_live.py). Проверка изолирована
от установленного приложения и пользовательских чатов. Используются настоящие
UI HTTP API, worker, scoped services, общая очередь, EngineManager и RAMVI Engine;
никаких STT/TTS или renderer в worker нет. Переключение 8B → 14B → 8B выполняется
самим общим провайдером. Перед GPU-проверкой проверены чужие процессы и свободная
память; своя сессия занимает маркер, имеет абсолютную автоостановку и освобождается
в `finally`. Процессы параллельной сессии не останавливаются.

Первый полный прогон: контроль `2+2` вернул `4`; три разных кода переданы точно;
название вымышленного маяка из 8B вспомнила 14B после suspend/resume, затем снова
заработала 8B. Stop очистил ожидающие события; профиль Friendly и запрет подколов
сохранились. Все десять ответов завершены структурированно, без fallback.

При этом одна из трёх новых сумм неверна: `100037 + 700019` дала `180015` вместо
`800056`. Другие две суммы верны; отдельная сумма после возврата на 8B тоже верна.
Схема проверяет формат и допустимые управляющие поля, а не истинность текста.
Это не закрывает смысловую приёмку 9.4 и не доказывает качество арифметики.
Константный ответ не проходит три разных кода: максимум один из трёх. Проверка
копирования кодов доказывает передачу текущего ввода, а не понимание сложных задач.

Финальный повтор актуального runtime: **7/7** ответов завершены корректно и содержат
ожидаемый текст, fallback **0**. Включены решаемый контроль, три новых разных кода
(101903, 102234, 102565), запоминание названия, его извлечение на 14B после перезапуска
и новый код после возврата на 8B. Для трёх разных кодов лучший константный ответ —
1/3, фактический результат — 3/3. Это проверка передачи ввода и истории, без
утверждения о качестве мышления. Проверки отмены/профиля/границ повторены.

SHA-256 исходников Character без assets/build:
`e347f08a4528c9ab3cf8615fc4bc060f635bb13e829b18ea42cd0eab2a1e4ebd`.
Локальные исходники совпадают с этим снимком. Первый полный прогон был до последних
защитных правок fallback/ожидания остановки; финальный прогон сделан после них.
