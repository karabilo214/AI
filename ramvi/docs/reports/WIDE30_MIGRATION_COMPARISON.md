## Методика и ограничения

- Скорость — сумма eval_count / сумма eval_duration. Для сравнения по одному вопросу также объединяются оба повтора; среднее скоростей не используется.
- TTFT — время первого непустого фрагмента по часам HTTP-клиента. Загрузка модели, прогрев и отдельные контроли не входят в измеряемые 30 запросов.
- Перед сравнением проверены одинаковые задачи, параметры, веса, токенизатор и размещение слоёв. Внутри каждого варианта hash кода одинаков во всех рядах.
- Ollama не запускалась; взят исторический JSON на тех же 30 вопросах. Это не одновременный A/B-замер с Ollama; её архив не содержит полного манифеста.
- Как в прежнем сравнении, eval_count нашего API исключает первый токен; архив Ollama не выделяет его отдельно. Историческая методика сохранена.
- Два повтора показывают наблюдаемый разброс; сами по себе они не доказывают статистическую значимость изменения скорости. Итог приёмки требует также контролей plain/draft, fp32 и проверки завершения процессов из журнала запуска.
- Совпадение текстов с Ollama не является критерием переноса: эталон поведения — наш движок до переноса. Сравнение текстов всех шести пар приведено выше.

Полные ответы остаются во входных JSON. Машиночитаемые итоги: `summary.json`, таблица: `comparison.csv`. SHA256 входных файлов и манифесты — в `summary.json`.

- Исходный снимок: `7e3330232b4b83e13f1456cb05c579fef52ef9a9`; перенесённый: `80ca19ee533f6155de9eee971fdf6e266d9e8ea4` (вычислительный код тот же, что в `e2c8b69`). - Один процесс сервера на ряд, новый процесс перед каждым повтором. Перед измерением: загрузка, контроли и прогрев. В каждом запросе новая беседа; порядок вопросов одинаков. История кэша внутри ряда формируется одним и тем же порядком запросов.

- `LLM_DRAFT_GATE=0`, `LLM_PREFILL=legacy`: опциональные O02 и блочный prefill выключены в обоих вариантах. Угадыватель включён. Длинный prefill и другие конфигурации железа этот опыт не оценивает.

## Проверки перед сравнением

На Windows в перенесённом снимке прошли 89 прежних модульных тестов и 48 проверок пакета без пропусков. Число этих тестов не является замером скорости приложения.

Самопроверка HF Qwen3-0.6B, 48 токенов на каждый из трёх запросов:

```sh
python -m llm_app.selftest --model Qwen3-0.6B --n 48
python -m llm_app.selftest --model Qwen3-0.6B --resident 0 --draft Qwen3-0.6B --n 48
```

В обоих запусках совпадение с эталоном fp32 — 3/3; продолжение с кэшем совпало. Во втором запуске все три последовательности с угадывателем совпали с обычной генерацией. Это fp32-проверка HF 0.6B, а не полная fp32-проверка квантованной модели 14B.

Дополнительно прошли `check_audit_gpu`: девять F32-кейсов и семь размеров графа с сохранением KV; `check_gcpu qwen3:14b`: native-матрицы Q4_K, Q6_K и F16 против декодированной матрицы, максимальная напечатанная относительная ошибка 2,3·10⁻⁷.

Перед каждым из четырёх серверных рядов выполнялись восемь контролей: обычная генерация target против генерации с draft, сравнение именно списков токенов. Три заведомо решаемых арифметических запроса дали `4`, `3973` и `100032`; ещё пять — вопросы WIDE №1, 9, 13, 20 и 29 по нумерации отчёта. Все 32 контроля прошли; списки токенов совпали и между повторами. Plain target служит контролем работы без угадывания. Контроли не доказывают истинность произвольных ответов.

Перед нагрузкой и каждым вопросом проверялось отсутствие игры и Ollama. Родитель и серверы имели абсолютный watchdog с остановкой дерева процессов. Опыт завершён в 21:20:00 UTC до дедлайна 21:29 UTC. После него подтверждены отсутствие тестовых процессов и 0 MiB занятой VRAM.

## Артефакты и повторение отчёта

Полные четыре ряда, 120 ответов, `controls.json` каждого ряда, журналы самопроверок, метаданные серверов, `integrity.json`, `hardware_finish.json`, `runtime_sources.zip`, точный внешний сценарий `run.py`, `experiment.json`, CSV и JSON хранятся локально в `ramvi/results/migration_20261113/`. Сырые данные, машинные пути и бинарники в git не включены. Для создания таблицы заново из корня репозитория:

```sh
python ramvi/engine/tools/bench/report_migration.py \
  --results ramvi/results/migration_20261113 \
  --ollama llm_app/results/wide_ollama_14b.json \
  --out ramvi/results/migration_20261113
```

Генератор проверен 16 отдельными тестами: одинаковые данные дают ровно 1.0× и 30/30, среднее отдельных скоростей не подменяет отношение сумм; неполные ряды, изменённые параметры/веса/план и неверные счётчики отклоняются. Команда создаёт числовую часть отчёта; эта проверенная секция условий и приёмки добавлена к публикации отдельно.

Пункт 1.4 принят для указанной конфигурации. Пункт 1.9 остаётся финальным экзаменом после следующих изменений 1.5–1.8: этот результат не является заранее выданной приёмкой будущего кода.
