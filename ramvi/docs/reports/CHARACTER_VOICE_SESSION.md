# Character 9.7: явно включаемая голосовая сессия

2026-11-19. Character 0.5.0. Это входящий голос; TTS — следующий пункт 9.8.

## Результат и ограничения

Добавлена отдельная кнопка голосовой сессии Character. После паузы окончательная
фраза передаётся в его текстовый диалог; предварительный текст только показывается.
Микрофон не открывается при активации текстового Character, загрузке профиля или
восстановлении checkpoint. Выход из раздела останавливает сессию. Ctrl+M/Esc
направляются текущему разделу, обычная кнопочная запись Chat/Agent сохранена.

VAD и распознавание работают в отдельных процессах. Начало речи отменяет текущий
ответ LLM; поздний результат после Stop не отправляется. Suspend/deactivate/dispose
закрывают свою сессию, освобождают микрофон и не возобновляют её после restart.
Если интерфейс перестал опрашивать сессию, Character прекращает её по сроку lease
(задан 5 с). Частичный текст и звук не сохраняются как память или подтверждённые
факты; окончательный ввод сохраняется обычным механизмом истории Character.

Вход поддерживает RU/EN и автоопределение языка заново в коротких окнах внутри
реплики. Смешанный текст одного синтетического голоса сохранён в новых проверках,
но Whisper нередко помечает весь такой текст как `ru`: пословной разметки языков нет.
Качество распознавания не объявляется решённым: один шестизначный номер распознан
неверно. Подробная оценка речи и задержек остаётся в 9.23.

Для собственного TTS предусмотрен доверенный сигнал playback и **полудуплексный
режим**: вход игнорируется во время воспроизведения и заданного хвоста 0,5 с.
Проверено, что такой сигнал не порождает новые транскрипции/ответы и отбрасывает
опоздавший результат. Это не акустическое эхоподавление: одновременное перебивание
звучащего TTS не поддерживается (`barge_in_during_playback=false`). Сам playback
ещё не подключён, поскольку TTS — 9.8; общий цикл перебивания — 9.9.

## Устройство

- `service/voice/session.py`: ограниченная очередь PCM, VAD, начало/конец речи,
  предварительное и окончательное STT, последовательные ID и курсор событий.
- `service/voice/vad.py`, `vad_worker.py`: Silero 5.1.2 ONNX на CPU в отдельном worker,
  общий ProcessSupervisor и shared-memory RPC; аудио не передаётся строками JSON.
- `VoiceService`: эксклюзивная аренда `audio_input`, проверка владельца и capture_id,
  изоляция записи Chat и сессии модуля. Сессия владеет своим распознавателем.
- `character/voice.py`: только политика Character — явный старт, окончательный ввод,
  отмена LLM, heartbeat, остановка. Core не импортирует Character.
- `CharacterVoiceViewModel`: явное управление, индикация, частичный текст, метка
  стороннего STT API при его выборе. Новые ответы идут через прежний валидатор 9.5.

Общие методы Scoped Services с правом `voice`: `voice.session.start/read/cancel/playback`.
Владельца задаёт scope, не JSON. `capture_id` защищает новую сессию от старого Stop.
`SpeechCapabilities.streaming=false` по-прежнему означает отсутствие нативного
streaming STT; `session.partial=true` — повторное распознавание снимков накопленной
речи. Политика автоотправки Character не меняет настройку кнопочной записи Chat.

Заданные пределы (не измерения производительности): очередь захвата 32 блока,
очередь распознавания 2 задания, кольцо 64 событий, до 4096 UTF-8 байт транскрипта.
Предварительные задания можно пропустить ради окончательного; потеря окончательного
ввода или пропуск событий завершает сессию с ошибкой. Пауза конца реплики 0,8 с,
предварительное STT через 3 с, реплика до 30 с плюс pre-roll, сессия до часа.
Пустое распознавание возвращает `rejected`, не оставляет интерфейс в ожидании и не
отправляется модели. Бюджет/профиль LLM и правила памяти не расширяются голосом.

## Находки реальной проверки

1. В pywhispercpp 1.5.1 VAD-функции видимы, но возвращаемый
   `whisper_vad_context_wrapper` не зарегистрирован. Нативная модель загрузилась,
   после чего Python-обёртка завершилась с TypeError. Поэтому потоковый VAD вынесен
   в ONNX Runtime CPU 1.24.4; обычное STT Chat через whisper.cpp не заменялось.
2. При завершении одного POSIX worker после успешного reap повторный killpg дал
   PermissionError. Исправлена только финализация закрытия RPC после завершённого
   корневого процесса; живой процесс и его таймауты не маскируются. Добавлена
   регрессия, проверены ProcessSupervisor/EngineProcess/Supervisor. Inference и
   CUDA-ядра не менялись; WIDE30 не повторялся.
3. Whole-file Whisper потерял EN-хвост склеенной RU/EN-записи. В сессии добавлены
   короткие независимые языковые окна, разделяемые паузами. Длинная пауза может
   разделить две записи разных дикторов на две реплики: это не выдаётся за одну
   смешанную реплику. Отдельно проверена синтетика одного голоса без длинной паузы.

## Проверки и данные

- 248 связанных Python-тестов прошли; 2 проверки Windows Job пропущены на Mac.
  33 проверки Avalonia прошли. Ruff/mypy и переводы RU/EN (683 ключа) — без ошибок.
- Тесты проверяют владение, отсутствие скрытого старта, stop/restart, отмену LLM
  началом речи, игнорирование partial, поздний final, таймаут heartbeat, переполнение,
  пустой результат, языковые окна и отсутствие транскрипций при playback gate.
- Настоящий Character worker проверен через scoped VoiceService: suspend освобождает
  микрофон; resume его не открывает; после этого обычная запись Chat работает.
- На Mac M1 Pro: реальный Silero отверг нулевую тишину и синус 440 Гц, обнаружил речь
  FLEURS RU и EN. Реальный whisper.cpp проверен на трёх RU и трёх EN файлах; сырые
  результаты с ошибками: [development STT](character_checks/voice/stt_development.json).
- Три новые смешанные диктовки одного локального синтетического голоса (Milena),
  поданные блоками в темпе записи: RU/EN-фрагменты сохранены **3/3**, числа точно
  **2/3**. `900731` превратился в `9731`; этот результат оставлен. Окончательный текст
  приходил один раз на реплику, partial отличался от final. Лучший постоянный код
  проходит не больше 1/3; постоянный пустой текст не проходит ни один случай.
  [Сценарии](character_checks/voice/cases.json), [результаты](character_checks/voice/mac_fresh.json),
  [воспроизведение](character_checks/voice_native.py). Это доказательство передачи
  речи/смены языка, а не точности диктовки или готовности озвучки.
- Windows, встроенный Python: VAD запущен, тишина отвергнута; физическая микрофонная
  сессия на 2 с перешла listening → idle, аренд осталось 0. Речь проверялась отдельно
  из файла: `Мой код 103137 and say hello in English.` получена как final.
  [Данные](character_checks/voice/windows.json), [скрипт](character_checks/voice_windows.py).
  Для физического микрофона скрипт требует явный `--physical-microphone`.
- После Windows-проверки: свои процессы/голосовые workers/задания **0**, VRAM **0 MiB**,
  маркера нет. [Уборка](character_checks/voice/cleanup.json). Установленное приложение
  не менялось; маленький тестовый каталог и изолированные зависимости оставлены,
  пользовательские LLM/STT-веса туда не копировались.
- Снимок окна проверен: [Character UI](character_checks/voice/ui.png).

## Комплект и первичные источники

Небольшой служебный VAD входит в сервис как фиксированный runtime-ресурс:
2 327 524 байта, SHA-256
`2623a2953f6ff3d2c1e61740c6cdb7168133479b267dfef114a4a3cc5bdd788f`.
Вместе с ним идут MIT-лицензия Silero и `SOURCES.json`. В проверке релиза разрешён
только этот путь с этим хешем; другой ONNX-файл или изменение содержимого отклоняется.
Пользовательские LLM/STT-модели по-прежнему не входят в комплект. В optional voice
зависимости и portable closure добавлен CPU onnxruntime. Wheel проверен вне checkout:
ресурс/хеш на месте, native VAD worker запускается, текстовая активация Character
по-прежнему не открывает устройств.

[CPU ONNX Runtime](https://onnxruntime.ai/docs/get-started/with-python.html),
