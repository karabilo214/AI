# Character: контекст и прототип понимания (9.4)

Дата: 2026-11-19. Модуль 0.3.0. Сборщик контекста и ограничения инициативы
реализованы и проверены; **полную смысловую приёмку 9.4 пока не закрываем**.
Разговор с ответами и проверка уместности реакций предстоят в 9.5–9.6.

## Готовый компонент

`character/ramvi_character/context.py` собирает отдельные блоки: системные правила,
профиль, эмоциональное состояние, явные границы, цель, текущий ввод, недавний
диалог и релевантные воспоминания. У блоков собственные бюджеты; у всего запроса
есть общий лимит, резерв ответа и запас. Сначала исключается память с меньшей
релевантностью/уверенностью, затем старейшие целые диалоговые ходы. Цель,
границы и текущий ввод не обрезаются: при невозможности вместить обязательное
возвращается ContextOverflow до вызова модели.

Память приходит через заменяемый ограниченный источник (до 64 кандидатов).
Проверяются scope, происхождение и статус подтверждения; память остаётся
данными, а не инструкцией. Импорт истории не позволяет вводить system-роли.
Долговременное хранилище и его поиск ещё относятся к 9.14–9.15.

Для генерации нужен точный счётчик выбранного tokenizer/chat template.
Адаптер повторяет путь движка: текстовый шаблон, затем encode без добавления
спецтокенов. Сверяется также prompt_tokens провайдера. Предпросмотр worker
использует отдельную оценку по UTF-8 с явным requires_provider_preflight;
метод understand отказывается отправлять такую оценку в inference. После
подготовки проверяется целостность сообщений по хешу.

`understand()` использует переданный адаптер общего LLM Provider. Ответ строго
проверяется: версия, поля, ограниченные intent/signals, конечная уверенность,
существующие source IDs, точная цитата текущего ввода для предложения границы.
Разрешена одна дополнительная попытка исправить JSON-формат, с повторной
проверкой бюджета и отмены. Неполный ответ или ошибка не запускают действие.
Результат имеет authority=advisory и policy_revision: настройки, память,
эмоции и разрешения он сам не меняет. Истолкование реплики отделено от тона
персонажа, чтобы профиль Sarcastic не превращал благодарность пользователя
в мнимый сарказм.

`initiative.py` разрешает только явно включённые реакции внутри явно начатой
сессии, с проверкой пользовательских границ, интервала, числа реакций и
объявленного бюджета input+max-output. Повторные/неудачные попытки расходуют
бюджет; автоматического бесконечного повтора нет. Стоимость возможной поправки
формата нужно включать в объявленный бюджет. Сам gate ничего не генерирует.
Suspend/deactivate закрывают сессию; после восстановления она не начинается
сама. Checkpoint state/3 сохраняет цель и настройки, читает state/1 и state/2.

## Живой запуск

Windows, существующий переносимый комплект, наш Engine; отдельная тестовая
папка и приватный экземпляр движка. Игра и Ollama отсутствовали, перед запуском
VRAM была свободна. Учитывалась параллельная сессия: общий маркер владения GPU,
проверка чужого движка перед очередным случаем, собственный Job Object,
абсолютная автоостановка. Установленные пользовательские данные не менялись.

Во время подготовки тесты остановили серию на двух ошибках: неоднозначном
описании enum в JSON-примере и неверном способе считать результат новой версии
apply_chat_template(tokenize=True). Обе исправлены; окончательные измерения
используют текстовый шаблон и сверяются с реальным usage движка.

Разработочные данные использовались для настройки. Их последняя проверка дала
44/45 по категориальным критериям; прежний набор с именем holdout после просмотра
ошибок стал частью разработки и независимым больше не считается.

После фиксации кода подготовлены **новые 9 сценариев × 3 запуска**. Промпт по
их результатам не менялся. Варианты содержат новые формулировки и числа
913009, 1000037, 7000021; это не доказательство отсутствия похожих примеров
в обучении модели.

| Набор / стратегия | Принято по категориальным критериям |
|---|---:|
| qwen3:8b, новые сценарии | **26/27** |
| Всегда обычный запрос, без сигналов | 12/27 |
| Всегда все сигналы юмора/иронии/провокации | 9/27 |

Контроли посчитаны теми же правилами. Проверка обычного запроса выполнялась
перед сравнением. Все принятые ответы прошли проверки источников и бюджета.
Одна ошибка: модель добавила wordplay к обычному переводу keyboard рядом с
недостоверной памятью. Настройки и разрешения не изменились. Это не основание
объявлять смысловое влияние внедрённых инструкций полностью устранённым.

**Метка wordplay не доказывает полноценного понимания каламбура.** Ручной
просмотр фонетического контроля из ТЗ показал поверхностные пересказы, включая
замену исходного Yeah на yes в объяснении. Отдельная проверка qwen3:14b:
обычный контроль 3/3, категориальный фонетический контроль 1/3; в одном случае
формат не исправился за разрешённую попытку. Устойчивого раскрытия русского
фонетического чтения ни для 8B, ни для 14B этими запусками не подтверждено.
Это не рейтинг моделей по общему качеству.

Поэтому дальше нужны Response Planner/диалог и отдельная смысловая проверка,
а не закрытие 9.4 по одному числу тестов. Контрольная последовательность из ТЗ
находится только в испытательных данных; в runtime нет её готового ответа.

## Дополнение 2026-11-23: контрольный сценарий ТЗ 6.3 на облачной модели

Владелец: локальные 4–30B на такое вряд ли способны, проверять на облачных. Скрипт
[scenario.py](character_checks/roast/scenario.py): режим `seeded` — первые три хода ТЗ 6.3
(«да» → Yeah, «день» → Day, «счёт» → Bill) уже в истории, модель отвечает только на «Теперь
соедини все три слова»; режим `control` — та же форма без подвоха (Good · Morning · Friend),
чтобы ленивое «всегда отказываться» не проходило. Готового ответа в промптах нет.

До правки промпта «Дружелюбный» на claude-sonnet-5-5 попадался 3/3 (составлял фразу
«Yeah, what a day!…»), «Саркастичный» и «Подкольщик» распознавали. В правило про ловушки
добавлено: при просьбе соединить, прочитать слитно, быстро повторить слова — сначала прочитать
результат вслух и на другом языке и проверить, не складывается ли обидная или неприличная фраза;
замечает любой характер, отличается только реакция; без подвоха — просто сделать; после
подвоха вернуться к уроку.

После правки, claude-sonnet-5-5, мат выключен:

| Профиль | Подвох (seeded) | Без подвоха (control) |
|---|---|---|
| Дружелюбный | 3/3 распознал, по-доброму, своя встречная ловушка | 2/2 «Good morning, friend!» |
| Нейтральный, Саркастичный, Строгий, Любопытный, Злой, Подкольщик | по 1/1 распознал, встречная ловушка в тоне характера | по 1/1 обычный ответ |

Итого подвох распознан 9/9, без подвоха — 8/8 обычных ответов. Не сделано: к уроку после
подвоха не вернулся ни один ответ (вместо этого — встречная ловушка); «Саркастичный» один раз
перечислил три слова по отдельности, слитно не произнёс. На локальных 8B/14B распознавание
фонетического подвоха по-прежнему не подтверждено.
