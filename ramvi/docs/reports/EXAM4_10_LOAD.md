# Экзамены 4 и 10, нагрузка (пункт 8.6)

Дата: 2026-11-19. Проверки на Mac: настоящий сервис, HTTP, SQLite и процессы; движок — тестовый (`tests/fixtures/fake_engine.py`). Каждый тест прогнан 3 раза подряд, сбоев нет.

## Экзамен 4: без интернета

`tests/test_exam4_offline.py`. Ловушка запрещает любое соединение и DNS-запрос наружу, разрешена только петля 127.0.0.1. Чат отвечает, голос распознаёт в поле ввода по локальной модели, экраны открываются, файловые инструменты агента работают: чтение, поиск, правка с diff и применение. Попыток выйти в сеть: 0. Контроль: прямое внешнее соединение ловушка ловит.

Ограничение: распознавание речи в тесте подменено, настоящей модели whisper на Mac нет. Настоящий whisper получает путь к файлу модели, а не имя для загрузки (`voice/worker.py`). Проверка с настоящими моделями и выключенной сетью — на ноутбуке с RTX 5060, по разрешению владельца.

## Экзамен 10: сбои без повреждения данных

`tests/test_exam10_failures.py`. После каждого сбоя проверяется: `PRAGMA integrity_check` = ok, прежняя история на месте, следующий запрос работает.

| Сбой | Что видит пользователь | Проверка |
|---|---|---|
| Нехватка памяти при загрузке модели | `engine.no_memory` | тест экзамена 10; также `test_ui_states.py` |
| Повреждённая модель | `engine.start_failed` после повторов | тест экзамена 10 |
| Падение движка посреди ответа | ответ помечен ошибкой, полученная часть сохранена, движок перезапускается, следующий ответ работает | тест экзамена 10 (`CRASH_MID` в тестовом движке) |
| Полный диск | `storage.disk_full`: «Нет места… прежние данные целы», папка для освобождения места; HTTP 507 | 3 теста: сообщение пользователя, сохранение ответа, откат транзакции целиком |
| Обрыв клиента посреди потока | генерация останавливается, сервис продолжает работать | тест экзамена 10; также `test_chat.py` |
| Драйвер недоступен | проверка компьютера называет нужную версию драйвера | `test_onboarding.py` (8.1) |
| Ошибки распознавания речи | понятные коды, состояние возвращается в «готов» | `test_voice.py` |

**Найдено и исправлено:** при полном диске пользователь получал «внутреннюю ошибку» с текстом «cannot rollback - no transaction is active». SQLite сам откатывает транзакцию при `SQLITE_FULL`, а наш повторный откат падал и прятал настоящую причину. Теперь `Database` откатывает только активную транзакцию, переводит `SQLITE_FULL` в `DiskFull`, а сервис показывает `storage.disk_full`. Если диск полон при сохранении ответа, ответ завершается этой ошибкой, а не обрывом потока.

## Нагрузка

`tests/test_load.py`. Одновременно идут 6 чатов по 5 сообщений, 4 клиента внешнего API по 6 запросов и опрос состояния каждые 50 мс. Результат: 54 запроса за 4,4–4,6 с (3 прогона). Сбоев 0, ответы не перепутаны, каждый ответ — эхо своего вопроса. Счётчики клиентов точные, ошибок 0. История каждого чата полная и по порядку, база цела, потоки освобождаются.

Нагрузка на настоящей модели (очередь, переключение режимов, 12 параллельных запросов) проверена экзаменами 7 и 8 на ноутбуке с RTX 5060 ([EXAM7_API.md](EXAM7_API.md)).
