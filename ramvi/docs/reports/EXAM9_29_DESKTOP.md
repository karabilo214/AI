# Экзамен 9.29: персонаж независим от главного окна и от контекста приложений

Дата: 2026-11-23. Ноутбук с RTX 5060 (Windows 11), комплект Desktop\RAMVI; Mac — UI-тесты и
облачные проверки. Сводит проверки 3.13, 9.26–9.28 и сегодняшние прогоны помощника.

| Что требует 9.29 | Как проверено | Итог |
|---|---|---|
| Все представления (в окне, отдельное окно, оверлей) | UI-тест смены представления (тот же персонаж, разговор, черновик, модуль не перезапускается, ответ не отменяется); Windows: окно персонажа и оверлей на экране | да |
| Фоновый режим и полный выход | Windows: без фона закрытие окна RAMVI — процессов нет, видеопамять 0; с фоном — окно прячется, «Открыть RAMVI» возвращает, «Выйти» из трея закрывает всё | да |
| Персонаж вне окна не зависит от раздела главного окна | исправлено: при переходе RAMVI в чат персонаж вне окна больше не замолкает (UI-тест, без исправления падает) | да |
| Три уровня грантов, немедленный отзыв | UI Context и Agent Control на Windows (чтение окна, действия агента в окне); отзыв — следующий ход «доступа нет», новые чтения запрещены, разговор продолжается; смена окна отзывает гранты модулей; Screen в помощнике не используется (по ТЗ сначала структура), его грант — у агента | да, Screen вживую не проверялся |
| Нет постоянной отправки скриншотов | помощник берёт только UI-снимок (`kind: ui`) по ходу разговора; снимок экрана автоматически не делается; облаку — только с отдельным разрешением (`egress.text`, иначе `cloud_not_allowed`) | да |
| Смена активного окна во время работы | на переднем плане другая программа (консоль) — помощник читает выбранное окно: выделено «Превет », поле «Превет мир, как дила?», снимок 0,75 с | да (после правки адаптера: чтение в фоне, действия — только в активном окне) |
| Сбой системного адаптера и повторное подключение | окно закрыто — `unavailable`, персонаж говорит, что окна нет; Блокнот открыт заново, окно выбрано и разрешено — снова `ok`, выделение видно | да |
| Нет действий в чужом окне | действие агента требует, чтобы целевое окно было активным и тем же приложением (проверка в адаптере); каждое действие — подтверждение агента | да |
| Нет утечек контекста между модулями | гранты на окно выдаются конкретному модулю (`/agent/target/module`) и не задевают гранты агента и наоборот (тест); поручение агенту идёт от имени персонажа | да |
| Нет регрессий Chat/Agent | полный набор тестов Python и UI | да |

## Задержки и стоимость (claude-sonnet-5-5, Windows)

- Снимок окна (UI Automation): 0,7–0,75 с.
- Ответ персонажа с контекстом окна: 7–10 с; «нет доступа» / «окно недоступно»: 2,5–4 с.
- Поручение агенту с правкой в окне (снимок, план, подтверждение, `set_value`): 17–20 с.
- Стоимость в деньгах не посчитана: цены облачных моделей в RAMVI не заданы (вписывает владелец).

## Что нашёл экзамен и что исправлено

- Чтение выбранного окна требовало, чтобы оно было активным, — пока пользователь пишет
  персонажу, активно окно RAMVI, и помощник был слеп. Теперь читать можно в фоне, действия —
  только в активном окне.
- В фоне ни одно текстовое поле не помечено фокусом (служебные панели помечены) — берётся
  первое текстовое поле окна; его выделение в фоне сохраняется.
- Блокнот Windows 11 — одно окно с вкладками и запоминает несохранённые вкладки; проверка
  закрывает его без сохранения и убирает только свои вкладки.
