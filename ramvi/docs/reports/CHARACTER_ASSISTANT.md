# Помощник в приложениях (9.28, CHAR-DESKTOP-03)

Дата: 2026-11-23. Персонаж понимает «вот здесь» в окне другой программы: пользователь выбирает
окно (тот же выбор, что у агента) и сам решает, что можно.

## Как устроено

- **Выбор окна и доступ** — «Настройки → Персонаж → Помощник в приложениях»: «Выбрать окно»
  (5 с, переключиться в нужную программу), галочки «Читать выделенный текст и элементы окна»,
  «Можно отправлять прочитанное облачной модели», «Агент может действовать в этом окне»,
  «Разрешить» / «Отключить». Маршрут `/agent/target/module` выдаёт гранты модулю на выбранное
  приложение: `context.ui`, `egress.text`, `agent.control`. Другое окно или «Отключить» — отзыв
  сразу. Гранты, выданные на экране агента, раздел не трогает.
- **Каждый ход** персонаж берёт снимок интерфейса (`context.capture`, только UI, без снимка
  экрана): выделенный текст и элементы окна. В запрос он идёт разделом `application_context` —
  данные, не инструкции; при нехватке места первым выбрасывается список элементов. Нет доступа,
  окно закрыто, нет системного адаптера (Mac), облачной модели отправлять не разрешено —
  персонаж получает состояние (`no_access`, `unavailable`, `cloud_not_allowed`) и прямо говорит,
  чего не хватает. Сам персонаж в окне ничего не меняет и не утверждает обратного.
- **После отзыва доступа** разговор продолжается: модуль сообщает сервису `context.release`
  (сырого снимка не хранит), новые чтения окна запрещены. Раньше любой запрос к модели после
  отзыва блокировался до нового сеанса модуля.
- **Поручение агенту** («Поручить агенту») несёт контекст окна (выделенный текст) как данные;
  с «Агент может действовать в этом окне» задача идёт с `use_ui` от имени персонажа и под
  подтверждениями агента. В истории остаётся только задача владельца.
- **Агент на облачной модели** в окне работает только с разрешением отправлять прочитанное
  облаку — на экране агента добавлена галочка «Можно отправлять облачной модели» (раньше такого
  гранта не было, и агент на облаке с окнами не работал вовсе).

## Проверка на ноутбуке с RTX 5060 (Windows 11, Блокнот, UI Automation)

[Скрипт](character_checks/assistant_win_live.py), [итог](character_checks/assistant_win_result.json).

| Что видит персонаж | `ok`, выделено «Превет », 32 элемента окна |
| Окно выбрано, чтение разрешено | «Да, ошибка в выделенном «Превет»: вторая «е» должна быть «и», правильно «Привет». Исправить сам не могу, это делает агент, если поручишь.» |

| Окно закрыто | состояние `unavailable`; «Окно «zametki.txt - Notepad» сейчас недоступно, выделенного текста я не вижу. Выдели нужное место заново…» |
| Поручение агенту в окне | агент правку не внёс: виден только выделенный фрагмент (7 из 21 символа), а `set_value` заменил бы весь текст — честный отказ, текст не испорчен |

На локальной qwen3-8b-q4_k_m механизм тот же (выделение доходит), но модель ответила «ошибок
нет», а агент искал файл вместо окна — качество модели, не механизма.

## Ограничения

- Значения полей ввода в снимок окна не входят (приватность, 6.10) — поэтому агент не может
  точечно поправить слово в чужом поле: только заменить значение целиком, от чего он
  отказывается. Включать ли значение поля с фокусом в снимок — решение владельца.
- Снимок экрана (Screen) и мультимодальная модель в помощнике не используются: по ТЗ сначала
  структурированный контекст.
- Системный адаптер окон есть только для Windows; на Mac раздел говорит, что недоступен.
- Блокнот Windows 11 — один процесс с вкладками: окно закрывается по заголовку, не процессом.
