# Character 9.10: отказы устройств и провайдеров

2026-11-19. Модуль Character 0.8.0. При ошибке голосовая цепочка освобождает свои
ресурсы и предлагает продолжить текстом. Текстовый ответ LLM не обрывается из-за TTS.

## Поведение

Поколение текстового ответа и попытка аудиовывода разделены. Ошибка TTS, смена голоса,
пробная фраза или «Приостановить озвучку» аннулируют только аудиопопытку. Текст,
профиль и история сохраняются. Основной Stop/Esc и новый ввод по-прежнему отменяют
поколение целиком по правилам 9.9. При уходе из раздела останавливается и ответ.

После ошибки TTS очищается очередь, вывод переходит в `mode=text`, автоматический
повтор синтеза не выполняется. «Возобновить для новых ответов»/«Применить» используют
новую аудиопопытку **для следующих ответов**. Ранее начатые сегменты и остаток текущей
реплики не переозвучиваются. Проба голоса — отдельный явный запрос и не отменяет
текущий текст. Поздняя ошибка/завершение старой попытки не выключают новую пробу.

Ошибка микрофона/STT завершает входящую сессию и приостанавливает свою озвучку,
сохраняя текстовый диалог. Пользователь может снова открыть сессию и отдельно
возобновить озвучку. Устройство не открывается автоматически после ошибки.
Порядок start/stop в UI сериализован: Stop не может пройти перед запоздавшим start
и оставить микрофон включённым после завершения остановки. Старые ответы UI отсекаются.

Провайдер не заменяется другим автоматически, текст во внешнее API не уходит ради
fallback. При выборе другого TTS-провайдера флаг внешней передачи сбрасывается,
если пользователь не передал его явно. Ключи STT/TTS по-прежнему раздельны.
Повторные платные запросы и точность эмоций/произношения этим пунктом не заявлены.

## Устройство и пределы

- PortAudio-вывод выполняет отдельный `speech.device_worker`, а захват непрерывной
  сессии — `voice.capture_worker`. Core управляет ими через ProcessSupervisor;
  закрытие/ошибка/таймаут останавливают собственную группу процессов/Windows Job.
  Зависший native open/write/drain не остаётся внутри процесса Core.
- Нативная запись обычного Chat сохранена. В ней исправлена очистка потока,
  если `start()` завершился ошибкой. Непрерывная сессия использует новый адаптер
  только для настоящего SoundDeviceMicrophone; тестовые/другие адаптеры не заменяются.
- Очистка микрофона, VAD, STT, выхода, gate и аренды независима: ошибка одного close
  не пропускает остальные. Первичная ошибка сохраняется, приватные exception-тексты
  устройства/провайдера не выдаются пользователю как диагностический код.
- Инвентаризация локальных голосов работает в фоне без удержания замка заданий.
  Есть «Обновить голоса»; отсутствующий сохранённый голос не заменяется молча первым
  из списка. Смена выбора ждёт приостановки старой попытки перед применением.
- UI показывает ошибку и текстовый режим вне раскрываемых настроек. При малой высоте
  окна настройки прокручиваются; поле текста сохраняется даже с длинным черновиком.

Заданные таймауты, **не измерения скорости**: первый PCM до 45 с, следующий PCM до
20 с, аудиозадание до 180 с; RPC PortAudio-вывода до 2 с, открытие захвата до 2 с,
чтение захвата до 1 с, отсутствие входных кадров до 3 с. Завершение процесса имеет
дополнительный ограниченный бюджет очистки. Это не обещание полного UI round-trip
за 2 с и не цель задержки перебивания из TZ. Сеть и системный синтез сохраняют
собственные меньшие/вложенные таймауты из 9.8.

Захват передаёт PCM в памяти через ограниченную очередь: 32 блока, одна посылка
за чтение; при 192 кГц mono int16 блок 100 мс укладывается в 64 КиБ RPC. Звук
микрофона на диск не пишется. Кадры помечаются монотонным временем захвата;
при переходе playback gate отсекается и PCM, задержавшийся в дочернем буфере.
Используется общая для процессов шкала [time.monotonic](https://docs.python.org/3/library/time.html#time.monotonic)
(Python 3.12+); сопоставимость проверена настоящим дочерним процессом на Mac.
Вход остаётся полудуплексным с хвостом 0,5 с; AEC/свободный дуплекс не добавлены.

## Проверки

Связанные наборы Python: `test_speech_recovery`, `test_capture_process`, speech/pipeline,
Character, voice/session, scoped LLM, Module Core/Data/API/Sections, модульный экзамен,
i18n и portable packaging. Проверены ошибки синтеза/HTTP, ожидание первого PCM,
пауза внутри PCM-потока, open/start/write/close устройства, отказ gate, ошибка close
провайдера, восстановление, несовпадение попыток и повторный preview.

Положительный путь обязателен: после отказа новый ответ выдаёт PCM; выключение всей
озвучки проверку не проходит. Проверены полный текст из восьми сегментов после ошибки
TTS, отсутствие автоматического повтора, сохранение primary generation при смене
голоса/preview/паузе, а также продолжающий звучать другой модуль при отказе Character.
Отдельно проверены очистка всех компонентов после ошибок close, отказ/буферизация
capture RPC, неактуальный start/stop UI, отсутствие скрытой смены сохранённого голоса
и текстовый ввод в окне высотой 500 с раскрытыми настройками и многострочным черновиком.
[Снимок UI](character_checks/recovery/ui.png).

Итог: **327 Python-проверок и 45 Avalonia-проверок** прошли. Ruff/mypy — без ошибок,
RU/EN — 725 ключей без ошибок. Полный набор проекта не запускался, inference/CUDA
не менялись и WIDE30 не повторялся. Wheel установлены вне checkout: системный синтез,
реальный аудиовыход, отсутствие оставшегося аудиопроцесса и изолированный отказ
несуществующего входного устройства: [пакеты](character_checks/recovery/wheel.json).

## Реальные локальные голоса и процессы

[Скрипт](character_checks/recovery/native_recovery.py) проводит три сценария:
несуществующий установленный голос, намеренно не отвечающий дочерний аудиопроцесс,
провайдер без PCM. Затем выбирается исправный локальный голос и произносится новая
фраза. Для двух таймаутных сценариев специально уменьшены тестовые бюджеты до 0,15 с;
полное время обнаружения включает синтез/запуск/очистку и не равно этому бюджету.

| Проверка | Mac | Windows |
|---|---|---|
| Новые ответы после трёх отказов | 3 из 3 | 3 из 3 |
| Ошибка отсутствующего голоса, мс | 288.426 | 391 |
| Ошибка зависшего аудиопроцесса, мс | 848.586 | 906 |
| Ошибка провайдера без PCM, мс | 179.630 | 156 |
| Разные ненулевые PCM после восстановления | 3 | 3 |
| Оставшиеся аренды | 0 | 0 |

Новые коды: 104729, 393241, 10000019; проверены ненулевая амплитуда, разные хеши и
один успешный старт на новую фразу. Это проверка передачи/восстановления, не качества
произношения чисел. Данные: [Mac](character_checks/recovery/mac.json),
[Windows](character_checks/recovery/windows.json). На Windows также получены 10 блоков
микрофона, 32000 байт при 16 кГц; затем capture worker и его reader завершены.

После своей Windows-проверки процессы/маркер/задания убраны, видеопамять была свободна:
[очистка](character_checks/recovery/cleanup.json). Desktop-комплект не обновлялся.
После финальной доработки временных меток и отсечения задержанных кадров повторный
живой прогон захвата на Windows не выполнялся: машину заняла параллельная проверка
Sandbox. Её процессы не трогали. Финальная логика буфера/часов проверена локально
контролируемыми кадрами и настоящим дочерним процессом; предыдущая аппаратная
проверка захвата относится к версии до этой последней корректировки.

Платные live TTS API, физическое отключение USB-устройства, слепая оценка голоса и
полный голосовой цикл не проверялись. Эти данные не закрывают 9.23/9.24; синхронизация
renderer по playback clock остаётся 9.12. Следующий пункт — 9.11, Character pack/renderer.
