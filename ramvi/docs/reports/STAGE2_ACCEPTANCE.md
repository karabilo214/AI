# RAMVI — приёмка этапа 2

Код пунктов 2.1–2.16 реализован. Итоговая приёмка **не закрыта**: полная численная проверка dense GGUF 14B не уложилась в лимит, а наблюдаемое снижение скорости относительно сохранённого этапа 1 ещё не отделено от условий измерения. ## Проверки

- Windows: **345 тестов, 125 подтестов**, один пропуск — POSIX process-group test; Windows Job проверен отдельно.
- macOS, полная среда: **344 теста, 125 подтестов**, два Windows-пропуска. Лёгкая среда: **242 теста, 15 пропусков** без вычислительных зависимостей/Windows.
- Ruff/format — без ошибок; mypy — **69 файлов**, macOS и Windows type targets. Два wheel установлены вне репозитория, импорты Host/EngineProcess не загружают CUDA/NumPy/UI. **4/4** локальных проверки официальных SDK OpenAI/Anthropic прошли; это проверка протокола, не замер модели.
- Реальный Engine HTTP-процесс: **4/4** интеграционных проверки — версии/auth/events/метрики/план; FIFO и отмена владельца; отмена запроса за чужой активной генерацией; аварийное завершение, живой родитель и новый экземпляр движка.
- После завершения Engine драйверная VRAM вернулась **0 → 0 MiB** ещё при живом родительском сервисе. Финальная проверка после всех нагрузок также 0 MiB; тестовых процессов нет.
- Независимый fp32: **2 из 3** итоговых архитектурных проверок прошли (HF и MoE). Dense GGUF 14B остановлен по лимиту 240 секунд и не считается пройденным. Проверяются полный вектор логитов с заданным допуском, argmax и последовательность ID, включая EOS. [Разбор 2+2](ARITHMETIC_2_PLUS_2.md).

Важное ограничение: после исправления MoE исходный 2+2 завершился ответом 4 в двух повторах; новые умножение/большое сложение при 384 токенах завершились по длине без финального текста. Это не верные и не неверные числовые ответы. Повтор с большим бюджетом не завершён до закрытия аппаратного окна.

Модульные проверки включают сбой/зависание worker, rollback обновления, scope данных и разрешений, прекращение подписок/аренд, чужие и поздние события. Неправильная постоянная стратегия и потерянный суффикс намеренно отвергаются эталоном; используются свежие случайные блоки и числа вне tiny-фикстуры.

## Условия и ограничения

- Windows 11, AMD Ryzen 7 260, RAM 15,29 GiB, RTX 5060 Laptop 8151 MiB. Версии вычислительной среды сохранены в сырых метаданных; Ollama не запускалась.
- Ollama — исторический результат на тех же 30 вопросах. Это не одновременный A/B; преимущество над ним нельзя приписывать только изменениям этапа 2.
- Скорость: сумма eval_count / сумма eval_duration, без среднего отдельных скоростей. Старый RAMVI eval_count исключает первый токен; архив Ollama его отдельно не выделяет. TTFT — первый непустой фрагмент по часам HTTP-клиента, отдельно от внутренних метрик.
- Расширенная диагностическая матрица была остановлена из-за стоимости полного fp32 forward. Она сохранена как незавершённая; её запуск не объявляется пройденным. Итоговые ограниченные проверки HF/GGUF/MoE выполнены отдельно полностью, с указанным числом позиций.
- По одному ряду на режим: этого недостаточно для статистической значимости небольших разниц. Auto меняет бюджет/размещение, поэтому сравнение режимов не изолирует влияние одного алгоритма.
- Auto выбирает допустимый бюджет по оценке памяти, не измеренный глобальный оптимум скорости. Настройки и границы: [планировщик](../architecture/AUTOMATIC_PLANNING.md). Ручной/legacy путь доступен явно.
- Настоящие OS screen/accessibility/audio adapters, постоянные секреты, полный Storage, Character и UI ещё не реализованы. Scoped Services обслуживают доверенные модули и не объявляются OS sandbox. Внешний streaming LLM adapter — дальнейшая работа.

## Исправленные ошибки Windows

Исправлены распознавание абсолютных путей с двоеточием, завершение соединений с недописанным HTTP-заголовком и статус фактически отключённого draft. В супервизоре устранена гонка venv-redirector до назначения Windows Job: защитный gate запускается базовым интерпретатором. Вывод читается без блокирующего TextIO.readline, Job завершается явно; отдельный тест удерживает копию Job handle. Проваленные попытки сохранены отдельно и не подменены успешными.

## Что осталось для закрытия этапа

1. Завершить полный independent fp32-контроль dense GGUF 14B. Текущий запуск остановлен по лимиту 240 с, а не по найденному численному расхождению. Следующий запуск должен отделить снимок native-логитов от памяти загруженной модели и профилировать стоимость эталона; повторять широкую матрицу не требуется.
2. Проверить наблюдаемое снижение скорости на сопоставимом прогреве и повторном before/after. Прежний сервер выполнял контроли в том же процессе до Hello8; теперь контроли были в отдельном процессе перед новым сервером. Историческое сравнение не изолирует накладные расходы нового кода.
3. Для оценки арифметики Thinking2507 закончить свежие задания с достаточным бюджетом рассуждений. Ограниченные384 токенами результаты не выдаются за правильные завершённые ответы. Это ограничение качества/бюджета модели отделяется от доказанной ошибки её прежнего шаблона.
