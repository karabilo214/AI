# Character 9.9: поток сегментов и отмена поколения ответа

2026-11-19, Character 0.7.0. Проверена цепочка LLM → проверенный сегмент → TTS →
ограниченный PCM-буфер → аудиоустройство; UI и renderer отбрасывают старые события.

## Поведение

Stop/Esc, новый текст и новое принятое событие речи аннулируют прежнее поколение.
Сначала закрывается допуск старого аудио, затем отменяется LLM и очищаются сегменты.
Новый текст можно отправить во время предыдущего ответа.
Исправлена также обработка UI-ответов: `error: null` означает отсутствие ошибки,
а поле ошибки операционного состояния не подменяет отказ RPC. UI ждёт завершения прежней
генерации асинхронно; опоздавшие start/poll/status не возвращают старый текст или жест.
При перезапуске учитывается новая сессия модуля: её счётчик может начаться заново.

Первый завершённый и проверенный сегмент может прозвучать до окончания LLM-ответа.
Неполный JSON в TTS не поступает. Синтез и передача PCM в устройство выполняются
раздельно; медленный вывод приостанавливает производителя. Очередь сегментов также
приостанавливает чтение LLM, сохраняя возможность Stop. Во время ожидания используется
`llm.read(max_chunks=0)`: поддерживается срок жизни потока, текст из него не забирается.
Для провайдера без streaming добавлен отменяемый асинхронный `llm.stream(single=true)`:
это один завершённый результат, capability `streaming=false` не меняется.

Предельные размеры в коде, **не измерения скорости**: очередь Character 3 сегмента,
до 8 принятых segment ID в поколении, сегмент до 2048 UTF-8 байт; PCM-очередь 4 блока
по 20 мс. Это ограничение очереди между синтезом и устройством, не всего звука:
unary-провайдеры по-прежнему сначала формируют ограниченный полный ответ (9.8).
Существующий буфер Scoped LLM ограничен 256 кусками, выдаёт до 64 за чтение.

## Почему старый звук не стартует после нового ответа

Общий метод Core `speech.advance` с правом `speech` публикует номер поколения
и response ID владельца. Он устанавливает отмену прежним заданиям и проходит барьер
их аудиовыхода. После подтверждения старое устройство не может начать вывод или
принять следующий PCM-блок. Устройство создаётся без запуска: отдельный `start()`
выполняется только после проверки отмены под тем же замком. Позднее завершение
открытия устройства не обходит барьер. Закрытие сети/процесса провайдера выполняет
собственный consumer; ожидание его завершения не держит замок диалога.

`generation` проверяется до создания провайдера внутри защищённого участка старта.
Ниже текущего поколения — отказ; повтор подтверждённого `advance` идемпотентен.
Повтор `(generation, response_id, segment_id)` с тем же содержимым возвращает прежний
job ID. Другое содержимое под тем же ID отвергается. Уже начатый или завершённый
сегмент не запускается повторно. Это защита повтора доставки **в одном поколении**;
осознанный новый ответ получает новое поколение и может произнести тот же текст.

Внешние старые callers без generation сохранены для совместимости только до первого
`advance` их scope. После перехода на fencing запрос без поколения отвергается.
Character всегда использует fencing. Владелец берётся из scope, не JSON, чужая отмена
не затрагивает другой модуль. После завершения/отмены закрываются выход, свой gate
микрофона, аренда и процесс провайдера. Очереди/поколение не возобновляются из checkpoint.

UI передаёт renderer только проверенные сегменты с эпохой представления, response ID
и segment ID. Смена эпохи останавливает движение; старый ID или повтор сегмента
отвергается. Это доставка жестов по сегментам, **не синхронизация по playback clock**.
Неизвестная картинка/анимация получает нейтральное представление/idle. Полная таблица
эмоций и проверка пака — 9.11, синхронизация рта и аудио — 9.12.

## Проверка

На отдельном снимке HEAD + только изменения 9.9: **299 связанных Python-проверок,
40 Avalonia-проверок**, Ruff/mypy без ошибок, RU/EN — 712 ключей без ошибок.
Полный набор проекта и WIDE30 не запускались: код inference/CUDA не менялся.
Снимок нужен, поскольку в общей папке параллельно разрабатывается установка модулей.
Соседние незавершённые файлы в результат и коммит 9.9 не включены. Совместимость
с установкой модулей 8.8 затем проверена отдельно: 85 связанных проверок прошли.

Проверены задержанные старт/открытие устройства, очередь медленного вывода, отмена
ожидания аренды, блокировка очереди без удержания замка диалога, первый звук до конца
LLM, повтор доставки, поздний poll/start UI, смена сессии после restart, старые жесты
и запоздавший final предыдущей реплики. Положительный путь тоже проверен: новый ответ
передаёт ненулевой PCM; отключение всего вывода эти проверки не проходит.

### Реальные аудиоустройства

[Повторяемый скрипт](character_checks/pipeline/native_pipeline.py) использует локальный
системный голос. В каждой серии: начат старый длинный ответ → `advance` → задержанный
старый запрос отклонён → новый ответ → повтор его сегмента не запускает новый выход.
Новые фразы содержат коды 131071, 262147, 524287. Проверены ненулевая амплитуда и три
разных хеша PCM; это не оценка правильности произношения чисел.

| Проверка | macOS | Windows |
|---|---|---|
| Завершённые новые ответы | 3 из 3 | 3 из 3 |
| Подтверждение аудиобарьера, мс, три прогона | 149.891 / 165.071 / 158.665 | 31 / 47 / 47 |
| Новые отправки старого PCM после подтверждения | 0 | 0 |
| Повторный запуск выхода при повторе сегмента | 0 | 0 |
| Максимум заполнения PCM-очереди | 4 блока | 4 блока |
| Максимальный PCM-блок, 16 кГц mono int16 | 640 байт | 640 байт |
| Аренды после завершения | 0 | 0 |

Данные: [Mac](character_checks/pipeline/mac.json),
[Windows](character_checks/pipeline/windows.json).
Это время вызова аудиобарьера Core, **не** время от микрофона/VAD/STT, не UI round-trip
и не акустический замер последнего звука в помещении. Цель полного перебивания
≤250 мс из TZ этим результатом не объявляется выполненной.
После Windows-проверки собственных процессов/маркера нет, GPU 0 МиБ, задания проверки
и автоостановки удалены: [уборка](character_checks/pipeline/cleanup.json).
Пакеты установлены и проверены вне checkout, нативный worker синтезировал ненулевой
PCM: [wheel](character_checks/pipeline/wheel.json). Desktop-комплект не обновлялся.

## Оставшиеся границы

Вход всё ещё **полудуплексный**: во время собственного TTS подавлен, сохраняется
хвост gate 0,5 с. Чтобы перебить звучащий ответ, используются Stop/Esc или новый текст;
событие новой речи также отменяет ответ, когда вход открыт. Открытие новой микрофонной
сессии сначала отменяет прежний ответ, чтобы он не попал в только что открытый вход.
Свободное одновременное распознавание речи поверх динамиков без кнопки/AEC не реализовано
и не выдается за готовый голосовой сценарий. Эта часть полной голосовой приёмки остаётся
открытой в 9.23/9.24. Реальные облачные TTS-вызовы без ключей не выполнялись.
Восстановление после отказов устройств/провайдеров относится к следующему пункту 9.10.
