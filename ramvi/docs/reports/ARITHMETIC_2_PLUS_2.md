# Почему на 2 + 2 получалось 2

У двух моделей причины различаются. Для GGUF MoE исправлена интеграция шаблона; у HF 0.6B воспроизведено поведение официального checkpoint. Специального правила «на 2+2 отвечать4» в движке нет.

## HF Qwen3-0.6B

Исходный запрос: `Reply with just the number: 2 + 2 =`, `enable_thinking=False`.

Native CUDA, независимый torch fp32 и официальный Transformers eager fp32 выбрали `[17,151645]` — `2` и EOS. В окончательном аппаратном контроле максимальная ошибка native/oracle на этих позициях **0.000289916992188**. Разрыв первого reference top-1/top-2 **6.1583366394**; это не неоднозначный выбор почти равных оценок.

В macOS official Transformers CPU три повторения также дали `[17,151645]`. Проверенный `model.safetensors` SHA256 `f47f71177f32bcd101b7573ec9171e6a57f4f4d31148d38e382306f42996874b` совпадает с опубликованным LFS SHA256 revision `c1899de289a04d12100db370d81485cdf75e47ca`; конфигурации и tokenizer проверены отдельно. [Метаданные производителя](https://huggingface.co/api/models/Qwen/Qwen3-0.6B?blobs=true), [закреплённый tokenizer config](https://huggingface.co/Qwen/Qwen3-0.6B/resolve/c1899de289a04d12100db370d81485cdf75e47ca/tokenizer_config.json).

С тем же вопросом в thinking-режиме native и официальный Transformers на Windows выдали одинаковые **129 токенов**, включая EOS, и финальный ответ **4**. Это зависимость поведения checkpoint от режима. Она не доказывает общую надёжность его арифметики. Глобальный non-thinking default для HF не менялся.

## GGUF MoE qwen3:30b

Метаданные установленного файла: **Qwen3 30B A3B Thinking2507**, `general.finetune=Thinking`. Производитель указывает поддержку только thinking-режима; открывающий маркер уже добавляется в prompt. [Официальная карточка модели](https://huggingface.co/Qwen/Qwen3-30B-A3B-Thinking-2507).

Прежний общий Qwen3-8B tokenizer добавлял в конец запроса:

```text
<think>

</think>

```

Встроенный шаблон данного GGUF оставляет:

```text
<think>
```

Старый шаблон принудительно закрывал рассуждения модели, для которой такой режим не предусмотрен. Совпадения vocabulary/special IDs было недостаточно: прежняя проверка совместимости не проверяла chat template.

На **тех же весах** старый renderer дал `[17, 198, 151668, 271, 17, 151645]`: `2`, перевод строки, `</think>`, переводы строк, `2`, EOS. Native и независимый fp32 совпали на всей этой последовательности из **6 токенов**, включая EOS. Максимальное абсолютное отличие полных логитов — **0.00776433944702**, все позиции уложились в заданные `atol=0.02, rtol=0.002`, argmax совпал. Значит, в этом воспроизведении ошибочный ответ возникает уже при исходном режиме/шаблоне, а не из-за выбора другого ID native-ядром.

После подключения встроенного template **два отдельных запроса** исходного 2+2 завершились EOS и ответом **4**, по **34 токена** с рассуждениями каждый. В тексте вопроса ничего не менялось.

## Что изменено

`model_template.py` использует встроенный GGUF template для явно помеченного Thinking checkpoint, проверяет наличие/размер шаблона и сохраняет источник. App правильно отделяет reasoning, даже когда открывающий маркер уже находится в prompt. Metadata/capabilities сообщают `thinking_required` и `chat_template_source`; для этой модели `think=false` не отключает её обязательное рассуждение. JSON-ограничение без reasoning adapter отклоняется. Обычные GGUF/HF сохраняют прежние шаблоны.

Математические native/C++ kernels не переписаны. Добавлены **21** проверка политики и интеграции, включая обычные модели, некорректные/слишком большие шаблоны и разделение reasoning/content.

Усечённые рассуждения не оцениваются как законченный правильный/неправильный ответ. Повтор с бюджетом 1024 не завершён до закрытия аппаратного окна. Это остаётся ограничением приёмки, а не скрытым успехом.

Финальная полная численная проверка **dense GGUF 14B** не завершилась за 240 секунд. Более ранний промежуточный forward на исходном вопросе совпал по argmax4 (maxabs0.0061324238777160645), но целый прерванный запуск не считается пройденным. Расширенная диагностическая матрица также сохранена как незавершённая. HF и MoE итоговые проверки завершены полностью.
