# Размер комплекта и готовность к бете (пункт 8.7)

## Размер (замер 2026-11-19, комплект на ноутбуке с RTX 5060)

Папка RAMVI — 4 402 МБ, 33 627 файлов. Из них 548 МБ — скачанная пользователем модель распознавания речи (`models/stt`), в раздачу она не входит. **Сам комплект — около 3,85 ГБ.**

| Часть | МБ |
|---|---|
| `runtime` (встроенный Python и пакеты) | 3 747 |
| — torch (из них библиотеки CUDA — основная часть) | 3 015 |
| — triton | 209 |
| — llvmlite (для numba) | 116 |
| — transformers | 103 |
| — sympy (нужен torch) | 66 |
| `RAMVI.exe` и оболочка | 100 |
| код RAMVI (`ramvi/`) | 6 |

Крупнейшие файлы torch: `torch_cuda.dll` 507, `cublasLt64_13.dll` 435, `torch_cpu.dll` 295, `cufft64_12.dll` 277, `cudnn_engines_precompiled64_9.dll` 214.

## Что можно убрать: `build_portable.py --trim` (по умолчанию выключен)

По таблицам импорта DLL (`import torch` статически тянет 16 библиотек из `torch/lib`) и по коду движка (свёрток, FFT, решателей и cuDNN-внимания нет, ядра свои на Triton и cuBLAS) не нужны:

| Что | МБ |
|---|---|
| подбиблиотеки cuDNN (`cudnn64_9.dll` остаётся: её импортирует torch) | 563 |
| `cusolverMg64_12.dll` (решатель для нескольких карт) | 107 |
| `nvperf_host.dll` (профилирование) | 27 |
| `cufftw64_12.dll` | ≈0 |
| заголовки и `.lib` torch, `torch/share`, `torchgen` (нужны только для сборки расширений) | ≈95 |
| **итого** | **≈790** |

`curand64_10.dll` (56) и `nvJitLink_130_0.dll` (84) статически тоже не подключаются, но в список пока не включены: движок вызывает `torch.randn` на видеокарте при автонастройке. Убирать их — только после отдельной проверки.

**Ещё не проверено:** работа комплекта с `--trim` на Windows с настоящей моделью (загрузка qwen3:8b, ответ, автонастройка, голос) и размер ZIP. Ноутбук был занят другими проверками. До проверки флаг выключен.

Сборщик теперь пишет в `BUILD.json` размеры частей (`sizes`) и что убрано (`trimmed`). С флагом `--zip` он собирает архив для раздачи и печатает его размер.

## Лицензии

Найдено и исправлено: файл `LICENSE` (MIT) не попадал в комплект, хотя механизм обновлений рассчитывает его там найти. Теперь сборщик кладёт в корень `LICENSE` и `THIRD_PARTY_NOTICES.txt`: сводку всех сторонних компонентов (название, версия, лицензия, где лежит текст). Туда входят части не из pip: встроенный Python (PSF), Visual C++ Redistributable, NVIDIA CUDA и cuDNN в составе torch, .NET/Avalonia, токенизатор Qwen3. Обновление может заменять и этот файл.

## Распространяемые компоненты (решения владельца 2026-11-19)

- Модели в релиз не входят (сборщик останавливается, если найдёт файл модели); основную модель и предсказатель (Qwen3-0.6B-GGUF есть в каталоге) пользователь скачивает сам.
- VC++ — только из каталога `VC\Redist\MSVC\<версия>\x64` Visual Studio / Build Tools (`packaging/redist.py`): подпись Microsoft, копия без изменений (SHA-256), основание лицензии — `--vs-license`. На ноутбуке сборки Build Tools пока нет — владелец разрешил установить.
- NVIDIA сверяется с CUDA EULA v13.2 (прил. A) и cuDNN SLA (22.02.2022). `cusolverMg64_12.dll` и `nvperf_host.dll` не распространяемы — удаляются всегда. **`ptxas.exe` (Triton) не распространяем, а нужен — релиз не собирается** (только `--internal`). Предложение владельца: не класть его в комплект, а при запуске проверять наличие CUDA ≥ 13.2 и писать, что установить; сделать следующим шагом.
- Тексты лицензий — папка `licenses/` (условия для NVIDIA и Microsoft, лицензии всех пакетов Python и NuGet, Python).
- Релизы — отдельный публичный репозиторий https://github.com/karabilo214/RAMVI (ничего не опубликовано).
