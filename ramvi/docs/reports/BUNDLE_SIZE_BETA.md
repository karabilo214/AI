# Размер комплекта и готовность к бете (пункт 8.7)

## Размер (замер 2026-11-19, комплект на ноутбуке с RTX 5060)

Папка RAMVI — 4 402 МБ, 33 627 файлов. Из них 548 МБ — скачанная пользователем модель распознавания речи (`models/stt`), в раздачу она не входит. **Сам комплект — около 3,85 ГБ.**

| Часть | МБ |
|---|---|
| `runtime` (встроенный Python и пакеты) | 3 747 |
| — torch (из них библиотеки CUDA — основная часть) | 3 015 |
| — triton | 209 |
| — llvmlite (для numba) | 116 |
| — transformers | 103 |
| — sympy (нужен torch) | 66 |
| `RAMVI.exe` и оболочка | 100 |
| код RAMVI (`ramvi/`) | 6 |

Крупнейшие файлы torch: `torch_cuda.dll` 507, `cublasLt64_13.dll` 435, `torch_cpu.dll` 295, `cufft64_12.dll` 277, `cudnn_engines_precompiled64_9.dll` 214.

## Что можно убрать: `build_portable.py --trim` (по умолчанию выключен)

По таблицам импорта DLL (`import torch` статически тянет 16 библиотек из `torch/lib`) и по коду движка (свёрток, FFT, решателей и cuDNN-внимания нет, ядра свои на Triton и cuBLAS) не нужны:

| Что | МБ |
|---|---|
| подбиблиотеки cuDNN (`cudnn64_9.dll` остаётся: её импортирует torch) | 563 |
| `cusolverMg64_12.dll` (решатель для нескольких карт) | 107 |
| `nvperf_host.dll` (профилирование) | 27 |
| `cufftw64_12.dll` | ≈0 |
| заголовки и `.lib` torch, `torch/share`, `torchgen` (нужны только для сборки расширений) | ≈95 |
| **итого** | **≈790** |

`curand64_10.dll` (56) и `nvJitLink_130_0.dll` (84) статически тоже не подключаются, но в список пока не включены: движок вызывает `torch.randn` на видеокарте при автонастройке. Убирать их — только после отдельной проверки.

**Ещё не проверено:** работа комплекта с `--trim` на Windows с настоящей моделью (загрузка qwen3:8b, ответ, автонастройка, голос) и размер ZIP. Ноутбук был занят другими проверками. До проверки флаг выключен.

Сборщик теперь пишет в `BUILD.json` размеры частей (`sizes`) и что убрано (`trimmed`). С флагом `--zip` он собирает архив для раздачи и печатает его размер.

## Лицензии

Найдено и исправлено: файл `LICENSE` (MIT) не попадал в комплект, хотя механизм обновлений рассчитывает его там найти. Теперь сборщик кладёт в корень `LICENSE` и `THIRD_PARTY_NOTICES.txt`: сводку всех сторонних компонентов (название, версия, лицензия, где лежит текст). ## Распространяемые компоненты (решения владельца 2026-11-19)

- Модели в релиз не входят (сборщик останавливается, если найдёт файл модели); основную модель и предсказатель (Qwen3-0.6B-GGUF есть в каталоге) пользователь скачивает сам.
- VC++ — только из каталога `VC\Redist\MSVC\<версия>\x64` Visual Studio / Build Tools (`packaging/redist.py`): подпись Microsoft, копия без изменений (SHA-256), основание лицензии — `--vs-license`. На ноутбуке сборки Build Tools пока нет — владелец разрешил установить.
- NVIDIA сверяется с CUDA EULA v13.2 (прил. A) и cuDNN SLA (22.02.2022). `cusolverMg64_12.dll` и `nvperf_host.dll` не распространяемы — удаляются всегда. `ptxas.exe` (Triton) тоже не распространяем — и **больше не нужен**: ядра Triton компилирует JIT драйвера NVIDIA (`engine/ramvi_engine/kernels/driver_jit.py`: загрузчику отдаётся PTX вместо cubin). Проверено на ноутбуке с RTX 5060, чистый кеш Triton: ответ из 344 токенов побайтно тот же (sha256 `6AE17847D8A5ECA4…` в обоих режимах), 15,0 с через драйвер против 16,3 с с ptxas; загрузка 28 и 29–48 с. Сборщик удаляет `ptxas.exe`. Клиенту нужен только драйвер, без CUDA Toolkit.
- Перед каждым запуском движка сервис спрашивает у драйвера поддерживаемую CUDA (`driver_gate.py`, `cuDriverGetVersion`). Нет драйвера → `engine.no_nvidia_driver`, CUDA ниже 13.2 → `engine.driver_cuda_old`. Сообщение говорит, что установить: драйвер GeForce с nvidia.com/drivers, CUDA Toolkit не нужен. Драйвер ноутбука 616.92 сообщает CUDA 13.4, проверка проходит. Порог 13.2 выбран владельцем; по правилу совместимости младших версий CUDA библиотеки 13.2 могли бы работать и с драйвером 13.0, но это не проверено.
- Тексты лицензий — папка `licenses/` (условия для NVIDIA и Microsoft, лицензии всех пакетов Python и NuGet, Python).
- Релизы — отдельный публичный репозиторий https://github.com/karabilo214/RAMVI (ничего не опубликовано).

## Релизный комплект 0.8.0 (собран 2026-11-19 на ноутбуке с RTX 5060)

Сборка: Python комплекта (те же пакеты), оболочка собрана на Mac (`dotnet publish -r win-x64 --self-contained`, без .pdb), встроенный Python 3.12.10 с python.org, VC++ из Build Tools 17.14 (`Redist 14.44.35112`, 10 файлов, подпись Microsoft, SHA-256 в BUILD.json), `--vs-license open-source --trim --zip`.

| | |
|---|---|
| Папка | 3 071 МиБ (было 3,85 ГБ без обрезки и модели речи) |
| ZIP | 1 916 593 117 байт = 1,79 ГиБ (меньше предела файла GitHub Releases 2 ГиБ) |
| SHA-256 ZIP | `1AAE16D77012DA38ACE4C39882FCDE58B4CA98F0E124CFAC05B18700D534CB1C` |
| Файлы NVIDIA | 14, все из списков CUDA EULA 13.2 и cuDNN SLA; ptxas, cusolverMg, nvperf_host, cufftw и подбиблиотеки cuDNN удалены |
| Лицензии | `licenses/`: 58 пакетов Python, 20 NuGet, Python, условия NVIDIA и Microsoft |

**Экзамен 4 на этом комплекте** (без сети, ловушка во всех процессах Python): чат qwen3:8b «391» (ядра собраны драйвером, cuDNN нет), голос 26/26, 8/9, 18/20, файлы агента работают, попыток выйти в сеть 0, с загруженной моделью свободно 8 ГБ RAM.

**Найдено при сборке и исправлено** (без проверки на настоящем комплекте ушло бы пользователям):
1. `--trim` удалял `torchgen`, а его импортирует `import torch`: движок не запускался. `torchgen` больше не трогается.
2. Сборщик терял DLL pywhispercpp (`whisper-*.dll`, `ggml-*.dll`): в RECORD они записаны как `pywhispercpp-1.5.1.data/platlib/…`, а `importlib.metadata` в Python 3.12 молча выбрасывает отсутствующие пути. Голос не работал. Теперь RECORD читается напрямую, такие пути переводятся в корень site-packages.
3. ZIP падал на файлах с датой раньше 1980 года — `strict_timestamps=False`.
4. Защита от моделей принимала служебный `distutils-precedence.pth` за модель — проверяются только файлы от 1 МБ.
5. У `tokenizers` нет файла лицензии — подкладывается текст Apache-2.0 из другого пакета комплекта.

**Вопрос владельцу:** колесо pywhispercpp само несёт копии библиотек Microsoft под изменёнными именами (`msvcp140-a4c2229b….dll`, `vcomp140-f96f3a14….dll` — так их переименовывает delvewheel, на них ссылаются DLL whisper). Это не файлы из каталога VC\Redist. Варианты: оставить как часть пакета pywhispercpp (так его раздаёт PyPI) или пересобрать whisper.cpp так, чтобы он брал общие `msvcp140.dll`/`vcomp140.dll` комплекта.

Решение владельца: копии VC++ внутри pywhispercpp оставить. Финальная сборка (с текстами MIT для пакетов NuGet без файла лицензии): ZIP 1 916 605 091 байт, SHA-256 `362b7409b82233395bfdb8ea8b907591f86cad6c598b7a53aadf43007b4201b2`. **Опубликовано:** https://github.com/karabilo214/RAMVI/releases/tag/v0.8.0.
