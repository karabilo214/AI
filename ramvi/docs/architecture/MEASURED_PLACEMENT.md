# Размещение по измерениям

Первоначальный план ограничивает постоянные GPU-слои доступной памятью. Для остальных слоёв можно явно измерить CPU, GPU-вычисление и передачу весов, затем выбрать маршрут отдельно для каждой измеренной длины пачки.

```python
profile = eng.calibrate_placement(batches=(1, 4, 16), repeats=3)
eng.configure_placement(profile)
```

Калибровку выполняют на свободном движке, перед обслуживанием запросов. Она компилирует/прогревает ядра, собирает медианы, инвалидирует KV и может добавить CPU-представление подкачиваемых слоёв. При недостатке RAM она прекращается с ошибкой. Настройки потоков должны соответствовать рабочему режиму.

Профиль можно сохранить как JSON и загрузить через `RAMVI_LAYER_PROFILE=/path/profile.json`. При загрузке через переменную нужен явный `--resident`, соответствующий профилю; после `autofit()` профиль применяют методом `configure_placement()`. Модель, CPU/GPU, RAM, число потоков, контекст и размещение должны соответствовать профилю. OOM-перенос слоя сбрасывает измеренные маршруты. Для неизмеренной длины пачки и контекста за пределами первого блока из 256 позиций действует исходный маршрут.

Алгоритм оценивает критический путь с двумя буферами DMA и ищет улучшения от исходной раскладки, CPU и подкачки. Кандидат проходит замер полного декодирующего прохода с копированием KV: три повтора с чередованием порядка. Если токены различаются или медианный выигрыш не превышает 5%, сохраняется исходный маршрут. Это поиск по измеренной модели стоимости, а не доказательство глобального оптимума. Фактическую скорость необходимо проверять парным прогоном: `python -m ramvi.engine.tools check measured_plan -- --deadline <ISO UTC>`.

Ограничения: не перераспределяет постоянные GPU-слои; не измеряет длинный prefill; не адаптируется автоматически к изменению фоновой нагрузки. Для обновления измерений нужна явная повторная калибровка. В `make_plan()` плотного HF-движка измеренные времена можно передать через `layer_costs`; автоматический сбор реализован для GGUF.
