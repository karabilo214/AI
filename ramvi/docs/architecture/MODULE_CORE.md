# Основа модулей RAMVI — пункты 2.9–2.16

Реализована лёгкая координация в пакете `ramvi/service/ramvi_service`. Это инфраструктура платформы, а не реализация Character, Chat/Agent UI, OS-захвата экрана или аудио. Engine не импортирует Service. Импорт Host не загружает torch/numpy, UI, микрофон, TTS или персонажа и не запускает процессы.

## Принятое решение

Вычислительный Engine остаётся независимым backend. Module Host хранит метаданные доверенных встроенных/явно установленных пакетов; отдельный модуль загружается через `package.module:factory` только при initialize/activate. В Host нет проверок идентификатора `character` или ветвлений по эмоциям.

Манифест содержит module_id, package version, Module API version, entrypoint, обязательные/необязательные зависимости, запрошенные сервисы/разрешения, лимиты ресурсов, версию собственных данных и необязательное описание UI. Module API сейчас `1.0`; неподдерживаемая версия, цикл, отсутствующая зависимость и несогласованный точный version pin диагностируются до активации. Это не менеджер пакетов и не магазин расширений; проверка подписи/доставки пакета относится к выпуску.

LLM Provider — отдельный публичный контракт с text/image/streaming/JSON/tools/external capabilities. Они описывают адаптер провайдера, а не архитектуру CUDA/CPU-слоёв. LocalEngineProvider использует публичный HTTP API; по умолчанию JSON/tools/image capabilities консервативно выключены до явной конфигурации. Текстовые вызовы не исполняют tools.

## Жизненный цикл и worker

`ModuleHost` реализует initialize, activate, deactivate, suspend, resume и dispose. Повторные допустимые операции идемпотентны; неправильный переход возвращает ошибку. Activate активирует обязательные зависимости. Initialize готовит лёгкий scope; ресурсы/LLM/контекст нельзя запрашивать до active. Запрошенные разрешения должны быть отдельно одобрены Host.

Worker запускается через **общий `ramvi_engine.processes.ProcessSupervisor`**, используемый также процессным Engine. Module controller не содержит второго кода убийства процессов/Windows Job. Используются ограниченный JSONL RPC, таймауты, ограниченный диагностический вывод и остановка дерева дочерних процессов. Hook error, crash или timeout переводят только этот модуль в error; соседи продолжают работать.

При остановке сохраняется JSON-checkpoint, завершается worker, закрываются подписки, отменяются аренды/LLM-запросы этого владельца, отзывается bearer scope. Suspend тоже завершает worker; resume создаёт новый worker с checkpoint и вызывает resume. Это исключает скрытый animation loop/микрофон у приостановленного модуля. Процесс недоступного/выключенного модуля не существует. Dispose не удаляет данные.

Update деактивирует модуль, сохраняет checkpoint, делает backup только его namespace, выполняет миграции и пробует новую версию. Ошибка возвращает прежние файлы/версию и прежнее активное состояние; другие workers и данные не перезапускаются. Uninstall сохраняет данные; `purge_data=True` — отдельное явное действие. Character worker по этому контракту появится в этапе 9; тестовый worker не объявляется готовым персонажем.

## Идентичность и Scoped Services

Authority создаёт непредсказуемый bearer token, связанный с module_id, principal_id и session_id. Владелец запроса определяется Host/авторизацией. JSON payload не может подменить owner/module/session. После отзыва scope новые запросы запрещены.

Module worker получает loopback Scoped Services endpoint и только свой token. Сервисы доступны через ServiceClient: settings, data, secrets, resources, events, LLM и optional Context Provider. Это реальные RPC-вызовы к общим Host-owned экземплярам, а не отдельные копии сервисов в каждом worker.

ScopedData ограничивает пути `modules/<module_id>`, отклоняет абсолютные пути, `..`, Windows drive/backslash и symlink-переходы. JSON ограничен по размеру и записывается атомарно. Миграции выполняются в staging с последовательной сменой версии и заменой только этого namespace; неуспешная миграция не портит исходные данные.

ScopedSecrets передаёт namespace в подключаемый SecretBackend. Bootstrap MemorySecrets хранит значения только в RAM, не пишет ключи в JSON и не является зашифрованным постоянным хранилищем. OS credential store и общий Storage — отдельные адаптеры этапа 3; текущий интерфейс позволяет подключить их без изменения модуля. Core API изолирует доверенные модули, но не является OS sandbox для произвольного враждебного Python-кода.

Scoped Services Gateway ограничен 32 соединениями, задаёт socket timeout до чтения HTTP headers и закрывает активные сокеты при остановке. Scope отслеживает текущие вызовы: деактивация отменяет их и ждёт завершения перед обновлением данных. Не завершившаяся в срок операция даёт диагностируемый timeout, а не ложное сообщение об очистке.

HTTP transport разрешает только чистый loopback URL с портом, без userinfo/path/query/fragment; proxy и перенаправления выключены. Таким образом ключ не перенаправляется на внешний хост через строку вида `127.0.0.1:port@other` или HTTP redirect.

## Методы и потоковый ответ модели

Методы Scoped Services регистрируются в одной таблице (`ROUTES`, декоратор `@handler`). У каждого метода задано право; оно проверяется до обработчика. Неизвестный метод даёт одну общую ошибку.

`llm.complete` возвращает ответ целиком; этого достаточно для обычного чата. Голосовому персонажу нужен поток: озвучка начинается с первых слов, перебивание должно срабатывать быстро (цели Character TZ §16: озвучка ≤ 1,5 с, перебивание ≤ 250 мс). Для этого есть:

- `llm.stream` — начать ответ, вернуть `stream_id`;
- `llm.read` — подождать до 0,5 с и забрать все накопленные куски; `done=true` означает, что генерация завершена и модель освобождена;
- `llm.cancel` — отменить сразу: старые куски больше не выдаются, движок получает `/engine/cancel`.

В модуле: `for chunk in services.stream(request): ...`; выход из цикла отменяет генерацию. Куски не зависят от протокола провайдера: `text`, `reasoning`, `tool_calls`, последний — `end` (`finish_reason`, `usage`). Провайдер объявляет `ProviderCapabilities.streaming` и реализует `StreamingLLMProvider.stream`; без этого `llm.stream` отклоняется.

Буфер потока ограничен (256 кусков): если модуль не читает, генерация ждёт. Если модуль не читает 30 с, поток отменяется и модель освобождается. Одновременно у модуля не больше 2 потоков. Новый запрос того же модуля после перебивания ждёт остановки старого, а не получает отказ по квоте. Остановка scope отменяет потоки и ждёт их завершения.

Замер на фальшивом движке (слово каждые 50 мс, 20 слов, 10 прогонов, Mac): первое слово у модуля через 53–61 мс (весь ответ 1059–1089 мс); после перебивания движок получает отмену через 2–10 мс; первое слово нового ответа через 105–114 мс (в это входят остановка старой генерации и задержка движка на первое слово). На настоящей модели не измерялось.



ResourceBroker выдаёт аренды по FIFO, проверяет общий бюджет и per-owner quota, ограничивает очередь и число аренд. Есть отмена/таймаут и освобождение владельца. Дополнительные RAM/VRAM считаются поверх **того же ResourceEstimate** через `with_model_estimate`; второй планировщик слоёв не создаётся. CPU/audio допускаются как отдельные единицы ресурса; захват реального устройства выполняет его будущий адаптер.

SharedLLM хранит ссылки владельцев общей модели и одну очередь inference. Остановка персонажа не выгружает модель активного Chat. Отмена касается только активного запроса владельца; execution slot освобождается в finally фактического завершения provider.complete, а не заранее. Поздний отменённый ответ отбрасывается. Выгрузка последней модели — подключаемая политика; временно выключенный модуль не распоряжается чужими ресурсами.

LocalEngineProvider посылает уникальный X-Request-ID и отменяет через `/engine/cancel {request_id}`. Idle cancel ничего не отправляет. Это не глобальная отмена произвольного запроса Engine. Внешний провайдер дополнительно требует разрешения egress.text, а изображение — image capability и egress.image. Отзыв egress сигналит тому же cancel Event выполняющегося provider.complete и аннулирует поздний результат. Scoped complete сейчас выдаёт один итоговый ответ; потоковый provider adapter подключается отдельно. Запрошенные tools/JSON отклоняются, если capabilities их не объявляют. Принудительная остановка некооперативного внешнего backend не обещается: адаптер обязан иметь сетевой таймаут и обрабатывать cancel.

## События

EventBus использует **общий `ramvi_engine.protocol.EventContext/EventFactory`**, version=1, request_id, монотонное время, module/session/response/event ID, sequence и payload. Тип — `module.<module_id>.<name>`. Host регистрирует EventSpec с обязательными/допустимыми полями и типами; неизвестные поля и несовместимые значения отклоняются, дополнительно действует ограниченный JSON-контракт Engine.

Каждая подписка ограничена по размеру, доступна только своему owner; переполнение учитывается dropped. Новый response_id и cancel очищают старую очередь, поздние события не выдаются и не вытесняют новый ответ. Отписка/остановка модуля закрывает его подписки. Обычные API-клиенты Engine не обязаны знать о Module Host.

## Контекст выбранного приложения

Optional ContextProvider получает OS adapter извне. Он не выбирает чужие окна сам и не включает постоянные облачные скриншоты. По умолчанию используется структурированный UI Context; Screen запрашивается явно и требует image-input capability.

Независимые гранты: context.ui, context.screen, agent.control, egress.text, egress.image; контекст/egress привязаны к выбранному приложению. Read-грант не даёт права кликать, вводить или менять данные. Snapshot имеет ID, время, источник, приложение/окно и проверяемую принадлежность владельцу; произвольный/изменённый snapshot не проходит egress.

Выбор приложения выполняет доверенный Host/UI через approve_application/revoke_application, а не module RPC. Одобрение общего разрешения context.ui само по себе не открывает все приложения. Выбранные гранты восстанавливаются на resume; явный revoke не восстанавливается.

Размер/частота сбора ограничены. Отзыв прав немедленно устанавливает cancel Event для текущего сбора/передачи; результат дополнительно проверяется после адаптера. `transmit` требует повторной проверки read/egress и передаёт cancel sender-адаптеру. Уже отправленные байты отозвать нельзя; адаптер обязан прекращать новые отправки. Данные экрана не сохраняются в память/журнал автоматически. OS accessibility/screenshot implementations и UI действий остаются этапами 6/9; контракт и разграничение прав уже работают без них.

## Приёмка инфраструктуры

В `ramvi/tests/module_fixture.py` находится небольшой независимый тестовый модуль; он не входит в продуктовый набор функций. Тесты запускают два настоящих дочерних worker, проверяют данные, events через ServiceClient, checkpoint/suspend/resume, crash/hang одного worker без повреждения другого, rollback обновления, очистку ресурсов и отсутствие тяжёлых импортов у выключенного модуля.

Дополнительно проверяются authority forgery, scoped path/symlink, миграция с откатом, независимые секреты, queue bounds, поздние события, FIFO/quota/cancel, ResourceEstimate accounting, shared LLM ownership, read/egress/image/agent rights, отзыв разрешения во время передачи и targeted provider cancellation. Это контрактная проверка инфраструктуры; новых аппаратных результатов или готовности Character из неё не следует.
