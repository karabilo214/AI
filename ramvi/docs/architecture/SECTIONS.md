# Разделы интерфейса (CORE-UI-01, пункт 3.11)

«Чат» — встроенный раздел, есть всегда. Agent (этап 6) и Character (этап 9) — разделы модулей:
появляются, только если модуль установлен. Если разделов больше одного, слева видна панель разделов.

## Описание раздела в манифесте модуля

```json
{
  "module_id": "character", "version": "1.0.0", "entrypoint": "ramvi_character.module:create",
  "ui": {"section": {"view": "character", "title_key": "section.character", "icon": "character", "order": 30}}
}
```

- `view` — один из встроенных видов оболочки (`agent`, `character`). Оболочка **не загружает код
  модулей**: виды встроены в неё (Character — на Skia, ADR-0003), модуль даёт только описание.
- `title_key` — ключ перевода `section.*`; `icon` — короткое имя; `order` — порядок в панели.
- Установленные модули: `<папка приложения>/modules/<id>/manifest.json`. Сломанный манифест не мешает
  остальным, он попадает в список проблем реестра.

## Ленивость и независимость

- При запуске модули только регистрируются в `ModuleHost`; процесс модуля стартует при **первом
  открытии** раздела (`POST /ui/v1/sections/{id}/open` → `ModuleHost.activate`). Приостановленный
  модуль при открытии возобновляется.
- Повторное открытие ничего не перезапускает, поэтому переключение разделов не меняет состояние,
  процесс и разрешения модуля. Вид раздела в оболочке создаётся при первом открытии и хранится.
- Чат — тот же объект со всеми диалогами, вводом и вложениями; переключение его не трогает.
- Ошибка модуля (нет пакета, падение) — статус его раздела с текстом ошибки; чат работает.
- При выходе сервис останавливает процессы открытых модулей.

API: `GET /ui/v1/sections` → `[{id, title_key, icon, order, view, module_id, state, error}]`;
состояния: `ready` (чат), `available` (установлен, не загружен), `active`, `suspended`, `error` …

Проверки: `tests/test_sections.py` (тестовый модуль `ramvi.tests.module_fixture`: процесс не запущен
до открытия; PID и состояние модуля не меняются при переключении; сломанный модуль — ошибка раздела),
`desktop/tests/.../SectionsTests.cs` и окно без экрана. Собственных экранов Agent/Character ещё нет —
показывается состояние модуля.
