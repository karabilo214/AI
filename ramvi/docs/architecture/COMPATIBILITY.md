# Совместимость модели с компьютером (4.4 MOD-03)

Код: `service/ramvi_service/compat.py` (статусы), `model_fit.py` (план движка → статус),
`gguf_meta.py` (заголовок GGUF без весов), `catalog/headers.py` (копии заголовков).
Тесты: `tests/test_compat.py`, `tests/test_model_fit.py`.

## Как считается

1. **Заголовок GGUF.** У модели каталога читается только начало файла: запрос Range,
   сначала 8 МиБ, при нехватке больше, но не более 64 МиБ. Копия сохраняется в
   `<папка данных>/catalog/headers/<sha256>.json` и больше не обновляется: у файла с тем
   же SHA-256 заголовок не меняется. У установленной модели заголовок читается из файла.
   Веса не читаются.
2. **План движка.** Заголовок отдаётся тому же планировщику, что выбирает размещение
   слоёв при загрузке: `planning.automatic.choose_plan` + `planning.resources.estimate_gguf`.
   `gguf_meta.GGUFMeta` повторяет нужный им интерфейс (`meta`, `tensors`, `raw`).
   Бюджет — возможности компьютера: VRAM самой большой NVIDIA и вся RAM. Контекст — 2048,
   как в чате. Угадыватель (draft) в оценку не входит.
3. **Статус** (`compat.assess`):

| Статус | Когда |
|---|---|
| Рекомендуется | все слои в видеопамяти |
| Медленно | часть слоёв на CPU или по шине, **или** веса из файла не помещаются в RAM и дочитываются с диска |
| Не хватает VRAM | даже самый лёгкий план не помещается в видеопамять |
| Не хватает RAM | собственная RAM движка больше всей памяти |
| Не хватает диска | не скачана, а места меньше файла + 512 МБ |
| Не поддерживается | нет NVIDIA, другая архитектура или тип матриц без ядра движка |
| Нет данных | заголовок ещё не прочитан — нужно обновить каталог |

Каждый статус приходит с причинами (ключи `compat.reason.*` с числами) и скоростью.
Скорость: замер (`compat.MEASURED`, ключ `model_fit.model_key`, например `qwen3-14b-q4_k_m`),
если он есть; иначе оценка по плану (`speed.py`, «оценка ~X–Y токенов/с»). Нехватка **свободной** RAM сейчас — пометка
«закройте программы», а не отказ.

### Две поправки к прежним правилам `compat.py`

- **Входные эмбеддинги.** Движок всегда читает их из файла, поэтому раньше даже модель целиком в
  VRAM получала «Медленно». Теперь «Медленно» ставится по байтам слоёв вне видеокарты по плану
  (`Candidate.off_gpu_bytes`).
- **Веса из файла больше RAM.** Раньше это было «Не хватает RAM», теперь «Медленно» с причиной
  «дочитываются с диска». На ноутбуке с RTX 5060 и 16 ГБ RAM так реально работали `qwen3:30b` и `qwen3-8b-f16`
  (2,35 ток/с), и планировщик движка тоже это допускает (`allow_paging`).

## Оценка скорости (`speed.py`)

Генерация токена упирается в чтение весов: каждый слой читается целиком (у MoE — только
выбранные эксперты: 8 из 128) оттуда, где он лежит по плану:

    t = VRAM_байты / 340 ГБ/с + CPU_байты / RAM + байты_по_шине / 14,5 ГБ/с
        + нехватка_RAM / 2,3 ГБ/с + слои × 89 мкс

- RAM = min(25 ГБ/с, ядра × 4 ГБ/с); у MoE на CPU — × 0,48 (слой 2,85 мс против 1,38 мс по
  пропускной способности, замер).
- Слои «hyb» в одиночном шаге считает CPU.
- Диапазон: нижняя граница — CPU и шина по очереди и −15 % накладных расходов, верхняя —
  параллельно.
- Угадыватель не учитывается: с ним 14B было в 1,5 раза быстрее.

Все константы взяты из замеров на ноутбуке с RTX 5060 8 ГБ, Ryzen 7 260 (8 ядер) и 16 ГБ DDR5
в один канал: чтение VRAM 320–360 ГБ/с, RAM 25–27, PCIe 14,5, SSD 2,3. Плата за слой выведена
из 8B: 17,5 мс на токен минус 14,3 мс на чтение, делённое на 36 слоёв. Пропускную способность
памяти другого компьютера мы не знаем — там оценка грубее, точное число даст контрольный
прогон (4.7).

| Модель, размещение | Оценка, ток/с | Замер, ток/с |
|---|---|---|
| 8B Q4, всё в VRAM | 48–57 | 55–58 |
| 14B Q4, 21 VRAM / 8 шина / 11 CPU, без угадывателя | 3,8–7,6 | 5,6–6,1 |
| 8B F16, 15 VRAM / 21 CPU | 2,4–2,9 | 2,35 (на 4 % ниже) |
| 30B MoE, 14 VRAM / 34 CPU | 8,2–9,7 | 8–9,7 |
| 0.6B, всё в VRAM | 220–260 | ~290 (3,4 мс, другой движок — HF 12 бит) |

Тест `tests/test_speed.py` держит эти точки: замер не дальше 10 % от диапазона оценки.

## API (`/ui/v1`)

- `GET /catalog`, `POST /catalog/refresh` — у каждой записи поле `compat`. Обновление каталога
  заодно читает недостающие заголовки (по 4 параллельно); `GET` в сеть не ходит.
- `GET /models` — у каждой установленной модели поле `compat` (заголовок из файла, кэш по пути,
  размеру и времени изменения).

`compat` = `{status, reasons[], speed, plan: {layers, resident, gpu, stream, cpu, hyb, off_gpu_bytes},
memory: {vram, ram, mapped}}`.

## Проверка

- Разборщик заголовка сверен с разборщиком движка до байта: на настоящем `qwen3:0.6b` (заголовок
  прочитан по сети Range, файл скачан целиком) совпали метаданные, все 311 тензоров и
  `estimate_gguf` на четырёх размещениях с C++-ядром и без. В тестах то же самое сверяется на
  маленьком настоящем GGUF.
- Настоящий каталог, профиль ноутбука с RTX 5060 8 ГБ и 16 ГБ RAM, Mac M1 Pro, 2026-11-17:
  заголовки 17 моделей прочитаны за 28,6 с (копии 408 КиБ).

| Модель | Статус | Слоёв в VRAM | Скорость, ток/с |
|---|---|---|---|
| qwen3:0.6b Q4_K_M | Рекомендуется | все | оценка ~230–270 |
| qwen3:1.7b Q4_K_M, 0.6b F16 | Рекомендуется | все | оценка ~140–170 |
| Qwen3 4B Q4_K_M | Рекомендуется | все | оценка ~81–95 |
| Qwen3 8B Q4_K_M | Рекомендуется | все | оценка ~48–59 |
| qwen3:1.7b F16 | Рекомендуется | все | оценка ~67–79 |
| Qwen3-14B Q4_K_M | Медленно | 29–30 из 40 | 7,8–9,1 (замер, с угадывателем) |
| qwen3:4b F16 | Медленно | 31 из 36 | оценка ~13–16 |
| Qwen3-30B-A3B Q4_K_M | Медленно, «закройте программы» | 18 из 48 | оценка ~9,2–11 |

Число слоёв здесь — оценка без угадывателя и при всей VRAM. При загрузке движок считает по
свободной памяти и с угадывателем, поэтому на этом ноутбуке у 14B при загрузке было 20–21 слой в VRAM.

## Чего пока нет

- Замеров скорости 0.6B–8B в `MEASURED` (только 14B) — показывается оценка. Точные числа даст
  контрольный прогон (4.7).
- Показа и фильтров в интерфейсе — 4.11. Данные для фильтров (квант, размер, лицензия, контекст,
  статус) уже есть в записях; `compat.filter_models` фильтрует по статусу и размеру.
- Профиля задачи (контекст, тип задачи) — 4.5.
