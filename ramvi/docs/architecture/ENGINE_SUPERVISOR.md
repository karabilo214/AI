# Супервизор движка и worker модулей — 3.3

`ramvi_service.supervisor.Supervisor` следит за одним процессом: запускает, проверяет, перезапускает и пишет файл состояния. Один и тот же класс работает с движком (`EngineProcess`, 2.8) и с worker модуля (`ProcessTarget` поверх `ProcessSupervisor`, 2.14). Нового способа запускать и убивать процессы нет: остановка по-прежнему идёт через `ProcessSupervisor` (группа процессов на POSIX, Job Object на Windows).

```python
from pathlib import Path
from ramvi_engine.engine_process import EngineProcess
from ramvi_engine.model_loader import ModelConfig
from ramvi_service.supervisor import Supervisor, discover

sup = Supervisor(EngineProcess(ModelConfig("Qwen3-0.6B")), Path(data_dir) / "run")
sup.start()  # сразу возвращает "starting", загрузка идёт в фоне
sup.wait("ready", "failed", timeout=300)
...
sup.stop()  # останавливает только свой движок и освобождает имя

discover(Path(data_dir) / "run", "engine")  # для интерфейса и других клиентов
```

## Состояния

| Состояние | Что значит | Что дальше |
|---|---|---|
| `starting` | первый запуск | `ready` или пауза и повтор |
| `ready` | процесс жив и отвечает на проверку | раз в `interval` секунд проверка |
| `restarting` | процесс упал или завис, ждём паузу | новый запуск |
| `failed` | слишком много падений подряд | только ручной `restart()` |
| `stopped` | остановлен владельцем | — |

Мониторинг: каждую `interval` (1 с) — жив ли процесс и `probe()`. У движка `probe()` — запрос `/health` с проверкой `instance_id` (таймаут 2 с), то есть отвечает именно наш экземпляр. Процесс умер — сразу перезапуск. Не ответил `failure_threshold` раз подряд (3) — считается зависшим: останавливается и перезапускается.

Перезапуск: пауза 1, 2, 4 … до 30 с (`RestartPolicy`). Не больше 5 автоперезапусков за 5 минут — затем `failed`, без бесконечного цикла. Причина последнего сбоя, код выхода и последние 50 событий — в `status()` и в файле состояния.

## Discovery: файл состояния

`<run_dir>/<name>.json` (по умолчанию имя `engine`) переписывается атомарно при каждой смене состояния: состояние, адрес движка, PID, `instance_id`, модель, число перезапусков, последний сбой, PID и ID владельца. **API-ключа в файле нет.** Интерфейс общается с сервисом, а не с движком напрямую.

Рядом `<name>.lock` — блокировка ОС (`flock` / `msvcrt.locking`), её держит владелец всё время работы. `discover()` возвращает содержимое файла и `live` — занята ли блокировка. Если владелец умер, ОС снимает блокировку сама, и файл становится историей (`live: false`).

## Чужие процессы не трогаются

- Пока блокировка занята, второй супервизор с тем же именем не запускается (`OwnershipError`) и ничего не меняет — ни процесс, ни файл.
- PID из старого файла **никогда не завершается**: после аварии этот номер мог достаться другому процессу. Новый владелец только записывает старые сведения в `previous` для диагностики.
- Движок прежнего владельца уходит сам. `EngineProcess` задаёт `RAMVI_EXIT_WITH_PARENT=1`, и `ramvi_engine serve` ещё до загрузки весов запускает `ParentWatch`: сервис держит stdin движка открытым и ничего не пишет. Умер сервис — ОС закрывает канал, движок видит конец потока и прерывает главный поток, как Ctrl+C: срабатывают прежние `finally` загрузки и `serve`, модели закрываются. Если мягкий выход не успел, через 10 с процесс завершается сам. Функция `serve` не менялась; в `cli.py` добавлена одна ветка запуска сторожа, она разрешена в исторической проверке `test_migration_sources.py`. На Windows это дополняет Job Object с kill-on-close.
- Если сирота ещё не успел уйти и держит видеопамять, первый запуск нового владельца может не удаться; пауза 1+2+4+8 с перекрывает 10 с сторожа.

## Worker модулей

`ProcessTarget(process, probe)` подключает `ProcessSupervisor` worker к тому же монитору; `probe` — например RPC `ping` с коротким таймаутом. У каждого worker своё имя (`mod-a`, `mod-b` …) и своя блокировка; падение одного не затрагивает другой. `ModuleHost` (2.14) пока по-прежнему отключает модуль после ошибки и восстанавливает его явным вызовом — автоматический перезапуск модулей через этот супервизор не включён.
