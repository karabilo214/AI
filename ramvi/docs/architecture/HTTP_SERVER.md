# Разделение HTTP-сервера (1.5)

Сервер разделён по ответственности без изменения форматов запросов, ответов, ошибок и потоковой выдачи.

| Модуль | Ответственность |
|---|---|
| `server/app.py` | Состояние модели, токенизация, авторизация, маршрутизация, ограничения очереди и соединений |
| `server/routes_openai.py` | Chat/completions и completions, включая SSE, tools и usage |
| `server/routes_anthropic.py` | Messages, блоки thinking/text/tool_use и события потока |
| `server/routes_ollama.py` | Chat/generate, JSON и NDJSON, счётчики времени и токенов |
| `server/validation.py` | Проверка чисел и возможностей, преобразование сообщений и схем инструментов |
| `server/streaming.py` | Очередь событий модели, отмена, разбор служебных меток, транспорт SSE/NDJSON |

Обработчики протоколов остаются замыканиями на один экземпляр приложения. `make_handler()` связывает их с HTTP-классом; состояние модели и блокировка остаются общими. Методы работы с очередью вынесены в `GenerationStream`, транспорт — в `StreamingResponse`. Значения ограничений, обработка исключений и порядок вызовов сохранены.

JSON на границе протоколов остаётся динамическим; добавлены аннотации и проверка mypy без преобразования старых форм данных в новые схемы. Переходные экспорты вспомогательных функций доступны в `server.app`, но сами обработчики импортируют зависимости напрямую.

`engine/tests/test_server_split.py` сравнивает тела всех вынесенных функций и методов с принятым сервером коммита `0759203`. Из сравнения исключаются только аннотации, документация и пути импортов; изменение кода ответа контроль обнаруживает. Прежние тесты проверяют реальные HTTP-запросы к пяти endpoint в обоих режимах, ошибки после начала SSE, отмену и медленного потребителя.

Локальные проверки не заменяют итоговый Windows/CUDA-экзамен этапа 1. Критерии — в [плане](../PLAN.md).

Итоговый Windows/CUDA-экзамен завершён: официальные API-клиенты 14/14, WIDE30 × 4 с текстами 30/30. [Условия и результаты](../reports/STAGE1_ACCEPTANCE.md).
