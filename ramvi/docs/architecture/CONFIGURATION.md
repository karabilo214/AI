# Настройки и изменяемые данные RAMVI (1.8)

Пакет читает настройки через `ramvi_engine.config`. Новые имена имеют префикс `RAMVI_`. Для переходного периода сохраняются прежние `LLM_`: если новое имя присутствует в окружении, используется именно его значение, даже пустое; иначе читается прежнее имя, затем прежнее значение по умолчанию. Пустое значение числовой настройки не заменяется старой настройкой и приводит к обычной ошибке разбора числа.

## Каталог данных

`RAMVI_DATA_DIR` задаёт корень изменяемых данных. Для одинакового правила перехода поддерживается и `LLM_DATA_DIR`; при наличии нового имени старое игнорируется. Относительный путь отсчитывается от текущего каталога запуска, `~` раскрывается. Пустой или состоящий только из пробелов корень отклоняется. Вычисление путей не создаёт каталогов; создание происходит перед фактической записью.

Если настройка отсутствует:

| Платформа | Корень |
|---|---|
| Windows | `%LOCALAPPDATA%/RAMVI`; без `LOCALAPPDATA` — `~/AppData/Local/RAMVI` |
| macOS | `~/Library/Application Support/RAMVI` |
| Linux | `$XDG_DATA_HOME/ramvi`; без `XDG_DATA_HOME` — `~/.local/share/ramvi` |

Внутри корня:

| Путь | Назначение |
|---|---|
| `cache/tune.json` | Настройка собственных вычислительных ядер RAMVI |
| `work/ramvi-grammar-*` | Временные вход и результат ограниченной компиляции грамматики; удаляются при выходе из контекста компиляции |
| `results/` | Результаты проверок и замеров инструментов |

Для переносимого запуска можно явно задать относительный корень, например `RAMVI_DATA_DIR=./data`, и запускать приложение из папки комплекта. Автоматического выбора portable-каталога по расположению исходников нет: рабочие файлы не должны требовать записи рядом с установленным Python-пакетом.

## Прежний кэш настройки

Пока `cache/tune.json` в новом корне отсутствует, настройка читает прежний `~/.cache/llm_app/tune.json`, если такой файл есть. Он не переносится, не удаляется и не перезаписывается. Проверка версии (hash исходника ядра и версия Torch) и ключи формы/видеокарты прежние. Подход сохраняет тёплые настройки для сравнения до/после переноса.

Если понадобилась новая настройка, полный обновлённый кэш записывается атомарно в новый `cache/tune.json`. При наличии нового файла он имеет приоритет, в том числе если он повреждён: обычная проверка отвергает его и выполняет настройку заново. Чужой старый кэш не маскирует повреждение нового. Явная замена `tune.CACHE` инструментом или тестом остаётся изолированной и не подмешивает прежний кэш.

## Переменные движка

| Новое имя | Прежнее имя | Значение по умолчанию |
|---|---|---|
| `RAMVI_VRAM_RESERVE_GIB` | `LLM_VRAM_RESERVE_GIB` | `0.9` |
| `RAMVI_CPU_FRAC` | `LLM_CPU_FRAC` | `0.58` |
| `RAMVI_LAYER_PROFILE` | `LLM_LAYER_PROFILE` | Не задано |
| `RAMVI_CPP_THREADS` | `LLM_CPP_THREADS` | `16` |
| `RAMVI_NO_CPP` | `LLM_NO_CPP` | Не задано; значение `1` отключает C++ |
| `RAMVI_DRAFT_GATE` | `LLM_DRAFT_GATE` | `0`; экспериментальный предварительный выбор выключен |
| `RAMVI_PREFILL` | `LLM_PREFILL` | `legacy` |
| `RAMVI_PREFILL_MIN_TOKENS` | `LLM_PREFILL_MIN_TOKENS` | `256` |

Числовые ограничения, флаги, вычислительные алгоритмы и значения по умолчанию сохранены. При включении `RAMVI_DRAFT_GATE=1` или `RAMVI_PREFILL=blocked` действуют те же экспериментальные пути, что и прежде.

## Сторонние пути и API

HF/Ollama хранилища моделей остаются внешними: `HF_HUB_CACHE` и `OLLAMA_MODELS` продолжают работать, модели не копируются в каталог данных RAMVI. Аналогично сохраняются стандартные или явно настроенные кэши компиляции Numba/Triton и их переменные `NUMBA_CACHE_DIR`, `TRITON_CACHE_DIR`; этот пункт не переносит их и не очищает. В `RAMVI_DATA_DIR` размещаются собственные файлы настройки, временные рабочие файлы и результаты RAMVI. Это позволяет менять организацию файлов без незапрошенной перекомпиляции сторонних ядер.

Для других компонентов доступны:

- `env(name, default=None)` — принимает суффикс (`CPP_THREADS`), новое либо прежнее полное имя; возвращает строку или `None`.
- `data_dir()`, `cache_dir()`, `work_dir()`, `results_dir()` — возвращают `Path`, не создавая каталоги.
- `ensure_dir(path)` — создаёт каталог с родителями непосредственно перед записью.
- `tuning_cache_for_read(destination=None)` — только выбор файла чтения с ограниченной совместимостью прежнего tuning-кэша.

Конфигурационный модуль не импортирует Torch, Triton, NumPy или модели. Тесты `engine/tests/test_config.py` проверяют приоритеты окружения, прежние значения, платформенные пути, отложенное создание и неизменность старого кэша без GPU.
