# Память и состояние персонажа (CHAR-14, пункт 9.14)

Таблицы памяти объявляет сам Character миграцией
[`modules/character/migrations/0001_memory.sql`](../../modules/character/migrations/0001_memory.sql).
Они лежат в собственной базе модуля `data/modules/character/data.sqlite3` (механизм 3.12,
[MODULE_DATA.md](MODULE_DATA.md)), а не в Core: данные Chat, Agent и других модулей недоступны,
потому что это другой файл. Код доступа: `character/ramvi_character/memory.py` (`MemoryStore`).

## Пространства

`memory_namespace` — пара «пользователь + персонаж», id вида `u:owner/c:default`. Каждый запрос
`MemoryStore` содержит этот id, поэтому записи разных пользователей и разных персонажей одного
пользователя не смешиваются даже при одинаковых id записей. Сейчас пользователь один (`owner`,
либо `user_id` из контекста модуля), персонаж — `default`; смена пака или профиля память не меняет.

## Запись памяти (`memory_record`)

Поля из ТЗ 10.3: `id`, `type`, `subject`, `value`, `confidence`, `occurrences`, `first_seen`,
`last_seen`, `status`, `source_ids`. Дополнительно:

| Поле | Значения |
|---|---|
| `kind` | `working`, `profile`, `episodic`, `semantic`, `behavioral` — виды памяти ТЗ 10.2 |
| `origin` | `user_said`, `observed`, `interpretation`, `assumption` — откуда знание (ТЗ 10.5) |
| `status` | `candidate`, `active`, `disputed`, `superseded` |
| `expires_at` | только у рабочей памяти; истёкшая запись не попадает в выборку |

Активным фактом может стать только сказанное пользователем или подтверждённое наблюдение:
интерпретация модели и предположение остаются кандидатом или спорной записью. Правило проверяет
и код, и `CHECK` в самой схеме. `observe` — та же запись встретилась снова: `occurrences + 1`,
`last_seen` обновляется, источники объединяются (не больше 32). `forget` удаляет запись по просьбе
пользователя.

## Character State (`character_state`)

Текущее состояние персонажа хранится отдельно от воспоминаний: одна строка на пространство,
JSON со схемой `ramvi.character.live_state/1` и счётчиком ревизий. Сейчас там эмоциональное
состояние. Модуль пишет его при checkpoint и читает при запуске; если строка есть, она важнее
прежнего JSON-checkpoint. Установки без базы (до 0.9.0) берут состояние из checkpoint и переносят
его в базу при следующем сохранении.

## Поиск (CHAR-15, пункт 9.15)

Миграция [`0002_memory_search.sql`](../../modules/character/migrations/0002_memory_search.sql)
добавляет к записи `importance`, `unfinished`, `topics`, `entities`, точный индекс тем и сущностей
`memory_tag` и полнотекстовый индекс FTS5 `memory_fts` (триггеры держат их в согласии с записями;
старые записи индексируются при миграции). Код — `character/ramvi_character/recall.py` (`Recall`).

Кандидаты берутся только запросами по индексам с LIMIT 48: полный текст по реплике, полный текст
по текущей задаче, совпадение тем/сущностей (слова и пары слов), незавершённые события, самые
значимые записи. Вся история не читается: на 3001 записи поиск вернул меньше 400 строк, на 10 000 —
128 строк за 17–20 мс (Mac M1 Pro). Затем каждый кандидат оценивается суммой сигналов:

| Сигнал | Вес |
|---|---|
| полный текст (bm25 относительно лучшего) | 0,28 |
| темы и сущности | 0,22 |
| текущая задача | 0,14 |
| смысловая похожесть (подключаемая) | 0,14 |
| значимость | 0,08 |
| давность (полураспад 30 дней) | 0,06 |
| незавершённое событие | 0,05 |
| частота повторений | 0,03 |

Смысловая похожесть — необязательная функция `similarity(query, texts) → [0..1]` (например,
эмбеддинги). Она только пересортирует найденное индексами: не добавляет записей и с весом 0,14 не
обгоняет совпадение по тексту и темам. Русские окончания покрывает поиск по началу слова
(«файлы» → `файл*`). Заменённые (`superseded`), истёкшие и чужие записи не возвращаются.

Диалог передаёт найденное в `ContextOrchestrator` (до 16 записей, с видом, происхождением и
статусом подтверждения); тот укладывает их в бюджет раздела памяти и выбрасывает сначала наименее
релевантные, не трогая инструкции и задачу. Авторизатор базы модулей разрешает FTS5 читать
`PRAGMA data_version` (счётчик изменений, только чтение); прочие PRAGMA по-прежнему запрещены.

## Кандидаты и консолидация (CHAR-16, пункт 9.16)

Модель только предлагает: в `end`-записи ответа до 4 кандидатов (`kind`, `text`, `confidence`,
`evidence`, необязательные `subject` — короткий ключ темы и `quote` — точные слова владельца).
Код — `character/ramvi_character/consolidate.py` (`Consolidator`).

**Откуда знание, решает код, а не модель:**
- `user_said` — `quote` дословно (без учёта регистра и пробелов) есть в той реплике владельца,
  на которую ссылается `evidence` (текущая или `recent:<id>u`);
- `interpretation` — ссылка на слова владельца есть, а цитаты нет или она не совпала;
- `assumption` — за кандидатом нет реплики владельца или модель сама не уверена (< 0,5).

**Статусы:** новая запись всегда `candidate`. Свои слова владельца становятся `active`, когда
повторились в другом ответе (тот же ответ дважды не считается). Интерпретация и предположение
активными сами не становятся. Та же мысль другими словами (совпадение основ слов ≥ 60 % в той же
теме) — та же запись: `occurrences + 1`, источники объединяются. Другое значение в той же теме —
противоречие: новая запись `disputed`, известный факт не меняется; две неподтверждённые версии
обе становятся `disputed`. Подтверждение владельцем (`memory_confirm`) делает запись `active`
(как его собственные слова), а противоречащие версии — `superseded`.

**Когда пишется:** только после полностью завершённого ответа, после последней проверки отмены.
Прерванный, невалидный и запасной (простым текстом) ответ памяти не создают.

**Фон:** очередь на 16 ответов; при переполнении ответ отбрасывается и считается в `dropped`,
речь не ждёт. Поток живёт, только пока есть работа. Остановка, пауза и выключение модуля
останавливают его: очередь очищается, начатый ответ дальше не обрабатывается. Счётчики —
в `status().memory.background`.

**Команды владельца** (`dialogue`): `memory` — список (фильтры `kind`, `status`, `limit`),
`memory_confirm {id}`, `memory_forget {id}`. Экран управления памятью — позже.

## Управление памятью и историей (CHAR-17, пункт 9.17)

Экран: «Настройки → Персонаж → Память и история» (`CharacterMemoryViewModel`). Записи с видом,
статусом и происхождением; значение можно исправить, запись — подтвердить или забыть. История —
по репликам с удалением. «Экспорт в файл…» сохраняет JSON (`ramvi.character.memory_export/1`:
записи, Character State, история) в файл, который выбирает пользователь. «Забыть всё» и
«Очистить историю» — в два нажатия. Команды модуля: `memory_correct`, `memory_clear`,
`memory_export`, `history_forget {ids}`, `history_clear` (плюс `memory`, `memory_confirm`,
`memory_forget` из 9.16).

**Удаление без следов текста.** Забытая запись удаляется из `memory_record`, её строки уходят из
`memory_tag` и FTS (триггеры + `optimize`, иначе FTS5 держит слова в старых сегментах), база модуля
открыта с `secure_delete`, затем `data.compact` сбрасывает WAL и удаляет копии миграций. Тест ищет
забытое слово в байтах всех файлов пространства модуля (база, WAL, FTS, копии) — его нет.

**Забытое не возвращается само.** Остаётся только след `memory_forgotten`: солёные хэши темы и
основ слов и id источников (ответы, реплики истории), без текста. Кандидат модели отбрасывается,
если ссылается на те же источники или совпадает темой и большей частью слов (≥ 60 %) с забытым —
так модель не восстановит запись из той же старой реплики или перефразом. Новое явное заявление
владельца в текущей реплике (дословная цитата) — его право, оно сохраняется. След переживает
перезапуск и привязан к пространству: чужие пользователи и персонажи не затронуты.

**Исправление** заменяет запись: новая — `active`, `user_said`, источник `owner:correction`; старая
версия забывается (со следом). **Удаление реплик** забывает записи, выученные только из них; у
записей с другими источниками удалённые источники просто убираются. Идущий ответ перед удалением
истории останавливается (до 5 с; иначе отказ, чтобы его реплика не дописалась после удаления).
Пользовательский текст на диске модуля есть только в базе памяти и `dialogue.json`; кэшей с текстом
ответов нет (кэш речи — только список голосов).

## Чего здесь нет

Последние реплики диалога по-прежнему в `dialogue.json`.

Проверки: `tests/test_character_memory.py` — все поля записи и перезапуск базы, все виды памяти
отдельно от состояния, изоляция пользователей и персонажей, запрет активного предположения в коде
и в схеме, отказ невалидных записей, истечение рабочей памяти, настоящий модуль под ModuleHost
применяет миграцию и после перезапуска восстанавливает состояние из базы.
