# Несколько видеокарт NVIDIA (4.10 ENG-MULTIGPU)

Код: `engine/ramvi_engine/planning/multigpu.py` (раскладка), `core/gengine.py` (GGUF-движок),
`model_loader.py` (бюджет плана), `service/ramvi_service/model_fit.py` и `compat.py` (оценка 4.4).
Тесты: `engine/tests/test_multigpu.py`, `tests/test_multigpu_fit.py`, сверка исходников
`engine/tests/test_migration_sources.py` (`MULTIGPU_410`).

## Как работает

- **Какие карты:** все видимые, или список из `RAMVI_DEVICES="0,1"`. Первая в списке — основная:
  на ней выходной словарь, подкачка по шине, слои вне видеопамяти и угадыватель.
- **Когда делить:** модель, которая целиком помещается в основную карту, остаётся на ней. Путь
  прежний, с CUDA-графом, передач между картами нет. Модели, которой одной карты мало, слои в
  видеопамяти раскладываются подряд блоками по всем картам (`split_layers`). Если помещаются все
  слои — пропорционально бюджетам карт; если нет — карты заполняются по очереди, остаток идёт на
  шину и процессор, как раньше.
- **Что где:** у каждой карты свои веса её слоёв, свой KV-кэш этих слоёв и свои рабочие буферы.
  Ядра Triton запускаются в контексте карты слоя. Между картами передаётся только состояние слоя
  (T×D чисел, например 16×5120×4 Б = 320 КБ на пачку) — один раз на границе блока. Чтение
  длинного запроса переносит запрос на карту блока тоже один раз.
- **CUDA-граф:** при слоях на нескольких картах шаг идёт без графа (обычный запуск ядер).
  Сколько это стоит в скорости, покажет замер на арендованной машине.
- **План:** бюджет видеопамяти плана = свободная память основной карты + дополнительные карты за
  вычетом их резерва (`automatic_reserve`) и рабочих буферов (384 МиБ). Так `choose_plan` разрешает
  положить в видеопамять больше слоёв, а движок раскладывает их по картам.
- **Нехватка памяти при работе:** слой с дополнительной карты уходит на подкачку, а его KV-кэш
  переносится на основную карту (прежний механизм `_demote`).
- **Оценка в каталоге (4.4):** для плотной Qwen3 GGUF берётся общая видеопамять карт по тому же
  правилу, для остальных — одна самая большая карта.

## Чего нет

- MoE (`qwen3moe`) и модели HF (safetensors) по-прежнему используют одну карту — основную.
- Проверено на 2× RTX 4060 Ti 16 ГБ (результаты ниже) и без видеокарт: раскладка (тесты), сверка
  исходников, оценка каталога для двух карт.

## Проверка на арендованной машине (приёмка пункта)

1. **Одна карта + CPU:** `RAMVI_DEVICES=0`, Qwen3-32B Q4_K_M, контекст 2048 — план, ток/с, ответы
   на контрольные вопросы (4, 3973, 100032) и жадный текст на 3 запросах.
2. **Две карты:** без `RAMVI_DEVICES` — все слои в видеопамяти (лог «несколько видеокарт»), тот же
   жадный текст побайтно, скорость не ниже варианта 1.
3. **Одна карта для маленькой модели:** Qwen3-8B Q4_K_M на двух картах остаётся на основной (в
   логе нет строки «несколько видеокарт»).
4. Всё — с одним и тем же кодом и весами, A/B подряд.

## Результат приёмки (2026-11-17)

Арендованная машина: 2× RTX 4060 Ti 16 ГБ (PCIe x8), 16 потоков, 62 ГБ RAM, Ubuntu 24.04, драйвер
595.91, torch 2.15.0+cu132, Triton 3.9.0. Код — коммит с 4.10, угадыватель выключен, 3 запроса по
64 токена жадно + контрольный вопрос.

| Модель | Карты | Раскладка | ток/с | 137 × 29 | Токены как у одной карты |
|---|---|---|---|---|---|
| Qwen3-32B Q4_K_M (20,2 ГБ) | `RAMVI_DEVICES=0` | 45 GPU / 8 шина / 11 CPU, 14,5 ГБ VRAM | 2,2 / 2,6 / 2,6 | 3973 | — |
| Qwen3-32B Q4_K_M | обе | 29 слоёв на cuda:0 (9,2 ГБ) + 35 на cuda:1 (10,3 ГБ) | 11,6 / 11,6 / 11,6 | 3973 | 3 из 3 |
| Qwen3-8B Q4_K_M (5,2 ГБ) | `RAMVI_DEVICES=0` | 36 GPU | 9,9* / 36,5 / 38,8 | 4973 | — |
| Qwen3-8B Q4_K_M | обе | 36 GPU на основной, деления нет | 38,6 / 39,5 / 39,4 | 4973 | 3 из 3 |

\* первый запрос после запуска включает компиляцию ядер Triton.

Итог: модель, которой мало одной карты, на двух работает в 4,5 раза быстрее, чем на одной с
подкачкой, текст побайтно тот же. Модель, помещающаяся в одну карту, на неё и кладётся (тот же текст,
та же скорость, CUDA-граф). Ответ 8B «4973» неверный, но одинаковый в обоих вариантах — это ответ
самой модели, не движка.
