# Выбор модели с объяснением (4.6 AUTO-04)

Код: `service/ramvi_service/recommend.py`, маршрут `GET /ui/v1/recommendations`.
Тесты: `tests/test_recommend.py`.

## Как выбирается

1. **Кандидаты** — модели каталога (4.2) и установленные модели. У каждой есть статус и план
   (4.4, [COMPATIBILITY.md](COMPATIBILITY.md)) под профиль задачи (4.5, [TASK_PROFILE.md](TASK_PROFILE.md)).
2. **Отсев.** Не предлагаются модели, которые не запустятся на этом компьютере, не подходят задаче
   профиля или ещё не оценены (заголовок не прочитан). Сколько отсеяно по каждой причине —
   поле `excluded`.
3. **Одна модель — одна строка.** Один и тот же файл из разных источников (одинаковые архитектура,
   размер и квант) считается одной моделью, установленная важнее.
4. **Порядок по приоритету профиля** — только по проверяемым величинам:

| Приоритет | Порядок |
|---|---|
| `balanced` (по умолчанию) | самая крупная среди комфортных (≥ 15 ток/с), иначе среди интерактивных (≥ 3 ток/с) |
| `quality` | больше параметров и точнее квант среди интерактивных (≥ 3 ток/с) |
| `speed` | выше скорость (замер, иначе оценка) |
| `ram` | меньше RAM (своя + веса из файла), затем VRAM |
| `ttft` | меньше весов вне видеопамяти, затем меньше модель |

При равенстве выигрывает установленная, затем более быстрая. В режиме `economy` при
приоритете `balanced` ранжирование идёт по `ram`.

Пороги 15 и 3 ток/с — выбор удобства, а не замер: 15 заметно быстрее чтения, при 3 текст ещё
можно читать по мере генерации. Без «баланса» `speed` всегда выбирал бы самую маленькую модель, а
`quality` — самую крупную на грани удобства.

## Чего здесь нет

Нет общего рейтинга «умнее»: проверенных измерений качества моделей у нас нет. Объяснения
`balanced` и `quality` прямо говорят, что выбор сделан по числу параметров, а не по качеству.

## Ответ

```
{profile, priority, best: {id, name, installed, compat}, reason,
 alternatives: [{id, name, installed, compat, reason}] (до 3), excluded: {unknown, not_runnable, not_for_task}}
```

`reason` — сообщение `recommend.reason.<приоритет>`: размер, квант, скорость, статус, память.
У альтернативы `reason` — чем она отличается от выбранной: крупнее/меньше, быстрее/медленнее
(разница больше 10 %), больше/меньше RAM (разница больше 256 МБ). Если ничего не подходит,
`best = null`, а `reason` перечисляет, сколько моделей отсеяно и почему.

## Проверка

Настоящий каталог (17 моделей), профиль ноутбука RTX 5060 8 ГБ / 16 ГБ RAM, 2026-11-17:

| Профиль | Выбор | Альтернативы |
|---|---|---|
| chat / balanced | Qwen3-8B Q4_K_M, ~50–59 ток/с | 4B F16, 4B Q4_K_M, 1.7B F16 |
| chat / quality | Qwen3-30B-A3B Q4_K_M, ~9–11 | qwen3:30b (Thinking-2507 — другой файл), 14B (замер 7,8–9,1), 8B |
| chat / speed, ttft | qwen3:0.6b Q4_K_M | 0.6B F16, 1.7B, 4B |
| economy | qwen3:0.6b Q4_K_M (меньше всего памяти) | 1.7B, 0.6B F16, 4B |
| long_context / balanced | Qwen3-8B Q4_K_M, ~9–16 | 4B Q4_K_M, 1.7B F16, 1.7B Q4_K_M |

Прежняя функция `compat.choose` (ранжирование по `Candidate`, без профиля и задачи) удалена,
её заменяет `recommend.rank`.
