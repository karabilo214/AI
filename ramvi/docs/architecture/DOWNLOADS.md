# Загрузки моделей (4.3 MOD-02 / MOD-04)

Код: `service/ramvi_service/downloads.py` (один файл), `service/ramvi_service/download_manager.py`
(очередь), `service/ramvi_service/web.py` (правила сети). Тесты: `tests/test_downloads.py`,
`tests/test_download_manager.py`.

## Что скачивается

Только запись каталога (4.2, [CATALOG.md](CATALOG.md)) с подтверждённым форматом. Адрес, размер и
SHA-256 берутся из каталога, клиент передаёт лишь `entry_id`. Неизвестная или скрытая запись —
`404 download.unknown_entry`, к файлу запроса нет.

## API (`/ui/v1`)

| Запрос | Действие |
|---|---|
| `GET /downloads` | все загрузки: состояние, байты, ошибка, подключённая модель |
| `POST /downloads {entry_id}` | поставить в очередь; повтор той же записи — та же загрузка |
| `POST /downloads/{id}/pause` | пауза; `.part` сохраняется |
| `POST /downloads/{id}/resume` | продолжить (из паузы или после ошибки) |
| `POST /downloads/{id}/cancel` | отменить; `.part` удаляется |

## Состояния

`queued → running → verifying → done`; также `paused`, `failed`, `cancelled` (таблица `downloads`
хранилища 3.2).

- **Очередь:** одна загрузка за раз, остальные ждут (ограничение параллелизма MOD-04).
- **Продолжение:** HTTP Range с места остановки, в том числе после переадресации на CDN
  (urllib сохраняет заголовок Range). Сервер без Range — загрузка заново, хеш считается заново.
- **Обрыв сети:** повтор через 2, 5 и 15 с. После последней неудачи — `paused` с причиной
  `download.interrupted`, продолжение кнопкой. Пауза или отмена во время ожидания срабатывают сразу.
- **Хеш:** SHA-256 считается по ходу загрузки. Файл получает своё имя (атомарный `os.replace`)
  только при совпадении, иначе `.part` удаляется (`failed`, `download.hash_mismatch`).
- **Подключение:** готовый файл проходит ту же проверку заголовка GGUF и архитектуры, что и импорт
  (3.8). Не прошёл — `failed`, в списке моделей его нет. Модель записывается с провайдером,
  sha256, лицензией и `catalog_id` / `version` каталога. Внутри папки приложения путь сохраняется
  относительным.
- **Перезапуск и выключение питания:** незаконченные загрузки после запуска стоят на паузе (сами
  гигабайты не качаются). `.part` никогда не считается моделью: в список попадает только
  проверенный и подключённый файл.
- **Защита:** место на диске проверяется до начала (с запасом 512 МБ); имя файла не выходит за
  папку моделей (`..`, абсолютные пути, диски, symlink); ограничение скорости `limit_bps`.

## Сеть

Только HTTPS, переадресация тоже только на HTTPS (`web.py`); переадресация на `http://` даёт
`failed`, `download.only_https`. Обычный HTTP разрешён лишь для 127.0.0.1 (тесты). User-Agent
`RAMVI`, без cookies, ключей и сведений о пользователе.

## Замер

Mac M1 Pro, 2026-11-17, настоящие провайдеры через сервис (`build` + API):

- `ollama:qwen3:0.6b` (522 640 096 байт): пауза на 107 МБ, продолжение, готово за 50,4 с
  (9,9 МиБ/с вместе с паузой). SHA-256 файла совпал с каталогом (`7f403014…`), модель подключена
  как `qwen3-0.6b-q4_k_m` (провайдер ollama, apache-2.0).
- `huggingface:Qwen/Qwen3-4B-GGUF/Qwen3-4B-Q4_K_M.gguf`: пауза на 55,6 МБ, продолжение, затем
  отмена (`.part` удалён). Отдельный запрос с Range к адресу каталога: CDN Hugging Face и CDN
  реестра Ollama после переадресации отвечают `206` с верным `Content-Range`.

Hugging Face целиком (2,5 ГБ) не скачивался: путь тот же, отличается только CDN, а продолжение на
нём проверено.
