# Инструменты проверки и замеров (1.6–1.7)

Это инструменты разработчика в рабочем дереве репозитория. Они отделены от исполняемого пакета `ramvi_engine` и не входят в wheel движка. Команды выполняются из корня репозитория с установленным движком и нужными для выбранной проверки зависимостями.

## Общий запуск

```sh
python -m ramvi.engine.tools --help
python -m ramvi.engine.tools unit -- -q
python -m ramvi.engine.tools --timeout 120 check selftest -- --model Qwen3-0.6B --n 48
python -m ramvi.engine.tools --timeout 900 bench wide -- current http://127.0.0.1:11435 qwen3:14b --output results/wide.json
python -m ramvi.engine.tools bench wide -- --compare results/a.json results/b.json
python -m ramvi.engine.tools bench compare -- results/bench_a.json results/bench_b.json
python -m ramvi.engine.tools bench report_migration -- --help
```

Параметры после `--` получает выбранный инструмент. Общий диспетчер не импортирует Torch/Triton. Он запускает один дочерний процесс, ждёт не более `--timeout` секунд (по умолчанию 600), при превышении останавливает дерево и возвращает код 124. В Windows используется `taskkill /T`; на POSIX дочерний процесс получает отдельную сессию. Общий таймаут действует и на инструменты со своим абсолютным дедлайном.

Запуск выбранной GPU-проверки всё равно требует CUDA, моделей и разрешения владельца на использование соответствующей машины. Диспетчер не получает такое разрешение автоматически и не выполняет SSH.

## Размещение

- `engine/tools/checks/`: прежние `check_*`, fp32 `selftest`, проверка официальными API-клиентами `api_test`, проверка C++-пула `native_pool`.
- `engine/tools/bench/`: GSM8K/скорость `bench`, WIDE30, парный O02, проверки сопоставимости результатов, сравнение GSM8K и отчёт переноса.
- `engine/tools/processes.py`: проверка занятости Windows и остановка дерева.
- `engine/tests/legacy/`: прежние 89 модульных тестов. Их загрузчик AST использует канонические исходники и не зависит от `llm_app`.

Временные старые имена оставлены в `llm_app` до удаления этого пакета по пункту 1.11. Тестовые обёртки сохраняют прежний запуск unittest; CI выполняет те же тесты из нового расположения вместе с остальными через pytest. В лёгком окружении без NumPy/Torch/Numba/xgrammar весь каталог legacy исключается из сбора; полный CPU-прогон обязан иметь эти зависимости.

## Параметры и данные

WIDE30 и GSM8K принимают `--output`; без него используют `ramvi_engine.config.results_dir()`. Кэш GSM8K использует `cache_dir()`. Парные проверки prefill, размещения и O02 используют ту же папку результатов. O02 требует явного `--baseline`; одиночный токен требует `--baseline` и `--library`, чтобы не открывать DLL из прежней рабочей папки. Native pool собирает временные файлы в отдельном каталоге и удаляет их после проверки.

Код запросов, набор WIDE30 и математическая методика замеров сохранены. Изменение путей и обвязки не доказывает сохранность результатов на NVIDIA: после всех изменений этапа 1 остаётся экзамен 1.9.
