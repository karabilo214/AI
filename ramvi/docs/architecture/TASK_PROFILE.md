# Профиль задачи и проверка выполнимости (4.5 AUTO-02 / AUTO-03)

Код: `service/ramvi_service/task_profile.py`, `model_fit.py`, `settings.py`, `engines.py`.
Тесты: `tests/test_task_profile.py`.

## Профиль (AUTO-02)

Хранится в `settings.json` (поля `task_mode`, `task_priority`, `task_context`) и меняется через
`POST /ui/v1/settings`; неверное значение — `400 settings.invalid`, файл не меняется.

| Режим | Контекст по умолчанию | Нужно от модели |
|---|---|---|
| `chat` — повседневный чат | 2048 | — |
| `code` — код | 8192 | — |
| `agent` — агент | 8192 | `tools` |
| `long_context` — длинный контекст | 32768 | окно модели ≥ контекста |
| `json` — структурированный JSON | 4096 | `json` |
| `economy` — экономия ресурсов | 2048 | — |

`task_context` (512–131072, 0 — по режиму) задаёт контекст вручную. Приоритет (`quality`,
`speed`, `ram`, `ttft`) хранится для ранжирования (4.6).

Смена профиля меняет только рекомендации и контекст следующей загрузки модели (`--maxt`).
Установленные файлы не трогаются (это проверяет тест). Профиль приходит в ответе `GET /catalog`
(поле `profile`).

## Выполнимость (AUTO-03)

Для каждой модели (`compat` в `GET /catalog` и `GET /models`):

- **План на весь компьютер** — с контекстом профиля. Оценка движка (`estimate_gguf`) уже
  включает веса, KV-кэш выбранного контекста, постоянные буферы GPU, буферы подкачки, рабочие
  массивы CPU и резерв VRAM. Отсюда статус, слои в VRAM и скорость.
- **`now` — план на свободную прямо сейчас память**: свободная VRAM карты и доступная RAM, а не
  только общая. Не помещается — причина «закройте программы» (`compat.reason.busy_now`), статус
  не меняется: компьютер способен, просто занят.
- **`task` — подходит ли задаче**: нужные возможности режима и окно контекста модели
  (`<arch>.context_length` из заголовка). Отдельно от статуса железа.
- **Угадыватель** в выполнимость не входит: если он не помещается, план движка его выключает
  (`draft=auto`).
- **Подкачка с диска** допускается, но интерактивная скорость не обещается: «Медленно» с причиной
  и низкая оценка (COMPATIBILITY.md).
- **Замер скорости** показывается только при том контексте, при котором его сняли (2048). При
  другом контексте план другой, поэтому показывается оценка.

## Проверка

Приёмка ТЗ «14B на GPU 8 ГБ при достаточной RAM — выполнима»: тест на заголовке с размерами
Qwen3-14B Q4_K_M и профиле ноутбука RTX 5060 8 ГБ / 16 ГБ RAM. Результат — «Медленно» (не отказ),
часть слоёв в VRAM, помещается и в свободную сейчас память.

Живьём — настоящие заголовки Ollama, тот же профиль, 2026-11-17:

| Модель | Режим (контекст) | Статус | Слоёв в VRAM | Скорость, ток/с |
|---|---|---|---|---|
| qwen3:14b | chat (2048) | Медленно | 29 из 40 | 7,8–9,1 (замер) |
| qwen3:14b | code (8192) | Медленно | 25 из 40 | оценка ~4,6–8,3 |
| qwen3:14b | long_context (32768) | Медленно | 14 из 40 | оценка ~2,9–5,9 |
| qwen3:8b | chat (2048) | Рекомендуется | 36 из 36 | оценка ~48–57 |
| qwen3:8b | code (8192) | Рекомендуется | 36 из 36 | оценка ~48–57 |
| qwen3:8b | long_context (32768) | Медленно | 22 из 36 | оценка ~8,3–16 |

## Попутно исправлено

Если создание движка выбрасывало исключение, `EngineManager.ensure` не снимал признак
«загружается», и интерфейс показывал загрузку бесконечно. Теперь сразу приходит
`engine.start_failed` (тест `test_engine_creation_error_does_not_hang_loading`).
