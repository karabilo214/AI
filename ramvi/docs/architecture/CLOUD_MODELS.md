# Облачные модели по API (7.7)

RAMVI работает транслятором: модель считает облачный сервис, а Chat, Agent и Character шлют тот
же запрос (формат OpenAI chat) и получают те же куски потока, что от локального движка:
`text`, `reasoning`, `tool_calls`, последний — `end` с `finish_reason` и `usage`.

Код: `service/ramvi_service/cloud.py`; тесты: `tests/test_cloud.py`;
живая проверка: `docs/reports/cloud_checks/live_mac.py`.

## Протоколы

| Сервис | Протокол | Ключ в заголовке |
|---|---|---|
| OpenAI (api.openai.com), в т. ч. Codex | Responses API `/v1/responses`, `store: false` | `Authorization: Bearer` |
| OpenRouter, DeepSeek, Groq, LM Studio/vLLM на этом компьютере | chat completions `/chat/completions` | `Authorization: Bearer` |
| Anthropic (Claude) | Messages `/v1/messages` | `x-api-key` |
| Google Gemini | `generateContent` / `streamGenerateContent?alt=sse` | `x-goog-api-key` |

Модели Codex у OpenAI есть только в Responses API (через chat completions — 404), и там же
у новых моделей OpenAI работают инструменты. Поэтому сам OpenAI идёт через Responses, а
совместимые сервисы — через chat completions.

Перевод запроса: системные сообщения — в `system`/`instructions`/`systemInstruction`;
вызовы инструментов и их результаты — в формат сервиса; картинки — только data:URL из
сообщения (ссылка в сеть не отправляется); у Anthropic и Gemini роли чередуются (соседние
сообщения одной роли склеиваются); из схемы функций для Gemini убираются ключи, которых она
не знает. Поля только для движка (`enable_thinking`, `ramvi_*`) в облако не уходят.

## Подключения и модели

- `cloud.json` в папке данных: сервис, имя, адрес. Ключ — только в хранилище секретов ОС
  (DPAPI / Связка ключей), в ответах — лишь `has_key`.
- Включённая модель — строка таблицы `models` с `provider="cloud"`, id `cloud:<подключение>:<модель>`:
  чаты ссылаются на неё как на локальную. Удаление подключения убирает его модели и ключ.
- Маршруты интерфейса: `GET /ui/v1/cloud`, `POST /ui/v1/cloud/connections` (создать/изменить;
  `key` — строка заменяет, `""` удаляет, нет поля — оставляет), `POST /ui/v1/cloud/models`
  (список моделей сервиса — проверка ключа), `POST /ui/v1/cloud/connections/<id>/models`
  (`{model, enabled}`), `DELETE /ui/v1/cloud/connections/<id>`.

## Маршрутизация и права

- `SwitchableProvider` по `ramvi_model_id` отдаёт облачную модель её сервису; локальный движок
  не запускается и не выгружается, «загрузка модели» не показывается. `POST /engine/load` для
  облачной модели ничего не делает; `EngineManager.ensure` облачную модель отвергает.
- Возможности считаются по модели запроса (`capabilities_for`): облачная — внешняя. Для модулей
  это значит: обычный текст уходит наружу только с правом `egress.text` (Character получил его в
  манифесте 0.17.0), а текст из контекста окна — только с отдельным правом на это приложение.
  Агент с управлением окном на облачной модели тоже считается внешним.

## Сеть, ошибки, отмена

- Только HTTPS (HTTP — лишь 127.0.0.1/localhost, ключ там не обязателен); переадресации не
  выполняются — иначе ключ ушёл бы на другой адрес.
- Коды ошибок: `cloud.key_rejected` (401/403), `cloud.rate_limited` (429), `cloud.service_error`,
  `cloud.unreachable`, `cloud.redirect_refused`, `cloud.only_https`, `cloud.no_key`,
  `cloud.stream_cut`; ключ вырезается из текста ошибки.
- Отмена закрывает соединение (сначала `shutdown` сокета — `close()` из другого потока не будит
  заблокированное чтение); сервис перестаёт считать при разрыве.
- Модель, отвергшая `temperature` (400), повторяется один раз без неё, до вывода.

## Без видеокарты

Облачный режим не требует NVIDIA, драйвера и CUDA: тест в отдельном процессе проводит облачный
чат и проверяет, что `torch`, `triton`, `transformers`, `numpy`, модули CUDA и ядра движка не
загружены. Мастер первого запуска уже позволяет «Пропустить» выбор локальной модели.

## Живая проверка на Mac (2026-11-20)

Mac без NVIDIA, сервис собран как в приложении, подключения созданы маршрутами интерфейса,
ответы озвучены облачным синтезом Google (`gemini-3.8-flash-tts`) через звуковой вывод RAMVI.

| | Claude `claude-sonnet-5-5` | OpenAI `gpt-5.3-codex` |
|---|---|---|
| Моделей в списке сервиса | 14 | 99 |
| «Представься»: первый текст / всего | 1,15 / 2,0 с | 2,61 / 3,29 с |
| Боль в груди: первый текст / всего | 1,36 / 7,2 с | 0,90 / 4,02 с |
| Номер скорой в ответе | 103 или 112 | 112/103 |
| Вызов инструмента | `get_weather(Казань)`, 1,6 с | `get_weather(Казань)`, 3,56 с |

Озвучка Google: первый звук через 5,8–10 с (синтез без потока), все 4 ответа озвучены.
Первый запуск той же проверки нашёл: Codex через chat completions — 404, у gpt-5.6-terra там
не работают инструменты — отсюда Responses API. Ответы — обычный чат без профиля персонажа:
сравнение характера с 8B ещё впереди. Данные: `docs/reports/cloud_checks/live_mac_result.json`.

## Экран (7.8)

- «Настройки» → «Подключения» → «Облачные модели» (`CloudModelsView`, `CloudModelsViewModel`):
  список подключений (сервис, адрес, «ключ сохранён / ключа нет», включённые модели; «Модели»,
  «Изменить», «Удалить» в два нажатия) и форма: сервис (OpenAI в т. ч. Codex, Anthropic, Gemini,
  совместимый с OpenAI со своим адресом), название, адрес, ключ. Ключ после сохранения не
  показывается; при изменении пустое поле оставляет прежний. «Проверить» запрашивает список
  моделей сервиса по значениям формы (или по сохранённому ключу).
- «Модели» подключения: поиск и галочки; отмеченная модель появляется в общем выборе модели.
  Включённые — первыми при открытии списка (под мышью строки не прыгают). Ошибка — галочка
  возвращается, текст ошибки по коду сервиса.
- Общий выбор модели (Chat, Agent и Character берут одну модель) показывает облачную как
  «модель · подключение» с пометкой «облако» и надписью «запросы уходят в <адрес>». Выбор
  облачной модели не загружает и не выгружает локальную. В библиотеке локальных моделей облачных нет.
- `/ui/v1/models` у облачной модели отдаёт `cloud`: подключение, имя, сервис, адрес, модель.

Проверено UI-тестами (клиент HTTP, форма, ключ, галочки, удаление, надпись, окно без экрана) и
снимками окна; мутаций поймано 13/13.

## Транслятор во внешнем API (7.9)

Внешние программы (IDE, агенты) обращаются к локальному API RAMVI в своём формате —
OpenAI chat/completions, Anthropic messages, Ollama chat/generate — с ключом клиента RAMVI.
Если `model` — включённая облачная модель, запрос переводится в общий формат
(`service/ramvi_service/cloud_api.py`), уходит облачному сервису с облачным ключом RAMVI и
возвращается в формате клиента, потоком или целиком (SSE у OpenAI/Anthropic, строки JSON у
Ollama; рассуждения — `reasoning_content` / блок `thinking` / `thinking`; инструменты в обе стороны).

- Имя модели: полный id `cloud:<подключение>:<модель>` или имя у сервиса, если оно одно среди
  включённых и не совпадает с загруженной локальной (локальная важнее; при двух одинаковых
  именах облако не угадывается).
- Право ключа клиента `cloud` — отдельное, по умолчанию выключено (запросы платные); без него
  403 `api.cloud_forbidden`, облачные модели не видны в `/v1/models` и `/api/tags`.
- Облачный ключ не уходит клиенту, ключ клиента — облаку; ошибка облака — 502
  `api.cloud_error` с кодом облака, ключ вырезан.
- Очередь локального движка облаку не нужна; ворота клиента (справедливость, лимиты) и учёт
  токенов — общие. Отзыв ключа и уход клиента обрывают облачный ответ.

Проверено: 12 тестов (перевод форматов, официальные `openai` 3.50.0, `anthropic` 2.8.0,
`ollama` 0.6.3, права, учёт, ошибки, отзыв и уход клиента посреди ответа, выбор по имени),
мутаций 17/17. Живьём на Mac (2026-11-20), клиенты через RAMVI:

| Клиент → модель | Ответ | Время |
|---|---|---|
| `openai`, поток → claude-sonnet-5-5 | «Париж» | 1,99 с |
| `anthropic` → gpt-5.3-codex | «Париж» | 2,60 с |
| `ollama`, поток → claude-sonnet-5-5 | «Париж» | 1,39 с |
| `openai`, инструмент → gpt-5.3-codex | `get_weather(Казань)` | 2,16 с |

Данные: `docs/reports/cloud_checks/live_translator_result.json`.
