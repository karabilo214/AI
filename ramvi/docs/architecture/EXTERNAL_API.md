# Внешний API (этап 7)

Код — `service/ramvi_service/api_server.py`. Требования — раздел 7 ТЗ (API-01…API-04), план — [PLAN.md](../PLAN.md), этап 7.

## Как устроено (7.1, API-01)

Внешние приложения (IDE, агенты) говорят с **сервисом**, а не с движком напрямую. Движок слушает свой случайный порт на 127.0.0.1 со своим секретным ключом и наружу не открыт.

```
IDE ──HTTP──▶ сервис :api_port ──(ключ клиента, очередь модели)──▶ движок 127.0.0.1:<случайный>
```

1. **Ключ клиента** — `Authorization: Bearer <ключ>` или `x-api-key: <ключ>` (Anthropic). Проверяет `KeyStore` (отдельный ключ на приложение, хранится только хеш, отзыв). Права по маршруту: генерация — `chat`, список моделей — `models`. Без ключа, с неверным, отозванным или без права — 401 `api.unauthorized`. `GET /` отвечает без ключа только «жив ли сервис».
2. **Модель.** Отвечает загруженная модель. Имя в запросе должно совпадать с ней (без учёта регистра) или отсутствовать; иначе 404 `api.model_not_loaded` с именами. Модель не загружена — 503 `api.no_model`. Запрос внешнего клиента модель не переключает.
3. **Общая очередь.** Каждый запрос получает своего владельца в `SharedLLM` и ждёт свою очередь вместе с чатом и агентом (`exclusive`): чужая генерация не прерывается, параллельные запросы одного клиента ждут, а не получают отказ. Не дождался за `queue_timeout` (600 с) — 503 `api.busy`.
4. **Поток.** Тело уходит движку как есть: движок сам понимает форматы OpenAI, Anthropic и Ollama и потоковый ответ. Ответ идёт клиенту по мере генерации. Клиент оборвал связь — запрос в движке отменяется (`/engine/cancel`).

| Маршрут | Формат | Право |
|---|---|---|
| `POST /v1/chat/completions`, `POST /v1/completions` | OpenAI | chat |
| `POST /v1/messages` | Anthropic | chat |
| `POST /api/chat`, `POST /api/generate` | Ollama | chat |
| `GET /v1/models`, `GET /api/tags`, `GET /api/version` | список загруженной модели | models |

Порт — `api_port` из настроек (11435); занят — сервис и окно работают, а сервис сообщает `api_error`/`api.port_busy`. Слушает только 127.0.0.1 (сеть — 7.4).

**Discovery** — файл `<data>/run/api.json`: адрес, порт, маршруты, PID, способ авторизации; ключей и секретов в нём нет. Удаляется при остановке.

**Без окна.** Чтобы IDE работала без интерфейса:

```
python -m ramvi_service.app --headless --data-dir <папка данных> [--model <id>] [--api-port <порт>]
```

Сервис печатает `{"event": "ready", ..., "api": "http://127.0.0.1:<порт>"}` и работает до Ctrl+C (или до закрытия stdin, если его запустила оболочка).

Тесты: `tests/test_api_server.py` (сервис и фальшивый движок — настоящие процессы и HTTP).

## Клиенты и ключи (7.2, API-02)

У каждого подключённого приложения свой ключ (`ramvi-…`, 32 случайных байта). В базе (`client_keys`, миграция v5) — только SHA-256 ключа, имя, права (`chat`, `models`, `agent`), дата создания, последнее обращение, состояние и счётчики:

| Счётчик | Откуда |
|---|---|
| `requests` | каждый запрос с действительным ключом |
| `prompt_tokens`, `completion_tokens` | из ответа движка: OpenAI `usage.*_tokens`, Anthropic `input_tokens`/`output_tokens` (в том числе в потоке), Ollama `prompt_eval_count`/`eval_count` (`parse_usage`) |
| `busy_seconds` | сколько модель работала на этого клиента (время в слоте очереди) |
| `errors` | ответ движка с ошибкой или обрыв связи с движком |

**Ключ показывается один раз** — в ответе на создание. Дальше в списке только подсказка `ramvi-…a1b2` (последние 4 символа), чтобы отличать ключи.

**Отзыв** (`ApiServer.revoke(id, cancel_running=True)`) сразу отклоняет новые запросы с этим ключом. С `cancel_running` останавливаются и идущие запросы этого клиента: ждущий в очереди получает 401, генерирующий — обрывается, а в движке запрос отменяется. Без него текущий ответ доходит до конца. Остальные клиенты не затрагиваются: их запросы, очередь и счётчики идут как шли.

Маршруты сервиса для экрана «Подключения» (интерфейсный API, ключ интерфейса):

| Маршрут | Что делает |
|---|---|
| `GET /ui/v1/connections` | адрес и состояние внешнего API, клиенты со счётчиками и числом идущих запросов (без ключей) |
| `POST /ui/v1/connections/keys` `{name, permissions}` | новый ключ — единственный раз целиком в ответе |
| `POST /ui/v1/connections/keys/<id>/revoke` `{cancel_running}` | отзыв |

Тесты: `tests/test_api_clients.py`.
