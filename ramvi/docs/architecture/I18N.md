# Переводы (пункт 3.14, CORE-I18N-01)

## Правило

Текст для человека не пишется в коде. Сервис отдаёт `{"code": "<ключ>", "params": {...}}`,
оболочка показывает текст из каталога на выбранном языке. Языки — `ru` и `en`
(`ramvi_service.i18n.LANGUAGES`, `Localizer.Languages`).

- Каталог ядра — `i18n/<язык>.json`, общий для сервиса и оболочки (в оболочку он встроен).
- Параметр в тексте — `{имя}`. Значением параметра может быть другое сообщение
  `{code, params}` (например, причина ошибки настроек или список причин выбора модели) —
  оно переводится тем же языком (`i18n.render` в Python, `Localizer.Format` в C#).
- Сообщения для разработчика (нарушение контракта, внутренние ошибки) — по-английски;
  если такое сообщение доходит до человека, то только как `{detail}` внутри переведённой
  фразы (например, «Ошибка модуля: {detail}»).

## Сервис

- `service/ramvi_service/i18n.py`: `Msg`/`msg` (ключ + параметры), `UserError` (ошибка с
  ключом), `render`, `load_catalog`, `check_catalogs`, `to_json`.
- На ключи переведены: совместимость и выбор модели (`compat.*`), загрузки
  (`download.*`), проверки настроек (`settings.*`), заголовок GGUF (`gguf.*`), ключи
  клиентов (`client_keys.*`), справка `ramvi-service --help` (`cli.service.*`, язык —
  `RAMVI_LANGUAGE`).
- Язык в настройках применяется сразу: `restart_required` содержит только `data_dir`.

## Модули

Модуль кладёт переводы в `<папка модуля>/i18n/<язык>.json`. Ключи — только свои:
`section.<id>` и `module.<id>.*`; на всех языках ядра; с одинаковыми параметрами; без
совпадений с ключами ядра. Иначе модуль не устанавливается (причина — в `problems`).
Оболочка получает переводы через `GET /ui/v1/i18n` и добавляет к каталогу.

## Оболочка

- `{l:T ключ}` в разметке — привязка, а не готовая строка: при смене
  `Localizer.Current` текст меняется сам (подписки слабые, обновление — в потоке UI).
- Тексты моделей представления (строка состояния, плашка, подписи тем и языков,
  проверки мастера, ошибки разделов) пересобираются в `MainViewModel.Relocalize`.
- Язык из настроек — `MainViewModel.ApplyLanguage`, без перезапуска.

## Проверка в CI

`python tools/check_i18n.py` (шаг «Translations (3.14)» в `.github/workflows/ramvi-ci.yml`,
и тот же код в `tests/test_i18n.py`) падает, если:

1. у каталога ядра или модуля из `modules/*/i18n` нет языка, разные ключи, пустой
   перевод, разные параметры; ключ модуля вне его пространства или совпадает с ядром;
2. ключ, который берёт код (строки-ключи Python сервиса и хранилища, ключи в C#,
   `{l:T …}` в разметке), отсутствует в каталоге;
3. в строковом литерале Python (кроме docstring), C# или в разметке (кроме комментариев)
   есть русский текст.

Не проверяется: ключи, собранные из частей во время работы (`state.{…}.title`,
`compat.relation.…`) — их покрывают тесты, сравнивающие готовый текст. Движок
(`engine/`) вне проверки: его сообщения сервис переводит в коды
(`engines.classify_failure`), справка `ramvi-engine` — пункт 3.15.
