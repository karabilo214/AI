# Данные модулей (CORE-DATA-01, пункт 3.12)

У каждого модуля своё пространство `data/modules/<id>/`: JSON-данные (настройки, checkpoint,
`data.get/set`) и **своя база SQLite** `data.sqlite3`. Core-база (`ramvi.sqlite3`: чаты, модели…)
модулям недоступна, а чужие записи модулей недоступны потому, что это другой файл.

## Таблицы объявляет модуль

SQL-миграции лежат в пакете модуля: `modules/<id>/migrations/0001_<имя>.sql`, `0002_…` — версии подряд.
Core таблиц модулей не определяет: профили, эмоции и память создаст миграция Character (этап 9).
Миграции применяет Host при запуске модуля (`ramvi_storage.migrate`, владелец `module` внутри файла
модуля), перед новыми шагами — копия базы в `data/modules/<id>/backups/`. Если шаг не прошёл, база
**целиком** восстанавливается из копии (уже применённые шаги этого запуска тоже откатываются), модуль
переходит в состояние ошибки. JSON-данные мигрируют прежним способом — во временной копии с атомарной
заменой (пункт 2.x).

## Доступ модуля

Модуль работает в отдельном процессе и обращается к базе вызовами Scoped Services с правом `data`:

| Вызов | Что можно |
|---|---|
| `data.query {sql, params}` | только чтение, не больше 10 000 строк |
| `data.execute {sql, params}` | INSERT / UPDATE / DELETE в одной транзакции |

Авторизатор SQLite на соединении модуля запрещает: `ATTACH`/`DETACH`, любые PRAGMA кроме чтения
структуры, изменение схемы (CREATE/DROP/ALTER — только миграциями), запись в `schema_migrations`,
`load_extension`. `params` — только строки, числа и null. Отказ — ошибка вызова, модуль не падает.

## Экспорт, сброс, удаление

- `ModuleHost.export_data` — ZIP: JSON-файлы, согласованная копия базы (во время работы), `EXPORT.json`
  (модуль, версия, версии схем, время). Резервные копии миграций в экспорт не входят.
- `reset_data` — стереть только данные этого модуля; модуль должен быть остановлен.
- `uninstall(purge_data=True)` — удалить модуль с данными; Core и другие модули не трогаются.

API приложения (экраны — позже): `GET /ui/v1/modules` (состояние, размер данных),
`POST /ui/v1/modules/{id}/export` (ZIP в `data/exports/`), `/reset`, `/uninstall {"purge": bool}`.

Проверки: `tests/test_module_data.py` — таблицы модуля не появляются в Core; модуль не читает и не
меняет записи другого (попытки ATTACH, PRAGMA, DDL, запись в служебную таблицу, запись через query
отклонены); откат неудачной миграции; экспорт во время работы; сброс только своего; удаление
Character сохраняет историю чата и данные Agent; API по HTTP.
