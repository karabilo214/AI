# Переносимый комплект (PORT-01/PORT-02, пункт 3.9)

Сборка: `packaging/build_portable.py` — запускать тем Python, чьё окружение проверено
(на ASUS — `C:\anm\.venv`), из папки с опубликованной оболочкой (`dotnet publish -r win-x64
--self-contained`), архивом встроенного Python той же версии и папкой токенизатора Qwen3-8B.

```
RAMVI/
  RAMVI.exe …                     оболочка Avalonia (self-contained .NET)
  ramvi/service|engine|storage    код RAMVI без тестов (+ engine/native/qmm.dll)
  runtime/python/                 встроенный Python 3.12 для Windows
    python312._pth                Lib\site-packages, ..\..\ramvi\<часть>, import site
    Lib/site-packages/            замыкание зависимостей движка из проверенного окружения
    Include/, libs/               для triton: при старте он компилирует C-модуль (tcc)
  runtime/tokenizers/Qwen3-8B/    файлы токенизатора без весов
  BUILD.json                      состав: версии пакетов, размер, sha256 кода
  settings.json, data/            появляются при первом запуске
```

Что важно и почему:
- Встроенный Python с `._pth` **не читает `PYTHONPATH`**, поэтому пути к коду RAMVI записаны в
  `._pth` — относительно, смена буквы диска на них не влияет.
- Замыкание зависимостей считается по метаданным установленных пакетов (маркеры платформы
  учитываются, extras — нет): в комплект попадают ровно проверенные версии.
- Оболочка сама находит комплект (`runtime/python/python.exe`, `ramvi/`, токенизатор), передаёт
  `RAMVI_TOKENIZER`, `PYTHONNOUSERSITE=1`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` и убирает
  чужой `PYTHONHOME`: комплект не зависит от Python пользователя и не ходит в сеть Hugging Face.
- Пути внутри папки приложения хранятся относительными: папки данных/моделей в `settings.json`
  (3.7) и импортированные модели в базе.
- Папка приложения только на чтение (USB): сервис сообщает `storage.no_access`, на плашке есть
  «Выбрать папку данных…»; выбор запоминается в `%LOCALAPPDATA%/RAMVI/locations.json`
  («папка приложения → папка данных») и применяется, только пока в папку приложения писать нельзя.

## Драйвер NVIDIA в диагностике (8.1, PORT-02)

Комплект не требует ни Python, ни CUDA Toolkit, но нужен совместимый драйвер NVIDIA. Мастер первого запуска показывает отдельную проверку «драйвер» (`onboarding.checks`, после видеокарты NVIDIA): версию драйвера из `nvidia-smi` и наименьшую версию для CUDA из комплекта (`torch.version.cuda`) по таблице NVIDIA «minor version compatibility» (CUDA Toolkit Release Notes): CUDA 13.x — 580, CUDA 12.x — 528.33 на Windows и 525.60.13 на Linux (`MIN_DRIVER`).

| Итог | Код |
|---|---|
| драйвер подходит | `system.driver` (версия, нужная, CUDA) |
| драйвер старше нужного | `system.driver_old` — «обновите драйвер с сайта NVIDIA», с нужной версией |
| видеокарта NVIDIA есть, драйвера нет | `system.driver_missing` — «установите драйвер; CUDA Toolkit не нужен» |
| версия CUDA комплекта неизвестна | `system.driver_found` — только версия |

На ASUS (2026-11-18): драйвер 616.92, CUDA комплекта 13.2 (torch 2.15.0+cu132) — подходит.

## Проверка на ASUS (Windows 11, RTX 5060), 2026-11-16

- Сборка из `C:\anm\.venv`: 49 пакетов (torch 2.15.0+cu132, triton-windows 3.9.0.post30, numba
  0.68.1, transformers 5.22.1, xgrammar 0.2.9 …), 4,14 ГБ, 34 с.
- Встроенный Python комплекта: torch видит RTX 5060, все зависимости и код RAMVI из комплекта,
  `.venv` в путях нет.
- Сервис и движок комплекта: модель внутри комплекта (`models/…gguf`, хранится относительно),
  токенизатор комплекта, офлайн — ответ потоком, первое слово 9,9 с, VRAM после закрытия 0.
- Тот же комплект через `subst R:`: история, мастер, модель на месте, ответ 8,8 с.
- Оболочка в сеансе пользователя **без прав администратора**, с диска S:, без переменных
  `RAMVI_*`: сервис запущен из `S:\RAMVI\runtime\python\python.exe`, видна прежняя история.
- Запрет записи в папку комплекта: плашка «Нет доступа к папке» с «Выбрать папку данных…».

Найдено и исправлено проверкой: `._pth` игнорирует `PYTHONPATH`; triton не мог собрать
`cuda_utils` без `Include/` и `libs/`.

Ограничения: не проверено на чистой Windows без Python и CUDA Toolkit (экзамен 3.10); выбор
папки данных кнопкой в живом окне не нажимался (проверен тестами); в тексте ошибки путь
показан после раскрытия подставленного диска (`C:\…` вместо `T:\…`).
