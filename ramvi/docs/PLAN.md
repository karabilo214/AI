# RAMVI — план выполнения

Основание: техническое задание [RAMVI_technical_spec_v1.pdf](spec/RAMVI_technical_spec_v1.pdf) / [DOCX](spec/RAMVI_technical_spec_v1.docx) (редакция 1.0). Идентификаторы требований (UI-01, ENG-03 …) — из ТЗ; там же критерии приёмки.

Отметка `[x]` ставится только после выполнения критерия «Проверка» данного пункта. Частично сделанное остаётся `[ ]` с пометкой в скобках, что осталось.

## Принятые решения

- [x] Название: приложение — **RAMVI**, движок — **RAMVI Engine**.
- [x] Расположение: каталог `ramvi/` в репозитории MyAI; всё, что относится к продукту, — только внутри него.
- [x] Движок `llm_app` переносится в `ramvi/engine/` и раскладывается по подпакетам (этап 1), без переписывания алгоритмов.
- [ ] Оболочка: решение — по итогам сравнения в пункте 3.1 (кандидат из ТЗ: Tauri + Vue/TypeScript; критерии: размер сборки, portable-режим, WebView2).
- [x] Лицензия: MIT (пересмотр возможен до публичной беты). Файл `LICENSE` — в пункте 1.3, правообладатель: `Copyright (c) 2026 karabin`.

## Правила проекта

Действуют для каждого пункта плана.

1. **Структура.** Один модуль — одна ответственность. Код продукта — в пакетах; проверки — в `tests/`; замеры — в `tools/bench/`; разовые эксперименты в продукт не попадают.
2. **Без личного.** В коде, конфигурации, документах и истории git нет имён, адресов, имён машин, личных путей (`C:\…`, `/Users/…`), ключей. Пути — из настроек и переменных окружения, по умолчанию — в папке данных приложения.
3. **Результаты замеров** (json, логи) в git не попадают; в документах — только сводные цифры с указанием модели, железа и команды запуска.
4. **Строки интерфейса** — в ресурсах локализации (ru, en), не в коде.
5. **Стиль.** Python 3.12: `ruff` (lint + format), `mypy` для новых пакетов, docstring у публичных классов и функций. TypeScript: `eslint`, `prettier`, `strict`. Имена — по-английски; комментарии и документация — по-русски.
6. **Готовность пункта.** Код + тесты + обновлённая документация; все тесты проходят; для изменений движка — экзамен скорости и точности (пункт 1.9) без ухудшения.
7. **Коммиты** — по одному логическому изменению, сообщение по-русски, в повелительном наклонении («Добавить …», «Исправить …»).

```
ramvi/
├── README.md                 обзор, быстрый старт, ссылки на документацию

├── docs/
│   ├── spec/                 ТЗ (docx, pdf)
│   ├── PLAN.md               этот план
│   ├── architecture/         устройство подсистем, контракты, схемы событий
│   ├── adr/                  записи архитектурных решений (ADR-0001 …)
│   └── reports/              отчёты проверок и замеров
├── engine/                   RAMVI Engine (бывший llm_app)
│   ├── ramvi_engine/
│   │   ├── core/             Engine (HF), GGUFEngine, MoEEngine, Loader, Arena
│   │   ├── kernels/          ядра Triton: внимание, матрицы, словарь, сжатие, prefill
│   │   ├── cpu/              слои на процессоре (Numba) и привязка к native/
│   │   ├── native/           C++ (qmm.cpp), сборка, манифест
│   │   ├── formats/          чтение GGUF, контрольные точки HF, проверка токенизатора
│   │   ├── planning/         план памяти, измеренное размещение, автонастройка ядер
│   │   ├── generation/       выборка, угадывание, ограничения JSON/грамматики
│   │   ├── server/           HTTP: приложение, маршруты OpenAI/Anthropic/Ollama, валидация
│   │   └── cli.py            serve | chat | plan
│   ├── tests/                модульные тесты (без GPU)
│   └── tools/
│       ├── checks/           проверки на целевой машине (GPU)
│       └── bench/            экзамены скорости и точности
├── service/ramvi_service/    супервизор движка, IPC API, реестр моделей, планировщик, профиль железа
├── agent/ramvi_agent/        Agent Runtime, инструменты, политика доступа, подтверждения, журнал
├── voice/ramvi_voice/        адаптер STT
├── storage/ramvi_storage/    SQLite (WAL), миграции, репозитории
├── desktop/                  Tauri + Vue/TypeScript
├── packaging/                portable-сборка, манифест обновлений
└── tests/e2e/                сквозные сценарии приёмки (раздел 14 ТЗ)
```
